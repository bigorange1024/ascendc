# Cloud Agent 额度与验收分层（经验：ML-KEM-512 全日跑）

**状态**：经验记录（2026-07-27）  
**案例**：ML-KEM-512 从 P0 到 incubating+liboqs glue（约数小时；Cloud 额度约 65%→82%）  
**纪要**：[qa/2026-07/2026-07-27-768收尾复盘与文档刷新.md](../../qa/2026-07/2026-07-27-768收尾复盘与文档刷新.md) §额度与 debug 复盘  
**范围**：**非**要求改 ML-KEM 现行流程；供**未来其他工程**在保持出口正确性的前提下省额度。

---

## 1. 案例里额度主要花在哪

| 类 | 说明 |
|----|------|
| **流程固有** | 每档探针/exp 出口 **CPU + `SIM_DIRECT=1` sim**；W0–W4 档数多，SIM 贵 |
| **真缺项返工** | D14 跨 AIV 竞态；**glue-c**：Encrypt `r` 误全 η2，自洽假绿后撞 liboqs，整树重验 |
| **工程摩擦** | W4×7 customspec/自包含移植、glue fixture、文档/用语清扫（与算法置信度无关） |

**用户立场（已确认）**：ML-KEM 流程为**任务完整性**设计，**不打算变更**；省额度建议只用于其他工程。

---

## 2. 原则：轻验迭代 · 重验出口

| 档 | 何时 | 目的 |
|----|------|------|
| **轻验** | 积木/半日迭代 | 尽快暴露形状、同步、I/O |
| **重验** | 波次出口 / 交叉 / 声称完成 | 贵路径（SIM、KAT、roundtrip） |

完整性放在**出口证书**；不必让中间每一步都跑满重验。

---

## 3. 其他工程可试的省额度做法

1. **先 CPU、后 SIM 成批** — 同波次 CPU 齐后再集中 SIM；失败单点重跑。  
2. **外部交叉前移** — 有权威实现时，在易误迁块（噪声 η、采样、长度）的**第一波出口**做小交叉，避免全家自洽后再 glue 返工。  
3. **参数差清单先于写码** — 相对参考参数组的硬差（η、d、I/O、批大小）勾选后再 retarget。  
4. **文档与写码分会话** — INDEX/用语/PDF 收工一次刷，不夹在长实现会话。  
5. **多目录复制：先 1 条模板再批量** — 打通 launch/vendoring/`gen_data` 后再复制其余。  
6. **勿并行多路 SIM**；非关键勿默认全量 msprof。  
7. **假绿三问** — golden 是否与实现同源？交叉是否已跑？跨核写读是否有 Sync？

---

## 4. 不建议省（换工程也建议留）

- 波次/阶段**出口**的双模式（或等价重验）  
- 已锁参数不得擅自改参绕过  
- 有权威实现时，出口必须交叉，不能只自洽
