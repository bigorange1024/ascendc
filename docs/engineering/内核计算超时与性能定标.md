# 内核计算超时与性能定标

## 两类不同概念（勿混用）

| 概念 | 变量 / 机制 | 适用范围 | 含义 |
|------|-------------|----------|------|
| **防挂死超时** | `KERNEL_COMPUTE_BUDGET_SEC` + `scripts/kernel-run-timeout.sh` | **各用例** `run.sh` 自行设定默认值 | 仅统计 kernel / 可执行**计算段**墙钟；超时 exit 124 → **疑似死锁/挂死**，须排错；**不是**性能达标线 |
| **NTT 全流程 SIM 性能定标** | 无统一 env；看 SIM 墙钟或 `totalTick` | **仅** ML-KEM **Tag5T NTT 全流程**类探针（见下表） | 正常实现 SIM **kernel 计算段约 ≤15s**（理想 ≤10s）；稳定远超此值优先查实现路径（标量 GM 环、多余搬运、CrossCore 死等），**不是**「SIM 本来就慢」 |

**禁止**：把 15s 写成全仓库默认 `KERNEL_COMPUTE_BUDGET_SEC`；把 KeyGen / Encrypt 全链 / Compress / ByteEncode 等长任务用 15s 超时验收。

---

## 防挂死超时（各用例 `run.sh`）

- **必须**：kernel 启动经 `bash "${REPO_ROOT}/scripts/kernel-run-timeout.sh" <binary>`（内部 `timeout`）。
- **默认值**：写在**该用例** `run.sh` 头注释 + `${VAR:-秒数}`；长短因任务而异（探针常见 60–1800s）。
- **脚本兜底**：`kernel-run-timeout.sh` 在未 export 时 fallback **120s** — 仅防 Agent 漏设；**不代表**该用例性能标准。
- **Agent**：跑某用例时遵守**该目录** `run.sh` 默认预算；超时须报阻塞/死锁并停下，不得无限等待。

示例（摘自活跃探针，非完整表）：

| 用例类 | 典型 SIM 默认预算 |
|--------|-------------------|
| 单功能探针（byteencode、compress、CBD…） | 60–120s |
| NTT 集成 `vec-k4-v2` | 600s |
| Encrypt compute / prep | 600s |
| KEM KeyGen / Encaps / Decaps | 900–1800s |

---

## NTT 全流程 SIM 性能定标（~15s）

**适用**：Tag5T 三段式 NTT + 同拓扑 matmul/split 集成路径，例如：

- `ascendc-tests/pass-fix-f203-2s1e-alg13-16171820-vec-k4-v2`（活跃 ML-KEM 行 16–20 基线）
- `pass-fix-f203-stage123-ntt-intt-polyvec8-vec`
- 同类 **matmul + S1–S3** 探针（见 `qa/2026-06-11` 纪要）

**定标口径**：

- 看 **SIM 模式 kernel 计算段**墙钟（`kernel-run-timeout.sh` 包裹段内），或 CaModel `totalTick` 作相对比较。
- **≤~15s**：实现路径正常量级（理想 ≤10s）。
- **稳定 >>15s**（且非调试宏）：优先查数据搬运、PIPE 同步、标量 GM 循环 — 见 [ascendc-DataCopy与数据搬运知识库.md](../notes/ascendc-DataCopy与数据搬运知识库.md)。

**不适用 ~15s 定标**（须用各自 `run.sh` 预算 + STATUS tick 记录）：

- KeyGen / Encrypt / Decaps **全链**
- Compress / Decompress / ByteEncode / tail pack
- SampleNTT、SHAKE toy、Â 16-poly 等

放宽 `KERNEL_COMPUTE_BUDGET_SEC` 仅证明「没挂死、数值可能对」；**不能**替代 NTT 路径优化。
