## 1. 搬码前（办公室 / Cloud，无 NPU 也可）

```bash
cd <repo>

# 看计划（不编译）
NPU_ONE_TRIP_MANIFEST=1 bash scripts/npu_kem_one_trip.sh

# 分卡 dry-run
NPU_SUITE_DRY_RUN=1 bash scripts/npu_kem_one_trip.sh
```

确认 `STATUS` 块序与分卡符合预期后再 sync 到实机。

| 类别 | 路径 |

## 2. 实机：一条命令

```bash
cd <repo>
unset ASCEND_DEVICE_ID
export SOC_VERSION=Ascend910B4

# 三包卡 preflight 后按块序跑全（约数小时，含 msprof app）
bash scripts/npu_kem_one_trip.sh
```

### 块序（为何这样排）

| 块 | 内容 | 卡 | 说明 |
|----|------|-----|------|
| **A** | preflight | 1/2/3 | `npu-smi` Process 段须干净 |
| **B** | E0 + stable PKE×3 + KEM KeyGen | 1 | 证明卡 1 环境与 MIX 低 risk 路径 OK |
| **C** | **E1** Encaps + `F203_L18_TRACE=1` → **E2** 再跑 Encaps | 1 | **l18 根因证据**；必须在教材 Encaps msprof **之前** |
| **D** | roundtrip + msprof Decrypt / Decaps-E / Decaps 全链 | 1 | 仅 **C 成功** 才跑 |
| **E** | 教材 14 档 msprof（`MSPROF_MODE=app`） | 1/2/3 | C 失败则卡 1 只跑 #1 KeyGen，跳过 #2–4 |
| **F** | 探针 alg13/14/15/19 | 3 | 不含 alg20/21 device 探针 |
| **G** | 可选 1024 incubating | 2 | `ONE_TRIP_INCLUDE_1024_INCUBATING=1` |
| **H** | `BRING_BACK.tar.gz` | — | 自动打包 |

**E1 失败默认仍继续** E 块 768/512 与探针（`ONE_TRIP_CONTINUE_ON_L18_FAIL=1`），避免「只测了一刀就停」。

### 常用变体

```bash
# 只要 l18 证据 + 安全基线（跳过教材 msprof，省时间）
ONE_TRIP_SKIP_TEXTBOOK=1 bash scripts/npu_kem_one_trip.sh

# 追加 1024 incubating 四档
ONE_TRIP_INCLUDE_1024_INCUBATING=1 bash scripts/npu_kem_one_trip.sh

# E1 失败就整趟停（不推荐，除非卡明显脏）
ONE_TRIP_CONTINUE_ON_L18_FAIL=0 bash scripts/npu_kem_one_trip.sh
```

等价入口：`NPU_SUITE_PHASE=one_trip bash scripts/npu_kem_real_machine_suite.sh`

**请拷回办公室（一个文件即可）**：


包内索引见 `BRING_BACK/README.md`。Agent 最关心：

| 文件 | 用途 |
|------|------|

| `snippets/key_lines.txt` | **`[l18-trace]`**、`124`、FAIL |

## 4. 卡死 / timeout 124

- **勿**在同 `ASCEND_DEVICE_ID` 立刻重跑 Encaps/Decaps（脚本已尽量跳过 D/E 卡 1 l18 重复项）。
- `npu-smi info | sed -n '/Process/,$p'` → 有残留则 reset 或换卡。
- 详见 [`qa/2026-08/2026-08-18-实机NPU脚本套件与卡死恢复.md`](../../qa/2026-08/2026-08-18-实机NPU脚本套件与卡死恢复.md)。
