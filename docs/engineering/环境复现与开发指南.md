## 2. 家用电脑前置条件

### 2.1 推荐与源机一致

- **WSL2** + **Ubuntu 22.04 x86_64**（与 CANN 9.0 x86 安装包匹配）
- 磁盘：`~/Ascend` 预留 **≥10GB**，`~/ascendc` 若带 `samples/` 再预留 **≥8GB**
- 网络：首次安装需下载约 **3.5GB** `.run` 包（可用脚本缓存到 `packages/`）

### 2.2 架构必须匹配

| 你的电脑 | CANN 安装包 |
|----------|-------------|
| x86_64（Intel/AMD，WSL 常见） | `Ascend-cann-toolkit_9.0.0_linux-x86_64.run` |
| aarch64（部分 ARM 服务器） | 需从昇腾官网下载 **aarch64** 对应 9.0 包，本文 OBS 链接为 x86_64 |

### 2.3 系统依赖

```bash
sudo apt-get update
sudo apt-get install -y gcc g++ make cmake wget curl python3 python3-pip \
  libssl-dev zlib1g-dev gdb
```

Python 依赖由 `scripts/install-cann-9.0.sh` 用 `pip install --user` 安装（无需 sudo）。

### 2.4 Cursor / VS Code

- 用 Cursor 打开文件夹：**`~/ascendc`**（整个仓库根目录）
- 扩展建议：**C/C++**、**C/C++ Runner**（可选；大仓库下 Runner 可能卡，见第 11 节）

## 3. 安装 CANN 9.0.0

### 3.1 一键安装（推荐，与源机相同）

```bash
# 先 clone 或拷贝 ascendc 仓库到 ~/ascendc，再执行：
bash ~/ascendc/scripts/install-cann-9.0.sh
```

脚本行为摘要：

1. `pip install --user`：`numpy`、`protobuf`、`scipy` 等 CANN 依赖  
2. 下载到 `~/ascendc/packages/`：  
   - `Ascend-cann-toolkit_9.0.0_linux-x86_64.run`  
   - `Ascend-cann-910-ops_9.0.0_linux-x86_64.run`  
3. 安装 Toolkit：`--feature=ascendc`  
4. 安装 910-ops  
5. 在 `~/.bashrc` 追加：`source ${HOME}/ascendc/scripts/env.sh`

### 3.2 手动安装（与脚本等价）

```bash
mkdir -p ~/ascendc/packages && cd ~/ascendc/packages
wget -c "https://ascend-repo.obs.cn-east-2.myhuaweicloud.com/CANN/CANN%209.0.0/Ascend-cann-toolkit_9.0.0_linux-x86_64.run"
wget -c "https://ascend-repo.obs.cn-east-2.myhuaweicloud.com/CANN/CANN%209.0.0/Ascend-cann-910-ops_9.0.0_linux-x86_64.run"
chmod +x Ascend-cann-*.run
./Ascend-cann-toolkit_9.0.0_linux-x86_64.run --install --quiet --feature=ascendc
./Ascend-cann-910-ops_9.0.0_linux-x86_64.run --install --quiet
```

安装后应有：

```text
~/Ascend/cann -> ~/Ascend/cann-9.0.0
~/Ascend/cann/set_env.sh
~/Ascend/cann/bin/ccec
```

### 3.3 配置 shell（若未跑安装脚本）

在 `~/.bashrc` 末尾添加：

```bash
# Ascend CANN 9.0.0
source ${HOME}/ascendc/scripts/env.sh
```

新开终端或 `source ~/.bashrc`。

### 3.4 验证 CANN

```bash
source ~/ascendc/scripts/env.sh
bash ~/ascendc/scripts/verify-cann.sh
```

预期：`version=9.0.0`、`ccec`、`tikicpulib: OK`、`simulator libs: N files`。

**注意**：不要直接 `source ~/Ascend/cann/set_env.sh` 且在 `set -u` 的 shell 里工作，会 `unbound variable`。统一用 `~/ascendc/scripts/env.sh`。

### 3.5 卸载 / 重装

```bash
cd ~/ascendc/packages
./Ascend-cann-910-ops_9.0.0_linux-x86_64.run --uninstall --quiet
./Ascend-cann-toolkit_9.0.0_linux-x86_64.run --uninstall --quiet
rm -rf ~/Ascend/cann-9.0.0 ~/Ascend/cann ~/Ascend/ascend-toolkit
# 再执行 install-cann-9.0.sh
```

## 6. 环境与脚本说明

### 6.1 `scripts/env.sh`（每次开发前）

```bash
source ~/ascendc/scripts/env.sh
```

作用：

- 设置 `CANN_HOME`（默认 `~/Ascend/cann`）
- `set +u` 后 `source ${CANN_HOME}/set_env.sh`，避免 unbound variable
- **不**硬编码某一芯片的 `LD_LIBRARY_PATH`（由 `run.sh` 按设备 prepend）

### 6.2 `ascendc-tests/add_custom/scripts/resolve_device.sh`

用户输入 → CMake / 链接参数：

| 用户输入 | SOC_VERSION (tikicpulib) | SIM_DEVICE (msprof/camodel) | CCEC_ARCH |
|----------|--------------------------|-----------------------------|-----------|
| `910B4` | Ascend910B4 | Ascend910B4 | dav-c220 |
| `910` | ascend910 | Ascend910A | dav-c100 |
| `910B1` | Ascend910B1 | Ascend910B1 | dav-c220 |
| `310p` | Ascend310P1 | Ascend310P1 | dav-m200 |

**注意**：`tikicpulib` 的 CMake target 名是 **PascalCase**，如 `tikicpulib::Ascend910B4`，不是 `ascend910b4`。

### 6.3 `ascendc-tests/add_custom/run.sh` 模式一览

| 模式 | 命令 | 需要 NPU | 典型用途 |
|------|------|----------|----------|
| `cpu` | `./run.sh cpu 910B4` | 否 | **WSL 首选**：孪生调试 + golden |
| `sim-build` | `./run.sh sim-build 910B4` | 否 | 只验证 sim 链接能否编过 |
| `sim` | `./run.sh sim 910B4` | 否* | 默认 msprof + `OPPROF_*`（慢）；`SIM_DIRECT=1` 时仅 CAModel 跑算子 |
| `npu` | `./run.sh npu 910B4` | **是** | 实机上板 |
| `all` | `./run.sh all 910B4` | — | cpu + sim |

\* `sim` 不占用真卡，但需要完整 CANN + `msprof`；在**无卡 WSL** 上应用 **camodel 链接**（见 7.2），否则 ACL 107001。

### 6.4 重要环境变量

| 变量 | 默认值 / 说明 |
|------|----------------|
| `CANN_HOME` | `~/Ascend/cann` |
| `ASCEND_DEVICE` | `910B4`（run.sh 第二参数可覆盖） |
| `MSPROF_AIC_METRICS_SIM` | `PipeUtilization`（sim **不支持** MemoryUB/Memory） |
| `MSPROF_AIC_METRICS_NPU` | `PipeUtilization,MemoryUB,Memory` |
| `MSPROF_LAUNCH_COUNT_SIM` | `1`（加快试跑） |
| `MSPROF_LAUNCH_COUNT_NPU` | `8` |
| `MSPROF_TIMEOUT_MIN` | `60` |
| `MSPROF_WALL_TIMEOUT_SEC` | `1800` |
| `SIM_DIRECT` | **0**（默认）：sim 走 msprof，生成 `prof_sim/` 与 `OPPROF_*`；**1**：仅 `./add_custom_npu`，不生成 `OPPROF_*`。可环境变量或第三参数 `SIM_DIRECT=1` |
| `SIM_BUILD_ONLY=1` | 同 `sim-build` |
| `RUN_WITH_MSPROF=1` | npu 模式走 `msprof op` |
| `PRINT_TIK_MEM_ACCESS` | `FALSE`（run.sh 设置） |
| `CAMODEL_LOG_PATH` | `ascendc-tests/add_custom/sim_log` |
| `KERNEL_COMPUTE_BUDGET_SEC` | **各用例** `run.sh` 自设防挂死秒数（非全仓 15）；经 `scripts/kernel-run-timeout.sh` 包裹 kernel。详 §6.5 |

### 6.5 内核防挂死超时 vs NTT 性能定标（勿混用）

定稿见 **[内核计算超时与性能定标.md](内核计算超时与性能定标.md)**（`.cursor/rules/ascendc-development.mdc` 同源）。

| 概念 | 变量 / 口径 | 适用范围 |
|------|-------------|----------|
| **防挂死超时** | `KERNEL_COMPUTE_BUDGET_SEC` + `kernel-run-timeout.sh` | 各 `ascendc-tests/`、`examples/` 用例在 **本目录 `run.sh`** 写 `${VAR:-秒数}`（60s–1800s 均常见）；超时 exit **124** → 疑似死锁 |
| **NTT 全流程 SIM ~15s** | 无统一 env；看 kernel 墙钟或 `totalTick` | **仅** ML-KEM Tag5T NTT 集成类（如 `pass-fix-f203-2s1e-alg13-16171820-vec-k4-v2`）；稳定远超 → 查搬运/同步路径 |

**禁止**：把 15s 当作全仓库默认 `KERNEL_COMPUTE_BUDGET_SEC`；用 15s 验收 KeyGen / Encrypt 全链 / Compress / ByteEncode 等长任务。

`scripts/kernel-run-timeout.sh` 在未 export 时 fallback **120s**，仅防漏设，**不是**性能标准。

## 7. AscendC 示例代码说明

### 7.1 算子逻辑 `add_custom.cpp`

- **功能**：向量加 `z = x + y`，类型 **float16**，总长 `8 × 2048`，**8** 个 AI Core block  
- **流水线**：`TPipe` + 双缓冲 `BUFFER_NUM=2`，分 tile 做 CopyIn → Add → CopyOut  
- **关键修复**（910B 必加）：

```cpp
if (GetBlockIdx() >= USE_CORE_NUM) {
    return;
}
```

原因：910B 系列 CPU 孪生会拉起整块 die 的 AIC/AIV（多于 8 核），`blockDim=8` 之外的核若执行业务逻辑会 **SIGSEGV**。

### 7.2 Host 程序 `main.cpp`

编译时通过宏分为两路：

| 宏 | 路径 | 行为 |
|----|------|------|
| `__CCE_KT_TEST__` | CPU 孪生 | `GmAlloc` + `ICPU_RUN_KF(add_custom, ...)` |
| 无上述宏 | NPU / 仿真 | `aclInit` → `aclrtMalloc` → `add_custom_do` → 写 `output_z.bin` |

**已修复 bug**：`yDevice` 的 `aclrtMalloc` 必须使用 `inputByteSize`（与 x 相同），不能误用 `outputByteSize`。

ACL 错误打印：`data_utils.h` 中 `CHECK_ACL` 会输出 `文件:行号 aclError:错误码`。

常见错误码：

| 错误码 | 含义 | 常见原因 |
|--------|------|----------|
| 107001 | 无效 Device | 无 NPU 却链了真机 `libruntime`；或未 `run_mode=sim` |
| 107002 | Context/Stream 为空 | 107001 之后连锁失败 |

## 10. 已踩坑与排障手册

| 现象 | 原因 | 处理 |
|------|------|------|
| `aclError:107001` | 无卡 + 链了真机 runtime | `./run.sh sim` 应用 `-Drun_mode=sim` 重编；WSL 日常用 `./run.sh cpu` |
| `aclError:107002` 一串 | 107001 后续失败 | 先修 107001 |
| `basic_filebuf::xsgetn Bad address` | msprof 子进程崩溃 / 无 output | 先用 `SIM_DIRECT=1 ./run.sh sim` 验证算子；再默认 `./run.sh sim` 采性能 |
| `Unexpected argument --aic-metrics=memoryub` | sim 不支持 MemoryUB | 用 `MSPROF_AIC_METRICS_SIM=PipeUtilization` |
| `libascend_hal.so` missing | 覆盖了 `LD_LIBRARY_PATH` | **只 prepend** simulator 路径，不要删掉 `set_env` 的 lib64 |
| `ErrorManager::ATCReportErrMessage` | devlib 排在 lib64 前 | `filter_ld_path_no_driver`；勿把 devlib 放最前 |
| CPU 孪生 SIGSEGV | 910B 多余 AIV 核 | `GetBlockIdx() >= USE_CORE_NUM` return |
| `tikicpulib::ascend910B4` CMake 失败 | 大小写 | 用 `Ascend910B4` |
| msprof 很久无输出 | CAModel 慢 | 看每 20s 进度；`launch-count=1` |
| `prof_sim` 无 csv | 子进程失败或未跑完 | 查终端 ACL 错误；确认 `output/output_z.bin` 存在 |
| C/C++ Runner 无反应 | `samples/` 太大 | 用 `Ctrl+Shift+B`；`settings.json` 已 exclude samples |
| `demo.h: No such file` | Runner 清空 includePaths | 保持 `.vscode/settings.json` 中 `includePaths: ["${workspaceFolder}/include"]` |
| 状态栏编译要选 **`src`** | Runner 按文件夹编译 | 根目录用 Makefile 任务 |

### 10.1 WSL vs 昇腾实机 — 能力矩阵

| 能力 | WSL 无卡 | 昇腾 Linux 实机 |

| `SIM_DIRECT=1 ./run.sh sim` | ✅ 仅 CAModel + golden | ✅ |

### 14.6 失败时优先查什么

1. **`ccec` 找不到** → `source ~/.bashrc` 或 `bash ~/ascendc/scripts/verify-cann.sh`  
2. **107001** → 无卡却链真机 runtime；用 `./run.sh sim` 且 `run_mode=sim` 重编，或改用 `./run.sh cpu`  
3. **无 `OPPROF_*`** → 是否用了 `SIM_DIRECT=1`？只有 **默认** `./run.sh sim` 才走 msprof  
4. **IDE 看不到 `OPPROF_*`** → `ls` 终端确认存在后 `chmod -R a+rX OPPROF_*`  
5. **msprof 指标报错** → sim 仅用 `PipeUtilization` 等，不用 `MemoryUB`（见 `MSPROF_AIC_METRICS_SIM`）

### 14.7 ascendc-tests：kernel 超时与 NTT 性能定标

本仓除 `add_custom` 外，`ascendc-tests/`、`examples/` 下各用例均有独立 `run.sh`。与 add_custom 的墙钟观察（§14.4）**不是同一套口径**。

| 场景 | 做法 |
|------|------|
| 跑任意探针 / example | 看该目录 `run.sh` 头注释中的 `KERNEL_COMPUTE_BUDGET_SEC` 默认值；kernel 须经 `scripts/kernel-run-timeout.sh` |
| 超时 exit 124 | 按**防挂死**处理，查死锁/同步；**勿**与 NTT 性能定标混谈 |
| ML-KEM NTT 全流程（如 `pass-fix-f203-2s1e-alg13-16171820-vec-k4-v2`） | SIM kernel 计算 **约 ≤15s** 为路径正常量级；稳定远超见 [ascendc-DataCopy与数据搬运知识库.md](../notes/ascendc-DataCopy与数据搬运知识库.md) §5.5 |
| KeyGen / Encrypt / Compress / ByteEncode 等 | **不适用** ~15s；用各自 `STATUS.md` 记录的 tick 与 `run.sh` 预算（常 120s–1800s） |

**交叉引用**：[内核计算超时与性能定标.md](内核计算超时与性能定标.md) · `.cursor/rules/ascendc-development.mdc`「用例计算超时」· `ascendc-tests/INDEX.md`
