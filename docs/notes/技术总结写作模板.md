# 技术总结写作模板

**用途**：在 `docs/notes/` 新建定稿技术总结时复制结构。  
**规范**：[docs-archiving.mdc](../../.cursor/rules/docs-archiving.mdc)「写作质量」  
**范例**：[F203-2s1e-NTT内积UB融合技术总结.md](F203-2s1e-NTT内积UB融合技术总结.md)

---

## 原则

| 教什么 | 不教什么 |
|--------|----------|
| 数学对象、数据契约、与 \((N,K,q)\) 等参数的关系 | 只背某次探针的 tick 数字 |
| 与函数名无关的工程不变量 | 只有 `pairCount_`、`stageFoo` 的踩坑表 |
| 可复用模式（读者未接触过本仓库也能套用） | 内部目录代号当文件名 |
| 验证方法论（Stage Gate、Early Probe、golden 角色） | 当日争论、未拍板备选作主结构 |

**类比**：先讲「加法交换律」，再举 `1+1=2` 印证；案例放 **附录**，并映射回原理章节。

---

## 文件命名

- 路径：**`docs/notes/<主题>-技术总结.md`** 或 **`docs/notes/<平台>-<主题>知识库.md`**
- 主题用可读中文或完整英文短语（算子族、阶段、结论类型）
- **禁止**仅用探针目录代号（`poly2`、`s12`、`batch-ntt-limb6`）
- 探针路径、日期、tick 写在正文附录，不塞进文件名

讨论过程 → `qa/YYYY-MM/`；实现方案 → 用例目录 `INTEGRATION_PLAN.md`。
