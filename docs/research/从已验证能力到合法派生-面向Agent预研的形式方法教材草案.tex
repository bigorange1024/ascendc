{\large 面向 Agent 的预研开发形式方法\\（教材式草案·持续修订）}}

\begin{abstract}
\textbf{愿景}：把「层层递进、先验证底层再拼高层」的工程直觉，提升为一套可教学、可门禁、可对照实验的形式方法——
使 Agent（以及人类协作者）在复杂预研任务中，\textbf{只沿已验证能力及其合法组合}生长实现，
从机制上压缩跳层发明与幻觉空间；最终服务一般预研开发，而非仅服务某一密码标准的算子清单。

\textbf{写法}：仿教材而非论文——先从特例讲故事，再抽象数学对象，再复盘与前瞻；
证明与完备性后置，允许边做边补。\textbf{地位}：\texttt{docs/research/} 调研草稿，非定稿、非交付验收依据。

\textbf{压力测试床}：ML-KEM-1024 链上的 \texttt{pke.keygen} / \texttt{kem.keygen} / \texttt{kem.encaps}，
并以 \texttt{kem.decaps} 为理论前瞻试金石；\texttt{*-correctness-*} 作为「只求正确、不计优化」的对照组标本。
\end{abstract}

\section{愿景、读者与本文怎么读}

\subsection{愿景（一句话）}
我们想表达的是：把复杂实现/预研交给 AI Agent 时，\textbf{不应当}把「输出对拍过」当成任务完成，
更不应当让它在开放文本空间里自由寻找答案；
而应把开放生成收成「沿已验证能力的可检查闭包做受控搜索」——少发散、少无效派生，把项目真正做完。
静态依赖图只是「谁依赖谁」的投影；真正的作业过程还要另说。

\subsection{我们希望最终得到什么}
\begin{enumerate}
  \item 一套\textbf{教材式}叙述：新人 / 新 Agent 能从特例读懂「图从哪来、树怎么长」；
  \item 一套\textbf{可操作门禁}：任务启动必须先交依赖闭包与缺项，再写码；
  \item 一套\textbf{对照实验协议}：方法论指导下的实现 vs correctness 标本 vs 人工指导路径；
  \item （成型后）可解释的接受/拒绝轨迹，以及必要的证明——\textbf{不}作为本稿前置条件。
\end{enumerate}

\section{一个完整例子：我们怎样做出 ML-KEM-1024 的 KEM.KeyGen}
\label{sec:hook}

本章用一个\textbf{已经做完}的真实任务当例子。
我们先说清楚「要算什么」，再贴 FIPS~203 里的算法原文，
然后交代我们手里已经有什么、前期做过哪些实验、最后怎样拼出 KEM.KeyGen。
例子讲完之后，我们再\textbf{提问}——这些问题应当能把读者自然带到后文的研究课题里。

\subsection{我们要交付什么}

我们的目标是：在 Ascend AI Core 上用 AscendC 实现
\textbf{FIPS~203 ML-KEM-1024 的密钥生成}（\texttt{ML-KEM.KeyGen}，即 Algorithm~19）。

读者可以把交付物理解成下面这张黑盒表（细节以 stable 目录 customspec 为准）：

\begin{center}
\begin{tabular}{@{}lll@{}}
  \toprule
  方向 & 内容 & 说明 \\
  \midrule
  输入 & \texttt{seed\_d.bin}（4\,B） & Host 写入；设备侧派生 $d$、$z$ \\
  输入 & NTT LUT（静态） & 与 PKE KeyGen 同表 \\
  输出 & \texttt{ek\_kem.bin}（1568\,B） & 与 \texttt{ek\_PKE} 相同 \\
  输出 & \texttt{dk\_kem.bin}（3168\,B） & 与 liboqs 展开布局一致 \\
  \bottomrule
\end{tabular}
\end{center}

我们\textbf{不}把 $d$、$z$、中间 $\hat{A}$、$\hat{s}$ 等当作交付文件落盘。
验收方式是：\texttt{run.sh} 跑 CPU 孪生 + SIM，输出与 golden / liboqs 对拍一致。

\subsection{FIPS~203 原文：三层算法怎样套在一起}

标准把 KEM 密钥生成拆成三层。
下面给出\textbf{与 FIPS~203 原文一致的参数、Input/Output 与步骤编号}。
正文引用 NIST FIPS~203 Algorithm~13 / 16 / 19；本文实例固定为 \texttt{ml\_kem\_1024}（$k{=}4$ 时 $\lvert\mathit{ek}\rvert{=}1568$\,B，$\lvert\mathit{dk}\rvert{=}3168$\,B）。

\begin{fipsalgo}{Algorithm 19 \texttt{ML-KEM.KeyGen()}（FIPS~203 §7.1）}
\fipsioparam{$n{=}256$，$q{=}3329$，$k{=}4$，$\eta_1{=}\eta_2{=}2$，$d_u{=}11$，$d_v{=}5$。}
\fipsioin{（无显式输入；$d$、$z$ 在算法内由 RBG 采样，见步骤 1--2。）}
\fipsioout{封装密钥 $\mathit{ek} \in \mathbb{B}^{384k+32}$；\\
           解封密钥 $\mathit{dk} \in \mathbb{B}^{768k+96}$。}
\begin{fipssteps}
  \item $d \leftarrow\$ \mathbb{B}^{32}$
  \item $z \leftarrow\$ \mathbb{B}^{32}$
  \item \textbf{if} $d = \mathrm{NULL}$ \textbf{or} $z = \mathrm{NULL}$ \textbf{then}
  \item \quad\textbf{return} $\bot$ \hfill{\footnotesize RBG 失败指示}
  \item \textbf{end if}
  \item $(\mathit{ek}, \mathit{dk}) \leftarrow \texttt{ML-KEM.KeyGen\_internal}(d, z)$
  \item \textbf{return} $(\mathit{ek}, \mathit{dk})$
\end{fipssteps}
\end{fipsalgo}

\begin{fipsalgo}{Algorithm 16 \texttt{ML-KEM.KeyGen\_internal}$(d, z)$（FIPS~203 §6.1）}
\fipsioparam{$n{=}256$，$q{=}3329$，$k{=}4$，$\eta_1{=}\eta_2{=}2$，$d_u{=}11$，$d_v{=}5$。}
\fipsioin{随机种子 $d \in \mathbb{B}^{32}$；随机种子 $z \in \mathbb{B}^{32}$。}
\fipsioout{封装密钥 $\mathit{ek} \in \mathbb{B}^{384k+32}$；\\
           解封密钥 $\mathit{dk} \in \mathbb{B}^{768k+96}$。}
\begin{fipssteps}
  \item $(\mathit{ek}_{\mathrm{PKE}}, \mathit{dk}_{\mathrm{PKE}}) \leftarrow \texttt{K-PKE.KeyGen}(d)$
  \item $\mathit{ek} \leftarrow \mathit{ek}_{\mathrm{PKE}}$
  \item $\mathit{dk} \leftarrow \mathit{dk}_{\mathrm{PKE}} \Vert \mathit{ek} \Vert H(\mathit{ek}) \Vert z$
  \item \textbf{return} $(\mathit{ek}, \mathit{dk})$
\end{fipssteps}
\end{fipsalgo}

\noindent 其中 $H = \mathrm{SHA3\text{-}256}$（FIPS~203 记号 $H$）。

\begin{fipsalgo}{Algorithm 13 \texttt{K-PKE.KeyGen}$(d)$（FIPS~203 §5.1）}
\fipsioparam{$n{=}256$，$q{=}3329$，$k{=}4$，$\eta_1{=}\eta_2{=}2$，$d_u{=}11$，$d_v{=}5$。}
\fipsioin{随机种子 $d \in \mathbb{B}^{32}$。}
\fipsioout{加密密钥 $\mathit{ek}_{\mathrm{PKE}} \in \mathbb{B}^{384k+32}$；\\
           解密密钥 $\mathit{dk}_{\mathrm{PKE}} \in \mathbb{B}^{384k}$。}
\begin{fipssteps}
  \item $(\rho, \sigma) \leftarrow G(d \Vert k)$ \hfill{\footnotesize 域分离：字节 33 为模块维 $k$}
  \item $N \leftarrow 0$
  \item \textbf{for} $i \leftarrow 0$ \textbf{to} $k-1$ \textbf{do}
  \item \quad\textbf{for} $j \leftarrow 0$ \textbf{to} $k-1$ \textbf{do}
  \item \quad\quad$\hat{A}[i,j] \leftarrow \texttt{SampleNTT}(\rho \Vert j \Vert i)$
  \item \quad\textbf{end for}
  \item \textbf{end for}
  \item \textbf{for} $i \leftarrow 0$ \textbf{to} $k-1$ \textbf{do}
  \item \quad$s[i] \leftarrow \texttt{SamplePolyCBD}_{\eta_1}(\texttt{PRF}_{\eta_1}(\sigma, N))$;\quad $N \leftarrow N+1$
  \item \textbf{end for}
  \item \textbf{for} $i \leftarrow 0$ \textbf{to} $k-1$ \textbf{do}
  \item \quad$e[i] \leftarrow \texttt{SamplePolyCBD}_{\eta_1}(\texttt{PRF}_{\eta_1}(\sigma, N))$;\quad $N \leftarrow N+1$
  \item \textbf{end for}
  \item $\hat{s} \leftarrow \texttt{NTT}(s)$
  \item $\hat{e} \leftarrow \texttt{NTT}(e)$
  \item $\hat{t} \leftarrow \hat{A} \circ \hat{s} + \hat{e}$ \hfill{\footnotesize NTT 域矩阵–向量乘加}
  \item $\mathit{ek}_{\mathrm{PKE}} \leftarrow \texttt{ByteEncode}_{12}(\hat{t}) \Vert \rho$
  \item $\mathit{dk}_{\mathrm{PKE}} \leftarrow \texttt{ByteEncode}_{12}(\hat{s})$
  \item \textbf{return} $(\mathit{ek}_{\mathrm{PKE}}, \mathit{dk}_{\mathrm{PKE}})$
\end{fipssteps}
\end{fipsalgo}

\textbf{读者只需抓住一条结构链}：
$\text{Alg.19} \Rightarrow \text{Alg.16} \Rightarrow \text{Alg.13}$。
Alg.19 比 Alg.13 \textbf{多出来的}主要是步骤 1--2 的 $z$、Alg.16 步骤 3 的拼接——
\textbf{并不是}把 NTT 或矩阵乘从头再写一遍。

\paragraph{本仓工程差异（验收已锁定，写在算法旁便于对照）}
\begin{itemize}
  \item 我们可复现跑分时，Host 只提供 4\,B \texttt{seed\_d}；$d$ 与 $z$ 在设备 UB 内派生（对应 Alg.19 步骤 1--2 的确定性扩展）。
  \item 我们对拍 liboqs 时，$\mathit{dk}$ 为 3168\,B 展开式
        $\mathit{dk\_pke}\Vert\mathit{ek}\Vert H\Vert z$，与 FIPS 代数最小形态一致，但字节布局与偏移以 customspec 为准。
\end{itemize}

\subsection{从这个例子出发，我们应当问什么？}

例子讲完，真正重要的是\textbf{问题}。
如果我们的研究课题是「怎样让 Agent 预研少幻觉、少撞墙」，
那么面对 KEM.KeyGen 这个故事，我们至少应当认真问下面四组问题。

\paragraph{第一组：标准与工程之间的缝隙}
\begin{enumerate}
  \item FIPS 只告诉我们\textbf{算什么}；它并没有告诉我们，在 Ascend 上应当\textbf{先验哪几块、按什么顺序拼}。
        我们凭什么在动手前就说「可以直接站在 stable PKE 上」——凭的是目录名，还是某种可写的证书？
  \item 探针列表（INDEX）像一张「能力菜单」。
        \textbf{菜单本身}是否等于\textbf{合法拼装说明书}？若不等，缺的那一页应当长什么样？
\end{enumerate}

\paragraph{第二组：「单点都对」之后，组合还对吗}
\begin{enumerate}
  \setcounter{enumi}{2}
  \item 当 NTT 探针 PASS、PKE KeyGen PASS 之后，\textbf{谁}来保证「2-launch 接缝」「Alg.16 尾拼 $\mathit{dk}$」也一定 PASS？
        我们能否把这种「组合不免费」写进理论，而不是每次靠工程师的经验？
  \item 若我们把 correctness 路线（更多 launch、更保守同步）与 device/stable 路线（更少 launch、吃到优化）
        都称为「正确」，\textbf{我们究竟在验收什么}——仅仅是输出字节，还是也要验收「沿已证能力生长」？
\end{enumerate}

\paragraph{第三组：Agent 若只知道算法和菜单，会发生什么}
\begin{enumerate}
  \setcounter{enumi}{4}
  \item 若我们只给 Agent 一段 Alg.19 伪代码 + INDEX 里有哪些探针 PASS，
        \textbf{但不给}确定的拼装路线，搜索空间会有多大？
        我们亲眼见过：过程高度混乱、大量回退、极耗 token，最后只留下「能跑对」的 correctness 标本。
  \item 我们能否把搜索空间收束为「只允许沿已证书边生长」，同时又\textbf{不}把工程优化堵死？
        收束的规则应当写在图里，还是写在某种「合法句子」里？
\end{enumerate}

\paragraph{第四组：怎样把一次成功变成可复用的方法}
\begin{enumerate}
  \setcounter{enumi}{6}
  \item 这次 KEM.KeyGen 的成功，能否被复述成一张\textbf{闭包表}：
        依赖谁、缺了谁、哪条边有证书、哪条边被禁止？
        若下一个人（或 Agent）做 Encaps / Decaps，我们能否\textbf{先交这张表再写码}？
  \item 当上游改了 tiling 或同步壳，下游哪些节点应当自动标「脏」？
        我们是否需要一种比「记得上次 PASS」更可靠的失效传播？
\end{enumerate}

\begin{itemize}
  \item \textbf{第一组}：我们能指着 stable PKE 说「KEM 应站在这里」，但还缺一张人人（含 Agent）都认的\textbf{证书页}。
  \item \textbf{第二组}：我们知道接缝要单独验（例如 2-launch、尾缝），但还没把这条经验收成\textbf{可检查的规则}。
  \item \textbf{第三组}：我们能用 correctness 证明「只给菜单会爆炸」；方法论要证明的是「给规则后能收敛」——这正是本专题要做的事。

\paragraph{这些问题的共同指向}

上面这些问题，表面上各不相同，但它们指向同一条研究主线：

\begin{quote}
我们能否把「已验证能力 + 合法组合 + 动态证书」整理成一套\textbf{可教、可检查、可对照实验}的形式方法——\\
让 Agent 的工作从「在菜单里瞎拼」变成「在自动机上走合法派生」？
\end{quote}

后文先用一章\textbf{方法论导论 + 数学底座}（第~\ref{sec:mathbg}~章）把工程策略说清并落到定义，
再把这些对象\textbf{装进工程语境}并写成门禁（第~\ref{sec:math}--\ref{sec:gates}~章），
最后用 Encaps 复盘、Decaps 前瞻检验这套语言是否管用。
\textbf{本章与后文均不展开} PQC / 数论变换等密码代数——那些细节见 \texttt{docs/notes/}；本专题专注方法论。

\subsection{导论：引子、问题实质、方法实质与工具落点}
\label{sec:mathbg-intro}
\label{sec:mathbg-why}

若一上来就讲集合与函数，读者容易以为本章只是在堆数学名词。
导论按三条线展开：先讲一件真实发生过的事（\textbf{correctness 引子}），
再抽象\textbf{问题的实质}与\textbf{方法的实质}，最后才落到架构直觉与三件数学工具。
正式定义从 §~\ref{sec:set-rel} 开始。

\subsubsection{引子：correctness 有了，任务就算完成了吗？}

故事发生在 Encaps / Decaps 这一刀。
当时仓库里已经有一批对拍通过的底层能力——NTT、内积、hash 等用例大致齐了；
Rule、Skill 与目录结构也相对清楚。
任务提示写得很轻：大致是让 Agent 自行阅读 FIPS~203，
在这些已有能力之上，把封装与解封装「做出来」。

从 correctness 看，Agent 确实交差了：输出能对上期望，像是做完了。
把过程与形态摊开，却是另一幅图：

\begin{itemize}
  \item \textbf{只保结果对}：工程路径极其简单粗暴，几乎不为 Ascend NPU 的架构与 AscendC 工具链特点做设计，
        性能差到不可用；
  \item \textbf{搜索空间几乎不设界}：AscendC 公开资料远少于成熟的 C/C++、Python，Agent 到处碰壁，
        反复试错与 debug，为了凑出 correctness，不惜采用极端低效的数据布局与任务调度；
  \item \textbf{成本失控}：短时间内耗尽约一个月的 token 配额；
  \item \textbf{还沉淀错东西}：过程中冒出并不正确的「经验」与结论，若不当场拆穿，会污染后续任务。
\end{itemize}

这件事把一种诱惑钉死了：\textbf{correctness 很容易被当成完成}。
但若只盯结果对、又把找答案的空间交给 Agent 在开放文本里自由闯，
得到的往往是伪完成——结果碰巧对，过程发散、形态不可用、钱与时间被烧光。

有了这层引子，才值得追问：问题的实质究竟是什么？该方法论又要把 Agent 收成怎样一种工作方式？

\subsubsection{问题的实质：开放生成被当成了合法派生}

大语言模型按概率在开放文本空间里续写，并不自带
「只能站在已验证能力上、按允许的方式往上推」这条不变量。
人在开放研究里也会发散；LLM 驱动的 Agent 只是把错误探索的\textbf{速度与代价}放大了。

引子里那些表象——可试的路像无穷多、乱试极贵、零件都绿整机却不可用——根子往往不在
「项目管理缺一张表」，而在于：

\begin{quote}
\noindent
\textbf{执行者把开放生成误当成了合法派生}：\\
菜单里有、局部测通、文本上看起来像解，就被当成「整体已经合法、可以交付」。
\end{quote}

工程语境里的「幻觉」，多半不是文学式的胡编，而是\textbf{无效派生}：
把语言里的非成员当成成员，把未获证节点当成可引用能力，把接缝与接口约定跳过去。
模块拆分、单元测试、版本管理仍然必要，但它们管的是代码资产与回归，
\textbf{不管}「Agent 下一步还准许做什么」。

所以真正要盯住的问题不是「Agent 会不会写出几段能正确对拍的 AscendC 代码」，而是：
\textbf{如何阻止它把无界生成当作完成预研/实现的合法途径？}

\subsubsection{方法的实质：要将无界生成问题转化为已认证闭包上的受限规划搜索，以已认证资产为世界模型}

对策不是让 Agent「优化代码」，而是换一种工作定义：

\begin{quote}
\noindent
\textbf{从「看起来合理就写」，转到「只沿已认证能力的可检查闭包推进」。}\\
别把 Agent 当自由写手，要把它当\textbf{证书闭包上的搜索器}。
\end{quote}

当前准许的下一步，由三类可检查对象界定（后文用数学钉名）：

\begin{enumerate}
  \item \textbf{已验证能力}：现在还能引用谁；
  \item \textbf{禁止项}：明确不能再当模板的路（含已关闭路线）；
  \item \textbf{合法拼装规则}：怎样衔接才算一步合法推进；缺的先补齐并验过，再往上引用。
\end{enumerate}

再加一条过程约束：作业状态本身可检查——走到哪算完成，下层约定一改，上层哪些「曾经通过」作废。

这里说的「有限」，精确含义是：\textbf{相对于当前能力集、禁止项与拼装规则，可接受的下一步是可枚举、可检查的}；
并不是说研究空间永久冻结——集合可以随新能力获证而长大。

收益是有条件的：当组合深、错路贵时，维护证书与禁止项才划算——少烧无效 token，少交付「只有 correctness、没有工程形态」的伪完成。
第~\ref{sec:hook}~章 KeyGen 是收得住的对照；引子里的 Encaps / Decaps 放飞，则是反面教材。
INDEX、\texttt{frozen/}、customspec、晋级复制、CPU+SIM 等，已是纪律雏形；

\subsubsection{我们已经收敛出的架构与流程（直觉图像）}

\subsubsection{集合、笛卡尔积、关系与函数}
\label{sec:set-rel}

\begin{definition}[集合与属于关系]
称由确定对象组成的汇集为\textbf{集合}。
若对象 $x$ 属于集合 $A$，记 $x\in A$；否则记 $x\notin A$。
不含任何元素的集合称为\textbf{空集}，记作 $\emptyset$。
若 $A$ 的每个元素都属于 $B$，称 $A$ 为 $B$ 的\textbf{子集}，记 $A\subseteq B$。
\end{definition}

\begin{definition}[幂集]
设 $V$ 为集合。由 $V$ 的\textbf{全部子集}组成的集合称为 $V$ 的\textbf{幂集}，记作 $2^{V}$
（亦常记作 $\mathcal{P}(V)$）。用集合造集的写法即
\[
2^{V}
\;=\;
\{\,A\mid A\subseteq V\,\}.
\]
特别地：$\emptyset\in 2^{V}$，$V\in 2^{V}$；若 $V$ 有限且 $|V|=n$，则 $|2^{V}|=2^{n}$
（这正是记号 $2^{V}$ 的来源）。

映射 $f:2^{V}\to 2^{V}$ 表示：输入是 $V$ 的某个子集，输出仍是 $V$ 的某个子集。
\end{definition}

\begin{remark}[为何是 $2^{V}$，而不是 $3^{V}$、$4^{V}$]
底数 $2$ 来自构造子集时的\textbf{二元选择}：对 $V$ 中每个元素，只有「放进该子集」或「不放进」两种可能。
因此不同子集的个数是 $2\times 2\times\cdots\times 2$（共 $|V|$ 个因子），即 $2^{|V|}$。
若改写成 $3^{V}$，一般既不等于「全部子集的集合」，也没有上述计数意义
（除非另作约定，例如讨论「每个元素三种染色」的函数集 $\{0,1,2\}^{V}$，那是另一对象）。

等价观点：把 $2$ 看成二元集 $\{0,1\}$，则 $2^{V}$ 也可理解为「全体函数 $V\to\{0,1\}$」
（特征函数：取 $1$ 表示属于子集，取 $0$ 表示不属于）；这与「全部子集」一一对应。
\end{remark}

\begin{example}[纯数学：幂集]
令 $V=\{a,b\}$。则
\[
2^{V}
=\bigl\{\,\emptyset,\;\{a\},\;\{b\},\;\{a,b\}\,\bigr\},
\qquad |2^{V}|=4=2^{2}.
\]
\end{example}

\begin{definition}[笛卡尔积]
设 $A,B$ 为集合。其\textbf{笛卡尔积}为
\[
A\times B \;=\; \{\,(a,b)\mid a\in A,\; b\in B\,\}.
\]
元素 $(a,b)$ 称为\textbf{有序对}；一般地 $(a,b)=(a',b')$ 当且仅当 $a=a'$ 且 $b=b'$。
\end{definition}

\begin{definition}[二元关系]
设 $A,B$ 为集合。若 $R\subseteq A\times B$，则称 $R$ 为从 $A$ 到 $B$ 的\textbf{二元关系}。
当 $A=B$ 时，也称 $R$ 为 $A$ 上的二元关系。
若 $(a,b)\in R$，常简记为 $a\,R\,b$。
\end{definition}

\begin{definition}[关系的定义域与值域]
对关系 $R\subseteq A\times B$，定义
\[
\mathrm{dom}(R)=\{a\in A\mid \exists b\in B,\;(a,b)\in R\},
\quad
\mathrm{ran}(R)=\{b\in B\mid \exists a\in A,\;(a,b)\in R\}.
\]
\end{definition}

\begin{definition}[函数]
设 $A,B$ 为集合。称关系 $f\subseteq A\times B$ 为从 $A$ 到 $B$ 的\textbf{函数}
（记 $f:A\to B$），若对每个 $a\in A$，存在唯一的 $b\in B$ 使得 $(a,b)\in f$。
此时记 $b=f(a)$，称 $b$ 为 $a$ 在 $f$ 下的\textbf{像}。
\end{definition}

\begin{property}[关系与函数的对比]
二元关系允许「一个 $a$ 对应多个 $b$」；函数禁止这一点。
后文「证书状态赋值」按函数理解；「依赖边」按一般关系理解。
\end{property}

\subsubsection{有向图、路与环}
\label{sec:digraph}

\begin{definition}[有向图]
\textbf{有向图}是一个有序对 $G=(V,E)$，其中 $V$ 为非空有限集（称为\textbf{顶点集}），
$E\subseteq V\times V$ 为\textbf{有向边集}。
若 $(u,v)\in E$，称有向边 $u\to v$，并称 $u$ 为该边的\textbf{起点}，$v$ 为\textbf{终点}。
\end{definition}

\begin{definition}[出邻域与入邻域]
对 $v\in V$，定义
\[
N^+(v)=\{u\in V\mid (v,u)\in E\},
\quad
N^-(v)=\{u\in V\mid (u,v)\in E\}.
\]
分别称为 $v$ 的\textbf{出邻域}与\textbf{入邻域}；
$|N^+(v)|$、$|N^-(v)|$ 称为出度、入度。
\end{definition}

\begin{definition}[有向途径、路径与环]
设 $G=(V,E)$。
\begin{enumerate}
  \item 顶点序列 $v_0,v_1,\ldots,v_k$（$k\ge 0$）称为\textbf{有向途径}，若对所有 $0\le i<k$ 有 $(v_i,v_{i+1})\in E$；
        称 $k$ 为该途径的\textbf{长度}。
  \item 若途径中顶点两两不同，则称为\textbf{有向路径}（简称路径）。
  \item 若 $k\ge 1$、$v_0=v_k$，且 $v_0,\ldots,v_{k-1}$ 两两不同，则称为\textbf{有向环}（简称环）。
\end{enumerate}
\end{definition}

\begin{definition}[可达]
若存在从 $u$ 到 $v$ 的有向途径，则称 $v$ 从 $u$ \textbf{可达}，记 $u\rightsquigarrow_G v$
（在上下文明确时可略去 $G$）。约定任意 $v$ 满足 $v\rightsquigarrow v$（长度为 $0$ 的途径）。
\end{definition}

\begin{lemma}[路径与途径]
在有限有向图中，$u\rightsquigarrow v$ 当且仅当存在从 $u$ 到 $v$ 的有向路径。
\end{lemma}
\begin{proof}
若存在途径，删去其上环段可得路径；反之，路径本身是途径。
\end{proof}

\begin{example}[纯数学：四点有向图]
令 $V=\{1,2,3,4\}$，$E=\{(1,2),(1,3),(2,4),(3,4)\}$。
则 $1\rightsquigarrow 4$，且存在两条不同路径 $1\to2\to4$ 与 $1\to3\to4$。
$4$ 的入邻域为 $N^-(4)=\{2,3\}$，出邻域 $N^+(4)=\emptyset$。
该图无环。

\subsubsection{有向无环图与拓扑序}
\label{sec:dag-topo}

\begin{definition}[DAG]
若有向图 $G$ 不含有向环，则称 $G$ 为\textbf{有向无环图}（Directed Acyclic Graph，DAG）。
\end{definition}

\begin{definition}[拓扑序]
设 $G=(V,E)$，$|V|=n$。
顶点序列 $v_1,\ldots,v_n$ 称为 $G$ 的一个\textbf{拓扑序}，
若它是 $V$ 的排列，且对每条边 $(v_i,v_j)\in E$ 都有 $i<j$。
\end{definition}

\begin{theorem}[DAG 与拓扑序的刻画]
设 $G$ 为有限有向图。则下列条件等价：
\begin{enumerate}
  \item $G$ 是 DAG；
  \item $G$ 存在拓扑序。
\end{enumerate}
\end{theorem}
\begin{proof}[证明梗概]
（2）${\Rightarrow}$（1）：若有环，则环上边无法全部满足「起点下标小于终点下标」。\\
（1）${\Rightarrow}$（2）：DAG 中必有入度为 $0$ 的顶点；取其为 $v_1$，删去后再对剩余图归纳。
\end{proof}

\begin{corollary}[可按先决条件调度]
若依赖关系构成 DAG，则存在线性顺序，使得每条依赖边都从「先处理」指向「后处理」。
\end{corollary}

\begin{remark}[预研建模提示]
「先验证下层能力，再拼上层任务」要求依赖关系可拓扑排序，因而应建模为 DAG。
若出现环，通常意味着节点切分不清或误把双向约束画成了依赖。
\end{remark}

\subsubsection{闭包：从一般概念到依赖闭包与缺项}
\label{sec:closure}

前几小节已有集合、关系、有向图。这里先回答：
\textbf{数学里说的「闭包」究竟是什么？}
再落到能力依赖图上的\textbf{依赖闭包}、\textbf{已获证}与\textbf{缺项}。

\paragraph{在运算下封闭}

\begin{definition}[一元运算下的封闭性]
设 $U$ 为全集（讨论所在的大集合），$A\subseteq U$，
又设 $\varphi:U\to U$ 为一元运算（函数）。
称 $A$ 对 $\varphi$ \textbf{封闭}（或「在 $\varphi$ 下封闭」），若
\[
\forall x\in A,\quad \varphi(x)\in A.
\]
即：从 $A$ 里任取元素做一次 $\varphi$，结果仍落在 $A$ 里。
\end{definition}

\begin{definition}[二元运算下的封闭性]
设 $*\!:U\times U\to U$ 为二元运算。
称 $A\subseteq U$ 对 $*$ \textbf{封闭}，若
\[
\forall x,y\in A,\quad x*y\in A.
\]
\end{definition}

\begin{definition}[对一族运算封闭]
若给定若干运算（可混一元、二元），称 $A$ 对它们\textbf{封闭}，
当且仅当 $A$ 对其中每一个运算都封闭。
\end{definition}

\begin{example}[纯数学：封闭与不封闭]
取 $U=\mathbb{Z}$。
\begin{itemize}
  \item 偶数集 $2\mathbb{Z}$ 对加法封闭：两偶数之和仍为偶数。
  \item 奇数集对加法\textbf{不}封闭：$1+1=2$ 不是奇数。
  \item $\{0,1,2\}$ 对「加 $1$」这一元运算不封闭，因为 $\varphi(2)=3\notin\{0,1,2\}$。
\end{itemize}

\paragraph{闭包：最小的封闭扩张}

直观想法：给定种子集合 $A$，以及若干「生成规则」（运算），
我们希望找到\textbf{既包含 $A$，又对规则封闭，又尽可能小}的集合。
这个最小集合就叫做 $A$ 的闭包。

\begin{definition}[闭包（由封闭性刻画）]
设 $U$ 为全集，$A\subseteq U$，并固定一组使子集可谈「封闭」的运算规则 $\mathcal{R}$。
称 $B\subseteq U$ 为 $A$ 关于 $\mathcal{R}$ 的一个\textbf{闭包}，若：
\begin{enumerate}
  \item $A\subseteq B$（包含种子）；
  \item $B$ 对 $\mathcal{R}$ 封闭；
  \item 若 $C\supseteq A$ 且 $C$ 对 $\mathcal{R}$ 封闭，则 $B\subseteq C$
        （$B$ 是所有「含 $A$ 的封闭集」中的\textbf{最小}者）。
\end{enumerate}
若这样的 $B$ 存在，常记作 $\mathrm{Cl}_{\mathcal{R}}(A)$，或在上下文明确时记 $\mathrm{Cl}(A)$。
\end{definition}

\begin{theorem}[闭包的存在性（有限情形够用版）]
若 $U$ 有限，则对任意 $A\subseteq U$ 与任意「从已有元素产生新元素」的规则族 $\mathcal{R}$
（形式：由已有元组确定性地加入有限个新点），$\mathrm{Cl}_{\mathcal{R}}(A)$ 存在且唯一，
并可取为
\[
\mathrm{Cl}_{\mathcal{R}}(A)
\;=\;
\bigcap\{\,C\subseteq U\mid A\subseteq C,\; C\text{ 对 }\mathcal{R}\text{ 封闭}\,\}.
\]
（任意一族含 $A$ 的封闭集，其交仍含 $A$ 且封闭；有限全集上该族非空，因 $U$ 本身封闭。）
\end{theorem}
\begin{proof}[证明梗概]
验证「含 $A$ 的封闭集」对任意交封闭，故交集是最小元。唯一性由最小性立即得到。
\end{proof}

\begin{remark}[两种看法同一个对象]
\begin{itemize}
  \item \textbf{由外向内}：所有合格封闭集的交；
  \item \textbf{由内向外}：从 $A$ 出发反复施加规则，直到不能再扩大（见下一小节迭代）。
\end{itemize}
后文算法几乎总用「由内向外」。
\end{remark}

\begin{definition}[迭代构造（一般模板）]
设规则是：对当前集合 $X$，令 $\Phi(X)$ 为「把 $X$ 对规则应用一轮后应有的元素」
（要求 $X\subseteq\Phi(X)$）。定义
\[
A_0=A,\qquad A_{k+1}=\Phi(A_k)\quad(k\ge 0),\qquad
A_\infty=\bigcup_{k\ge 0}A_k.
\]
在有限全集且 $\Phi$ 单调时，存在 $K$ 使 $A_K=A_{K+1}=\cdots=A_\infty$，且 $A_\infty=\mathrm{Cl}(A)$。
\end{definition}

\paragraph{闭包算子}

不必每次都提运算 $\mathcal{R}$，也可以直接把「取闭包」看成作用在幂集上的函数
（幂集 $2^{U}$ 的定义见 §3.2）。

\begin{definition}[闭包算子]
设 $U$ 为集合。映射 $\mathrm{Cl}:2^{U}\to 2^{U}$ 称为\textbf{闭包算子}，若对任意 $A,B\subseteq U$
（即对任意 $A,B\in 2^{U}$）：
\begin{enumerate}
  \item \textbf{扩张性}：$A\subseteq \mathrm{Cl}(A)$；
  \item \textbf{单调性}：$A\subseteq B\Rightarrow \mathrm{Cl}(A)\subseteq\mathrm{Cl}(B)$；
  \item \textbf{幂等性}：$\mathrm{Cl}(\mathrm{Cl}(A))=\mathrm{Cl}(A)$。
\end{enumerate}
称 $\mathrm{Cl}(A)$ 为 $A$ 的\textbf{闭包}；若 $A=\mathrm{Cl}(A)$，称 $A$ 为\textbf{闭集}（对该算子而言）。
\end{definition}

\begin{proposition}[闭集即「已经封闭」]
$A$ 为闭集当且仅当 $\mathrm{Cl}(A)=A$。
对由规则 $\mathcal{R}$ 导出的闭包算子，闭集恰好是对 $\mathcal{R}$ 封闭的那些子集。
\end{proposition}

\begin{property}[闭包是「补全到封闭」]
$\mathrm{Cl}(A)$ 可以理解为：从 $A$ 出发，把所有被规则逼出来的点都补上，直到不能再补。
幂等性说：补第二次不会再增加新点。
\end{property}

\begin{example}[纯数学：若干熟悉的闭包]
\begin{center}
\begin{tabular}{@{}L{3.2cm}L{5.0cm}L{5.2cm}@{}}
  \toprule
  场景 & 种子 $A$ & 闭包在补什么 \\
  \midrule
  实数区间 & $\{0,1\}$ & 对「中间点」封闭 $\to [0,1]$（拓扑闭包的朴素版） \\
  线性代数 & 若干向量 & 对加与数乘封闭 $\to$ 生成子空间 \\
  关系 & 边集 $E$ & 对「可走更长路径」封闭 $\to E^{*}$（下一小节） \\
  \bottomrule
\end{tabular}
\end{center}
\end{example}

\paragraph{关系的传递闭包：闭包的第一个正式例子}

现在回到二元关系。这是连接「一般闭包」与「图上依赖闭包」的桥梁。

以下固定有限集 $V$，关系 $R\subseteq V\times V$。

\begin{definition}[关系的复合与幂]
对 $R,S\subseteq V\times V$，定义复合
\[
R\circ S=\{\,(u,w)\mid \exists v,\;(u,v)\in R,\;(v,w)\in S\,\}.
\]
令 $R^{1}=R$，$R^{k+1}=R^{k}\circ R$，并令 $R^{0}=\Delta_V=\{(v,v)\mid v\in V\}$。
注意：$R^{0}$ 是\textbf{单独约定}的恒等关系，表示长度为 $0$ 的途径；
它\textbf{不是}把 $R$ 与自身复合得到的（复合从 $R^{1}$、$R^{2},\ldots$ 才开始）。
\end{definition}

\begin{definition}[传递闭包与自反传递闭包]
\[
R^{+}=\bigcup_{k\ge 1}R^{k},
\qquad
R^{*}=\bigcup_{k\ge 0}R^{k}=R^{0}\cup R^{+}.
\]
称 $R^{+}$ 为 $R$ 的\textbf{传递闭包}，$R^{*}$ 为\textbf{自反传递闭包}。
\end{definition}

\begin{proposition}[$R^{*}$ 确实是闭包]
在「关系集合」$U=2^{V\times V}$ 上，若规则是「若有 $(u,v),(v,w)$ 则加入 $(u,w)$，且保留全部恒等对」，
则从 $R$ 生成的闭包恰为 $R^{*}$。
特别地：$R\subseteq R^{*}$，$R^{*}$ 传递且自反，且是满足这些性质的最小关系。
\end{proposition}

\begin{theorem}[传递闭包与路径]
$(u,v)\in R^{k}$ 当且仅当存在长度恰为 $k$ 的 $R$-途径从 $u$ 到 $v$。
因而 $(u,v)\in R^{*}$ 当且仅当 $u$ 经若干步（含 $0$ 步）到达 $v$。
\end{theorem}

\begin{example}[纯数学：三点关系的传递闭包]
令 $V=\{a,b,c\}$，$R=\{(a,b),(b,c)\}$。逐项按定义展开：
\begin{align*}
R^{0} &=\Delta_V=\{(a,a),(b,b),(c,c)
\} && \text{（恒等关系；\textbf{不是}由 $R$ 复合得到）}, \\
R^{1} &=R=\{(a,b),(b,c)\}, \\
R^{2} &=R\circ R=\{(a,c)
\} && \text{（复合：经中间点 $b$）}, \\
R^{+} &=R^{1}\cup R^{2}=\{(a,b),(b,c),(a,c)
\} && \text{（传递闭包：只含正长度路径）}, \\
R^{*} &=R^{0}\cup R^{+}=\{(a,a),(b,b),(c,c),(a,b),(b,c),(a,c)\}.
\end{align*}
因此：$(a,a)$ 这类对角元来自 $R^{0}$（$0$ 步路径约定），
\textbf{不是} $R\circ R$ 算出来的；本例中 $R$ 本身也没有自环。
图中三种线分别对应三类来源：

\begin{example}[工程预告]
若把「$u$ 是 $v$ 的直接先决」看成关系 $R$，
则「$u$ 是 $v$ 的直接或间接先决」就是 $(u,v)\in R^{*}$。

\paragraph{有向图上的依赖闭包}

从此固定有向图 $G=(V,E)$，并取边语义为依赖：
\[
u\to v \quad\text{表示}\quad\text{「$v$ \textbf{依赖} $u$」}
\quad\text{（$u$ 先决，$v$ 后继）}.
\]
与 §2 数据流箭头可能相反；\textbf{计算闭包以本节为准}。

\begin{definition}[转置图]
$G^{\top}=(V,E^{\top})$，$E^{\top}=\{(v,u)\mid (u,v)\in E\}$（箭头反向）。
\end{definition}

\begin{definition}[直接前驱 / 直接后继]
\[
\mathrm{Pred}_G(v)=N^-(v),\qquad
\mathrm{Succ}_G(v)=N^+(v).
\]
\end{definition}

\begin{definition}[祖先与后代]
若 $u\rightsquigarrow_G v$，称 $u$ 为 $v$ 的\textbf{祖先}，$v$ 为 $u$ 的\textbf{后代}
（含 $u=v$）。
\end{definition}

\begin{definition}[单点依赖闭包]
\label{def:dep-star}
\textbf{工程术语}：目标 $T$ 的\textbf{依赖闭包}——完成 $T$ 理论上必须齐备的全部先决能力（含 $T$ 自身）。\\
\textbf{数学记号}：固定依赖图 $G=(V,E)$，对目标 $T\in V$ 定义
\[
\mathrm{Dep}^*_G(T)
\;=\;
\{u\in V\mid u\rightsquigarrow_G T\}
\;=\;
\{u\in V\mid (u,T)\in E^{*}\}.
\]
恒有 $T\in\mathrm{Dep}^*_G(T)$。略下标时写作 $\mathrm{Dep}^*(T)$。
此后正文若写 $\mathrm{Dep}^*(T)$，一律读作「$T$ 的依赖闭包」。
\end{definition}

\begin{remark}[与一般闭包的对接]
取种子 $\{T\}$，规则为「若 $v$ 已在集合中，则把 $\mathrm{Pred}(v)$ 全部加入」。
则对该规则的闭包恰等于 $\mathrm{Dep}^*(T)$。
换言之：\textbf{依赖闭包 $=$ 「对取前驱封闭」的最小扩张}。
\end{remark}

\begin{proposition}[四种等价说法]
对任意 $u,T\in V$，下列等价：
\begin{enumerate}
  \item $u\in\mathrm{Dep}^*(T)$；
  \item $(u,T)\in E^{*}$；
  \item 存在路径 $u\to\cdots\to T$ 或 $u=T$；
  \item 在 $G^{\top}$ 中 $T\rightsquigarrow_{G^{\top}} u$。
\end{enumerate}
\end{proposition}

\paragraph{依赖闭包的迭代、算法与算子性质}

\begin{definition}[依赖闭包的迭代序列]
为计算 $\mathrm{Dep}^*(T)$，我们\textbf{新引入}一串辅助集合，记作
\[
D_0(T),\; D_1(T),\; D_2(T),\; \ldots
\]
（字母 $D$ 仅表示「Dependency 迭代的第几层近似」，下标 $k=0,1,2,\ldots$ 表示迭代步数；
前文并未使用过该记号，本定义即其首次出现。）

约定：
\begin{align*}
D_0(T) &= \{T\}
&& \text{（第 $0$ 步：只有目标本身）}, \\
D_{k+1}(T) &= D_k(T) \;\cup\; \bigcup_{v\in D_k(T)}\mathrm{Pred}(v)
&& \text{（第 $k{+}1$ 步：把当前集里每点的直接前驱都并进来）}.
\end{align*}
直观上：$D_k(T)$ 是「从 $T$ 沿依赖边反向走、最多 $k$ 步能摸到的点」所生成的集合
（含更近的点）；随着 $k$ 增大，集合只增不减。

这与前面「迭代构造（一般模板）」中的 $A_k$ 是同一类对象：
取种子 $A=\{T\}$、一轮算子 $\Phi(X)=X\cup\bigcup_{v\in X}\mathrm{Pred}(v)$ 时，
恰有 $D_k(T)=A_k$。
\end{definition}

\begin{theorem}[迭代收敛到依赖闭包]
对有限图 $G$，序列 $\{D_k(T)\}_{k\ge 0}$ 在有限步内稳定，且
\[
\bigcup_{k\ge 0} D_k(T) \;=\; \mathrm{Dep}^*(T).
\]
更精确地：存在 $K\le |V|$ 使对所有 $k\ge K$ 有 $D_k(T)=\mathrm{Dep}^*(T)$。
\end{theorem}
\begin{proof}[证明梗概]
$D_k(T)$ 单调递增且含于有限集 $V$，故稳定。
稳定时集合对取 $\mathrm{Pred}$ 封闭，且含 $T$，故包含一切能走到 $T$ 的顶点；
反之，任何通向 $T$ 的长度为 $\ell$ 的路径上的点在 $D_\ell(T)$ 中出现。
\end{proof}

\begin{remark}[与一般闭包模板的关系]
因此「迭代收敛到依赖闭包」就是一般闭包「由内向外」构造在依赖图上的具体化：
做够多步之后，$D_k(T)$ 不再变化，其稳定值就是 $\mathrm{Dep}^*(T)$。
\end{remark}

\begin{lemma}[反向搜索算法]
在有限图上执行：
从 $T$ 出发，在 $G^{\top}$ 中做 BFS/DFS（等价于沿 $G$ 的边反向走），
访问到的顶点集合恰为 $\mathrm{Dep}^*(T)$。
时间复杂度 $O(|V|+|E|)$（邻接表）。
\end{lemma}

\paragraph{目标集的闭包、基与缺项}

前几小节处理的是\textbf{单个}目标 $T$。
工程上一次任务往往同时盯住多个目标（或先把目标拆成若干子目标），
并且手里已有一份「哪些能力当前允许被引用」的清单——下文形式化为\textbf{已获证能力集}（数学记号 $\Gamma$）。
本小节先把依赖闭包从单点推广到有限目标集，再引入证书与缺项、生成集。

\paragraph{为何需要目标集}
若只定义单目标的依赖闭包 $\mathrm{Dep}^*(T)$，则同时要完成 $T_1,T_2$ 时，需要的先决整体是
$\mathrm{Dep}^*(T_1)\cup\mathrm{Dep}^*(T_2)$。
把它写成目标集的依赖闭包 $\mathrm{Dep}^*(\{T_1,T_2\})$，可避免每次手写大并集，也便于后文闭包表一行写多个目标。

\begin{definition}[有限目标集]
称非空有限集 $A\subseteq V$ 为一次讨论中的\textbf{目标集}。
其元素仍是顶点（能力/任务结点）；$A$ 只表示「当前要一起完成的那些目标」。
单点情形是特例：$A=\{T\}$。
\end{definition}

\begin{definition}[目标集的依赖闭包]
\label{def:dep-star-set}
\textbf{工程术语}：目标集 $A$ 的\textbf{依赖闭包}——完成 $A$ 中全部目标所需先决的并集。\\
\textbf{数学记号}：对 $A\subseteq V$，定义
\[
\mathrm{Dep}^*_G(A)
\;=\;
\bigcup_{T\in A}\mathrm{Dep}^*_G(T).
\]
并约定 $\mathrm{Dep}^*_G(\emptyset)=\emptyset$。
不致混淆时略去下标 $G$，写作 $\mathrm{Dep}^*(A)$。
\end{definition}

\begin{proposition}[目标集闭包的等价说法]
对任意 $A\subseteq V$ 与 $u\in V$，下列等价：
\begin{enumerate}
  \item $u\in\mathrm{Dep}^*(A)$；
  \item 存在某个 $T\in A$，使 $u\in\mathrm{Dep}^*(T)$（即 $u\rightsquigarrow T$ 或 $u=T$）；
  \item 存在 $T\in A$，使 $(u,T)\in E^{*}$。
\end{enumerate}
因而 $\mathrm{Dep}^*(A)$ 是「能通向 $A$ 中至少一个目标的全部祖先（含这些目标自身）」。
\end{proposition}

\begin{proposition}[$\mathrm{Dep}^*$ 作为幂集上的闭包算子]
定义 $\mathrm{Cl}:2^{V}\to 2^{V}$ 为 $\mathrm{Cl}(A)=\mathrm{Dep}^*(A)$
（此处 $2^{V}$ 为 $V$ 的幂集，见 §3.2）。则 $\mathrm{Cl}$ 满足：
\begin{enumerate}
  \item \textbf{扩张}：$A\subseteq\mathrm{Cl}(A)$；
  \item \textbf{单调}：$A\subseteq B\Rightarrow\mathrm{Cl}(A)\subseteq\mathrm{Cl}(B)$；
  \item \textbf{幂等}：$\mathrm{Cl}(\mathrm{Cl}(A))=\mathrm{Cl}(A)$。
\end{enumerate}
因此 $\mathrm{Cl}$ 是前文意义下的\textbf{闭包算子}。
进一步：$A$ 对该算子为闭集（即 $\mathrm{Cl}(A)=A$）当且仅当
$A$ 对「取直接前驱」封闭——若 $v\in A$ 则 $\mathrm{Pred}(v)\subseteq A$。
\end{proposition}
\begin{proof}[证明梗概]
（扩张）每个 $T\in A$ 满足 $T\in\mathrm{Dep}^*(T)$，故 $A\subseteq\mathrm{Dep}^*(A)$。\\
（单调）并集对包含关系显然单调。\\
（幂等）若 $u\in\mathrm{Dep}^*(\mathrm{Dep}^*(A))$，则 $u$ 能通向 $\mathrm{Dep}^*(A)$ 中某点 $v$，
而 $v$ 又能通向 $A$ 中某点，故 $u$ 能通向 $A$ 中某点，即 $u\in\mathrm{Dep}^*(A)$。\\
闭集刻画：对取前驱封闭 $\Leftrightarrow$ 含某点则含其直接前驱，归纳得含全部祖先。
\end{proof}

\begin{property}[并与交的粗界]
对任意 $A,B\subseteq V$，
\[
\mathrm{Dep}^*(A\cup B)=\mathrm{Dep}^*(A)\cup\mathrm{Dep}^*(B),
\qquad
\mathrm{Dep}^*(A\cap B)\;\subseteq\;\mathrm{Dep}^*(A)\cap\mathrm{Dep}^*(B).
\]
右式一般\textbf{不能}改成等号（「交的闭包」可以严格小于「闭包的交」）。
\end{property}

\paragraph{证书、已证书项与缺项}
闭包回答「理论上需要谁」；工程上还要问「其中哪些已经允许引用、还缺哪些」。
为此先钉死本教材中的\textbf{证书}一词（此前第~2~章资产清单、愿景段已口语出现，此处才给形式含义）。

\begin{definition}[证书]
方法论中的\textbf{证书}不是公钥基础设施里的数字证书，而是对某个顶点 $v\in V$（能力/任务结点）的\textbf{可引用判决}：
在约定验收准则下已通过验证，因而允许被后续任务当作先决引用。
\begin{itemize}
  \item \textbf{主语}是顶点 $v$，不是 Agent、也不是操作者本人；
  \item \textbf{工程载体}可以是探针 PASS 记录、stable 交付与 KAT、技术总结中的闭合条件等
        （§2 资产清单「证书」列即此类证据形态）；
  \item \textbf{数学抽象}先只关心「$v$ 当前是否被承认为已获证」，细节状态机见迁移系统一节与第~\ref{sec:math}~章。
\end{itemize}
\end{definition}

\begin{definition}[已证书集与已证书项]
\label{def:gamma}
\textbf{工程术语}：\textbf{已获证能力集}（亦称已证书集）——当前允许被后续任务引用的能力集合。\\
\textbf{数学记号}：固定讨论时刻，令 $\Gamma\subseteq V$ 表示该集合。
对任意 $v\in V$：
\begin{itemize}
  \item 若 $v\in\Gamma$，称 $v$ \textbf{已获证}，并称 $v$ 为相对 $\Gamma$ 的一个\textbf{已证书项}；
  \item 若 $v\notin\Gamma$，称 $v$ \textbf{未获证}。
\end{itemize}
口语「已经拿到证书 / 已获得证书」即指 $v\in\Gamma$。
$\Gamma$ 随预研过程可变：新顶点验收通过后可写入 $\Gamma$；既有判决因上游变更不再被承认时可移出 $\Gamma$。
本小节先把 $\Gamma$ 当作给定的集合参数；改写 $\Gamma$ 的转移名称在缺项集定义之后预习，完整转移见后文。
此后正文若写 $\Gamma$，一律读作「当前已获证能力集」。
\end{definition}

\begin{definition}[缺项集]
\label{def:missing}
\textbf{工程术语}：相对已获证清单的\textbf{缺项}——依赖闭包里还不允许引用的那些先决。\\
\textbf{数学记号}：对目标集 $A\subseteq V$ 与已获证能力集 $\Gamma\subseteq V$，定义\textbf{缺项集}
\[
\mathrm{Missing}_\Gamma(A)
\;=\;
\mathrm{Dep}^*(A)\setminus\Gamma
\;=\;
\{\,u\in\mathrm{Dep}^*(A)\mid u\notin\Gamma\,\}.
\]
当 $A=\{T\}$ 时简记为 $\mathrm{Missing}_\Gamma(T)$。
直观：$u$ 落在「完成 $A$ 的依赖闭包」里，但当前还\textbf{未获证}，故不能直接引用。
此后正文若写 $\mathrm{Missing}_\Gamma(A)$，一律读作「相对 $\Gamma$ 的缺项」。
\end{definition}

\begin{remark}[三类转移名称的预习]
完整转移关系在「迁移系统」一节定义。此处先约定三个\textbf{工程动作}的名称，并预告后文数学记号：
\begin{center}
\begin{tabular}{@{}L{3.2cm}L{2.6cm}L{7.6cm}@{}}
  \toprule
  工程动作 & 后文记号 & 本小节所需的含义 \\
  \midrule
  写入证书 & $\mathsf{Certify}$ &
  对未获证顶点 $v$：验收通过后执行 $\Gamma\leftarrow\Gamma\cup\{v\}$ \\
  探针取证 & $\mathsf{Probe}$ &
  对缺项启动探针/预研，收集可供写入证书使用的证据（本身不自动改 $\Gamma$） \\
  脏标记（作废） & $\mathsf{Dirty}$ &
  撤销部分既有证书：使某些 $v$ 不再属于 $\Gamma$（证书库非单调，详见后文） \\
  \bottomrule
\end{tabular}
\end{center}
\end{remark}

\begin{definition}[闭包已满]
若 $\mathrm{Missing}_\Gamma(A)=\emptyset$，称目标集 $A$ 相对 $\Gamma$ \textbf{闭包已满}
（亦称「依赖已齐备」）。
此时 $\mathrm{Dep}^*(A)\subseteq\Gamma$：完成 $A$ 所需的全部先决都已是已证书项。
\end{definition}

\begin{proposition}[缺项的基本性质]
对任意 $A\subseteq V$ 与 $\Gamma,\Gamma'\subseteq V$：
\begin{enumerate}
  \item $\mathrm{Missing}_\Gamma(A)\subseteq\mathrm{Dep}^*(A)$；
  \item $\mathrm{Missing}_\Gamma(A)=\emptyset \iff \mathrm{Dep}^*(A)\subseteq\Gamma$；
  \item 若 $\Gamma\subseteq\Gamma'$，则 $\mathrm{Missing}_{\Gamma'}(A)\subseteq\mathrm{Missing}_\Gamma(A)$
        （已证书集只增时，缺项只减或不增）；
  \item $\mathrm{Dep}^*(A)$ 可划分为
        $\bigl(\mathrm{Dep}^*(A)\cap\Gamma\bigr)\;\dot{\cup}\;\mathrm{Missing}_\Gamma(A)$
        （已证书部分与缺项部分不相交，并起来恰为闭包）。
\end{enumerate}
\end{proposition}

\begin{definition}[闭包表（工作对象）]
称一次任务启动时填写、供核对的检查表为\textbf{闭包表}。
数学上它至少应能填写：目标集 $A$、当前已证书集 $\Gamma$、算出的 $\mathrm{Dep}^*(A)$，以及缺项集 $\mathrm{Missing}_\Gamma(A)$
（后文还可附加禁字、接缝声明等）。
「先交闭包表再写码」指：实现之前必须先交出可核对的上述四元组（及约定扩展栏）。
\end{definition}

\begin{definition}[门禁（工作含义）]
\textbf{门禁}指预研工作流里「允许或拒绝某步动作」的检查规则
（例如：缺项非空则禁止直接写顶层实现；引用未获证依赖则拒绝）。
其数学内核后文用语言成员判定与配置转移表述；本小节只需把它当作「对着闭包表做的硬检查」。
\end{definition}

\begin{remark}[闭包表与门禁如何联动]
若 $\mathrm{Missing}_\Gamma(A)\neq\emptyset$，门禁应阻止「直接写顶层实现」，
并要求先对缺项做探针取证（$\mathsf{Probe}$），再在验收通过后写入证书（$\mathsf{Certify}$），直至相对 $\Gamma$ 闭包已满（或明确缩小目标）。
\end{remark}

\begin{definition}[能力菜单与绿项]
\textbf{能力菜单}（简称\textbf{菜单}）指仓库中列出的可命名能力清单，典型来源是各活跃 \texttt{INDEX.md}。
菜单上出现的项称为\textbf{可见能力}；若某可见能力当前属于 $\Gamma$，口语可称其为\textbf{绿项}
（「绿」只表示「此刻已获证」，不是形式状态机字母）。
菜单提供构造 $\Gamma$ 的\textbf{证据来源候选}，本身既不等于 $\Gamma$，也不蕴含 $\mathrm{Missing}_\Gamma(T)=\emptyset$。
\end{definition}

\paragraph{生成集与基（为「最小补洞」作准备）}
$\mathrm{Dep}^*(T)$ 可能很大；有时只需指出一堆「种子点」，其闭包已能覆盖整个 $\mathrm{Dep}^*(T)$。
下面先定义生成集，再说明「补洞」指什么。

\begin{definition}[生成集]
设 $T\in V$。若 $B\subseteq V$ 满足
\[
\mathrm{Dep}^*(B)=\mathrm{Dep}^*(T),
\]
则称 $B$ 为 $\mathrm{Dep}^*(T)$ 的一个\textbf{生成集}
（亦称「$B$ 生成 $\mathrm{Dep}^*(T)$」）。
特别地，取 $B=\{T\}$ 时，由定义 $\mathrm{Dep}^*(\{T\})=\mathrm{Dep}^*(T)$，故 $\{T\}$ 总是生成集。
\end{definition}

\begin{definition}[极小生成集与基]
若 $B$ 是 $\mathrm{Dep}^*(T)$ 的生成集，且 $B$ 的任何真子集都不再是生成集，
则称 $B$ 为\textbf{极小生成集}。
在有限图上极小生成集一定存在（从任意生成集不断删点直至不能再删）。
本教材把「基」暂当作极小生成集的同义语；更细的唯一性/规范基问题留待门禁章。
\end{definition}

\begin{definition}[补洞与最小补洞]
相对已证书集 $\Gamma$，把缺项逐步变成已证书项、从而使目标闭包已满的过程，称为\textbf{补洞}。
形式上一轮补洞至少包含：选取某些缺项 $u\in\mathrm{Missing}_\Gamma(T)$，经探针取证后写入证书，得到更大的已获证集合 $\Gamma'$。
若优先寻找尽可能小的缺项生成集（定义见下）作为补证对象，则称该选择问题为\textbf{最小补洞}（算法细节后置）。
\end{definition}

\begin{definition}[相对 $\Gamma$ 的缺项生成集]
工程上更关心：在已经知道 $\Gamma$ 的前提下，还需要新获证的是哪些点。
若 $B\subseteq\mathrm{Missing}_\Gamma(T)$ 满足
\[
\mathrm{Dep}^*\bigl((\mathrm{Dep}^*(T)\cap\Gamma)\cup B\bigr)=\mathrm{Dep}^*(T),
\]
则称 $B$ 为相对 $\Gamma$ 的一个\textbf{缺项生成集}：
把「已证书部分」$\mathrm{Dep}^*(T)\cap\Gamma$ 与「还打算补证的 $B$」合在一起，闭包就能盖住整个 $\mathrm{Dep}^*(T)$。
最小补洞即在缺项生成集中寻找尽可能小者。
\end{definition}

\begin{property}[菜单、$\Gamma$ 与闭包]
由能力菜单的定义：菜单提供构造 $\Gamma$ 的证据来源候选，但
\[
\text{菜单上有许多绿项}
\quad\not\Rightarrow\quad
\mathrm{Missing}_\Gamma(T)=\emptyset.
\]
必须先算 $\mathrm{Dep}^*(T)$，再与当前 $\Gamma$ 做差得到缺项。
菜单回答「可能有哪些能力」；闭包与缺项回答「为了 $T$ 必须有谁、还缺谁」。
\end{property}

\subsection{形式语言与合法拼装}
\label{sec:tool-lang}

本大节专门写第二件数学工具：\textbf{形式语言}。
目标一句话：把「怎样拼积木」写成可检查的\textbf{合法拼装计划}（字是否属于语言、是否避开禁止拼法）。
工程上它回答：菜单绿不等于拼法合法；单点 PASS 推不出接缝合法。
工程落点留到后文「工程体现」。

\subsubsection{字母表、字与语言}
\label{sec:words-lang}
\begin{definition}[字母表与字]
\label{def:alphabet-word}
\textbf{工程术语}：\textbf{可用步骤}组成的字母表；一次\textbf{拼装计划}是步骤的有限序列。\\
\textbf{数学记号}：非空有限集 $\Sigma$ 称为\textbf{字母表}；其元素称为\textbf{字母}。
$\Sigma$ 上的\textbf{字}是有限序列 $w=a_1a_2\cdots a_n$（$n\ge 0$，$a_i\in\Sigma$）；
$n=0$ 时称为\textbf{空字}，记 $\varepsilon$。
称 $n=|w|$ 为字长。全体字之集记 $\Sigma^*$（Kleene 星）。
又记 $\Sigma^+=\Sigma^*\setminus\{\varepsilon\}$。
在本方法论中：字母 $\approx$ 已证能力或接缝动作；字 $w$ $\approx$ 某次拼装计划。
\end{definition}

\begin{definition}[前缀、后缀与因子]
设 $w,x\in\Sigma^*$。
\begin{itemize}
  \item 若存在 $y$ 使 $w=xy$，称 $x$ 为 $w$ 的\textbf{前缀}；
  \item 若存在 $y$ 使 $w=yx$，称 $x$ 为 $w$ 的\textbf{后缀}；
  \item 若存在 $y,z$ 使 $w=yxz$，称 $x$ 为 $w$ 的\textbf{因子}（子字）。
\end{itemize}
\end{definition}

\begin{definition}[语言]
\label{def:language}
\textbf{工程术语}：\textbf{合法计划集合}——门禁承认的全部拼装计划。\\
\textbf{数学记号}：若 $L\subseteq\Sigma^*$，则称 $L$ 为 $\Sigma$ 上的一个\textbf{语言}。
称 $w$ 对 $L$ \textbf{合法}（或 $w$ 属于 $L$），若 $w\in L$。
此后若写 $w\in L$，一律读作「拼装计划 $w$ 合法」。
\end{definition}

\begin{definition}[语言的连接与星闭包]
对 $x,y\in\Sigma^*$，\textbf{连接} $xy$ 表示把 $y$ 接在 $x$ 后。
对语言 $L,M\subseteq\Sigma^*$，定义
\[
LM=\{xy\mid x\in L,\,y\in M\},
\quad
L^{0}=\{\varepsilon\},\;
L^{k+1}=L^{k}L,\;
L^{*}=\bigcup_{k\ge 0}L^{k}.
\]
\end{definition}

\begin{property}[连接对合法性不必封闭]
一般地，$x\in L$ 且 $y\in L$ \textbf{不能}推出 $xy\in L$。
（这是后文「组合不免费」的纯语言版本。）
\end{property}

\begin{proposition}[$\Sigma^*$ 的通用性]
任一语言都是 $\Sigma^*$ 的子集；讨论「合法计划」即指定某个 $L\subseteq\Sigma^*$。
门禁的数学内核是：给定 $w$，判定 $w\in L$ 是否成立（成员判定，见后文）。
\end{proposition}

\subsubsection{文法、产生式、派生与派生树}
\label{sec:grammar}

\begin{definition}[上下文无关文法（本教材用法）]
\textbf{上下文无关文法}是四元组 $\mathcal{G}=(N,\Sigma,P,S)$，其中：
\begin{itemize}
  \item $N$ 为有限\textbf{非终结符}集；
  \item $\Sigma$ 为有限\textbf{终结符}集，$N\cap\Sigma=\emptyset$；
  \item $S\in N$ 为\textbf{开始符号}；
  \item $P$ 为有限\textbf{产生式}集，每个产生式形如 $A\to\alpha$，其中 $A\in N$，$\alpha\in(N\cup\Sigma)^*$。
\end{itemize}
\end{definition}

\begin{definition}[一步派生与多步派生]
若 $\alpha=\alpha_1 A \alpha_2$，$A\to\beta\in P$，则称 $\alpha$ \textbf{一步派生}出 $\alpha_1\beta\alpha_2$，记 $\alpha\Rightarrow\alpha_1\beta\alpha_2$。
$\Rightarrow^*$ 表示 $\Rightarrow$ 的自反传递闭包（零步或多步派生）。
\end{definition}

\begin{definition}[文法生成的语言]
\[
L(\mathcal{G}) \;=\; \{\,w\in\Sigma^*\mid S\Rightarrow^* w\,\}.
\]
\end{definition}

\begin{definition}[派生树]
对一次从 $S$ 到 $w\in\Sigma^*$ 的派生，其\textbf{派生树}（语法树）是满足以下条件的有根有序树：
根标记为 $S$；内部结点标记为非终结符；叶子从左到右连接恰为 $w$；
若内部结点标记 $A$ 且其孩子标记依次拼成 $\alpha$，则 $A\to\alpha\in P$。
\end{definition}

\begin{theorem}[派生与派生树]
对上下文无关文法，$\mathcal{G}$ 能派生出 $w$ 当且仅当存在以 $w$ 为叶子连接的派生树。
\end{theorem}

\begin{remark}[方法论中的对应]
非终结符 $\approx$ 尚未落到已证书原子步骤的目标；
终结符 $\approx$ 已证书调用或不可再分的合法动作；
产生式 $\approx$ 「目标可展开为哪些子目标 / 接缝」的改写规则。
\end{remark}

\begin{example}[纯数学：匹配括号的文法片段]
令 $N=\{S\}$，$\Sigma=\{(,)\}$，产生式 $S\to(S)\mid SS\mid\varepsilon$。
则 $()\in L(\mathcal{G})$，$()()\in L(\mathcal{G})$，而 $()\notin$ 的补——更精确地说 $)(\notin L(\mathcal{G})$。
派生树记录括号如何嵌套，而不仅仅是字母的前后顺序。
\end{example}

\subsubsection{成员判定、禁字与组合不免费}
\label{sec:membership}

\begin{definition}[成员判定问题]
\textbf{工程术语}：检查一份拼装计划是否合法（门禁里的成员检查）。\\
\textbf{数学记号}：给定语言 $L\subseteq\Sigma^*$ 与字 $w\in\Sigma^*$，判断是否 $w\in L$，称为 $L$ 的\textbf{成员判定}。
\end{definition}

\begin{definition}[禁字集]
\label{def:forb}
\textbf{工程术语}：\textbf{禁止拼法}——不得出现在合法计划中的子串或关闭路线。\\
\textbf{数学记号}：设 $\mathrm{Forbidden}\subseteq\Sigma^*$。称语言 $L$ \textbf{避开} $\mathrm{Forbidden}$，若
\[
L \;\subseteq\; \{w\in\Sigma^*\mid \text{不存在 }f\in\mathrm{Forbidden}\text{ 作为 }w\text{ 的因子}\}.
\]
其中「因子」指存在 $x,y$ 使 $w=xfy$。
此后若写 $\mathrm{Forbidden}$，一律读作「禁止拼法集合」（工程来源含 \texttt{frozen/} 判决等）。
\end{definition}

\begin{definition}[组合不免费（方法论公理图式）]
称语言 $L$ 满足\textbf{组合不免费}，若存在 $x,y\in L$ 使得 $xy\notin L$。
在预研建模中我们\textbf{不假定} $L$ 对连接封闭；
若工程上需要把 $x$ 与 $y$ 顺序拼装，通常引入新的非终结符（接缝）与产生式，并要求该接缝获证。
\end{definition}

\begin{proposition}[菜单不能代替成员判定]
设 $\Sigma_0\subseteq\Sigma$ 为「菜单上可见的字母」。
仅给出 $\Sigma_0$ 不能唯一确定 $L$。
尤其，$L$ 还依赖产生式集合与禁字集 $\mathrm{Forbidden}$。
\end{proposition}

\begin{example}[纯数学]
取 $L=\{a,b\}\subseteq\{a,b\}^*$。则 $a,b\in L$ 但 $ab\notin L$，故组合不免费。
若希望允许 $ab$，必须把 $ab$ 显式加入 $L$，或增加产生式（例如 $S\to ab$）。
\end{example}

\begin{example}[工程]
PKE.KeyGen 计划与「某段哈希拼接」各自可能合法，
但「在新的 2-launch 边界下拼接二者」不必自动合法——这正是接缝节点
（如 Alg.16 尾缝、\texttt{KemKgTailFused}）存在的理由。
\texttt{frozen/} 文书对应 $\mathrm{Forbidden}$ 的工程来源之一。
\end{example}

\begin{remark}[门禁雏形]
Agent 提交「闭包表 + 展开计划 $w$」时，门禁检查的是：
$\mathrm{Missing}_\Gamma(T)=\emptyset$（全依赖已覆盖）且存在派生表明 $w\in L(\mathcal{G})$，
并且 $w$ 避开 $\mathrm{Forbidden}$。这是「先交闭包表，再写码」的数学表述。
\end{remark}


\subsection{作业过程自动机}
\label{sec:tool-auto}
\label{sec:transition}

本大节专门写第三件数学工具：\textbf{自动机}；在本方法论中的专名是\textbf{作业过程自动机}（亦称门禁自动机）。
目标一句话：描述一次作业如何按合法转移走到接受，以及证书何时因脏标记作废。
它接管「进度」：状态怎么变、何时接受/拒绝。
工程落点留到后文「工程体现」。

\subsubsection{迁移系统、配置与接受}
\begin{definition}[迁移系统]
\textbf{迁移系统}是三元组 $\mathcal{T}=(Q,\to,Q_0)$，其中 $Q$ 为配置集，
$\to\subseteq Q\times Q$ 为转移关系，$Q_0\subseteq Q$ 为初始配置集。
若 $(q,q')\in{\to}$，记 $q\to q'$。
它是定义自动机时常用的底料；下一款定义把它特化成作业过程自动机。
\end{definition}

\begin{definition}[作业过程自动机]
\label{def:job-process-automaton}
\textbf{数学工具名}：\textbf{自动机}。\\
\textbf{本方法论中的专名}：\textbf{作业过程自动机}（门禁自动机）。\\
固定能力库顶点集与约束库后，作业过程自动机是一个迁移系统，其
\begin{itemize}
  \item \textbf{状态}取为预研配置 $q=(\Gamma,F,S)$（定义见下）；
  \item \textbf{转移}取为展开 / 探针取证 / 写入证书 / 声明接缝 / 脏标记 / 冻结路线等合法动作；
  \item \textbf{初始状态}由开任务时的已获证清单与前沿给出；
  \item \textbf{接受}见后文「接受配置」。
\end{itemize}
此后若只说「自动机」，在本章默认指作业过程自动机。
\end{definition}

\begin{definition}[预研配置（自动机的状态）]
\label{def:config}
\textbf{工程术语}：一次作业的\textbf{预研配置}——记下已获证能力、前沿还欠什么、以及约束。\\
\textbf{数学记号}：预研配置是三元组 $q=(\Gamma,F,S)$，其中
\begin{itemize}
  \item $\Gamma\subseteq V_{\mathrm{lib}}$ 为已获证能力集；
  \item $F$ 为前沿目标的有限多重集（待展开或待获证的目标）；
  \item $S$ 为约束库（含 I/O 契约、接缝声明、禁止拼法等）。
\end{itemize}
\end{definition}

\begin{definition}[基本转移（名称可修订）]
在约束 $S$ 允许的前提下，定义以下几类转移（均为 $\to$ 的子集）。
表中先给\textbf{工程动作名}，再给后文沿用的数学记号：
\begin{center}
\begin{tabular}{@{}L{3.0cm}L{2.6cm}L{8.0cm}@{}}
  \toprule
  工程动作 & 记号 & 作用 \\
  \midrule
  展开 & $\mathsf{Expand}$ & 按产生式展开 $F$ 中某目标，更新缺项 \\
  探针取证 & $\mathsf{Probe}$ & 对缺项启动探针/预研以寻求证据 \\
  写入证书 & $\mathsf{Certify}$ & 验收通过后将结点写入 $\Gamma$ \\
  声明接缝 & $\mathsf{Compose}$ & 声明并认证接缝（落实组合不免费） \\
  脏标记 & $\mathsf{Dirty}$ & 使部分证书失效（见下一节） \\
  冻结路线 & $\mathsf{Freeze}$ & 将某路线写入禁止拼法 / 否定约束 \\
  \bottomrule
\end{tabular}
\end{center}
\end{definition}

\begin{definition}[接受与拒绝]
固定目标 $T$ 与生产 I/O 契约 $\mathcal{C}$。
\begin{itemize}
  \item 配置 $q=(\Gamma,F,S)$ 称为\textbf{接受配置}，若 $T\in\Gamma$、$F$ 为空（或仅含已放电目标），且 $\mathcal{C}$ 满足；
  \item 若转移过程试图使用 $\mathrm{Forbidden}$ 中的因子、或引用 $\notin\Gamma$ 的依赖边且未先 $\mathsf{Probe}/\mathsf{Certify}$，
        则进入\textbf{拒绝}（具体可建模为沉入拒绝阱状态）。
\end{itemize}
\end{definition}

\begin{definition}[合法性与幻觉（工作定义）]
\begin{enumerate}
  \item 称一次作业过程\textbf{合法}，若它对应作业过程自动机中从某初始配置到接受配置的有限转移序列，
        且每一步都符合产生式与 $S$ 中约束。
  \item 称行为构成\textbf{幻觉}，若它执行了非法转移，或在图上使用了无证书边
        （等价地：计划字 $w\notin L$ 或未避开 $\mathrm{Forbidden}$）。
\end{enumerate}
语义 oracle（FIPS / liboqs / golden）判定「计算结果是否正确」；
本定义判定「砖是否允许那样砌」。
\end{definition}

\begin{example}[纯数学：作业过程自动机小品]
状态 $\{q_0,q_{\mathrm{ok}},q_{\mathrm{bad}}\}$，字母 $\{a,b\}$。
$q_0\xrightarrow{a}q_0$，$q_0\xrightarrow{b}q_{\mathrm{ok}}$，其余进 $q_{\mathrm{bad}}$。
则字 $aab$ 被接受，$ba$ 被拒绝。这与「先合法前缀、再结束符」的门禁同构。
\end{example}

\begin{example}[工程]
初始已获证清单含 stable PKE 等；前沿含 \texttt{kem.keygen}。
经\textbf{展开}得到尾缝缺项 $\to$ \textbf{声明接缝/探针取证} $\to$ \textbf{写入证书}后目标获证，到达接受。
若中途使用了\textbf{禁止拼法}中的因子（已关闭或明确禁止的路线），
则触发拒绝（\textbf{冻结路线}已写入禁止拼法集合）。
\end{example}

\subsubsection{证书的非单调更新（脏标记）}
\label{sec:dirty}

\begin{definition}[单调与非单调证书库]
称证书更新机制为\textbf{单调}的，若任意转移满足 $\Gamma\subseteq\Gamma'$（证书集只增不减）。
若允许某次转移后 $\Gamma'\subsetneq\Gamma$，则称为\textbf{非单调}的。
\end{definition}

\begin{definition}[脏标记]
\label{def:dirty}
\textbf{工程术语}：\textbf{脏标记}（证书作废）——因上游约定变更，下游既有证书不再被承认。\\
\textbf{数学记号}：对 $v\in\Gamma$，若因上游接口、布局或同步约定变更，使 $v$ 的既有证书不再被承认，
则称 $v$ 被标记为 $\mathsf{dirty}$，并在转移 $\mathsf{Dirty}$ 下将 $v$ 移出 $\Gamma$
（或移入「待重证」区）。具体存储格式后文工程化。
此后若写 $\mathsf{Dirty}$，一律读作「脏标记 / 证书作废」动作。
\end{definition}

\begin{proposition}[工程引理库非单调]
本方法论采用的证书库是非单调的：存在合法的 $\mathsf{Dirty}$ 转移使 $\Gamma$ 严格缩小。
\end{proposition}

\begin{corollary}[过期证书不可当作永真公理]
门禁在引用 $v\in\Gamma$ 时，须能够回答「自获证以来上游是否触发 $\mathsf{Dirty}$」。
\end{corollary}

\begin{example}[纯数学：撤回引理]
证明系统中若发现引理 $L_1$ 的证明有漏洞而撤回，则所有依赖 $L_1$ 的定理证书失效。
这与「断言永真后只增不减」的理想图景不同。
\end{example}

\begin{example}[工程]
P1 某能力的 I/O、布局或同步约定变更后，曾基于旧约定的 P2/P3 证书应标 $\mathsf{dirty}$，
不得因「上次 PASS」而默认继续合法。
\end{example}

\subsubsection{依赖图与依赖闭包 $\to$ 闭包表、资产清单与 \texttt{frozen/}}
\label{sec:tool-dep-eng}

依赖图与依赖闭包在工程里主要落成三样东西（第~\ref{sec:hook}~章已见过雏形）：
\begin{enumerate}
  \item \textbf{资产清单}：当时认为「已获证」的能力列表（$\Gamma$ 的手工版）；
  \item \textbf{闭包表}：目标、已获证、依赖闭包、缺项四栏核对——动手前先交这张表；
  \item \textbf{\texttt{frozen/}}：明确不再允许当作依赖去走的边（禁止再引用的路线）。
\end{enumerate}
没有依赖图与闭包，就会把「INDEX 上有绿项」误当成「依赖已齐、可以开写」。

\subsubsection{形式语言 $\to$ 拼装计划、门禁与禁止拼法}
\label{sec:tool-lang-eng}

形式语言在工程里主要落成：
\begin{enumerate}
  \item \textbf{拼装计划}：一次任务打算按什么顺序、用哪些已证能力与接缝去拼；
  \item \textbf{门禁的成员检查}：这份计划是否属于合法计划集合，是否避开禁止拼法；
  \item \textbf{禁止拼法}：\texttt{frozen/} 等关闭路线的语言侧对应物。
\end{enumerate}
没有形式语言，就会把「菜单上有这些绿项」误当成「任意拼接都合法」。


\subsubsection{作业过程自动机 $\to$ 作业怎么走完、证书何时作废}
\label{sec:tool-auto-eng}

作业过程自动机在工程里主要落成：
\begin{enumerate}
  \item \textbf{作业轨迹}：从开任务配置走到「目标获证、前沿清空」的接受配置；
  \item \textbf{过程动作}：展开缺项、探针取证、写入证书、声明接缝；
  \item \textbf{脏标记}：上游 I/O、布局或同步约定变更后，下游不得继续假绿。
\end{enumerate}
没有作业过程自动机，就只能事后说「这次碰巧 PASS」，无法描述过程是否合法、证书为何作废。

\cdots
\;\xrightarrow{\mathsf{Probe}/\mathsf{Compose}}\;
\cdots
\;\xrightarrow{\mathsf{Certify}}\;
(\Gamma_m,\emptyset,S_m),

\]
若中途引用了禁字集 $\mathrm{Forbidden}$ 中的因子（已关闭或明确禁止的路线），
应直接拒绝（$\mathsf{Freeze}$ / 沉入拒绝阱）。

\paragraph{流程八：上游一变——$\mathsf{Dirty}$}

则原先依赖该约定的下游（P2/P3）不能因为「上次 PASS」就继续留在 $\Gamma$ 里；
必须走 $\mathsf{Dirty}$（§3.11）。

\subsection{枢纽：依赖、展开与进度各由哪件工具管}
\label{sec:three-layers}

三件工具的数学与工程落点都写过了。收束前再钉死一句读章枢纽：
\textbf{依赖、展开与进度是三件不同的事}，并分别由三件工具接管——
\textbf{依赖}归依赖图与依赖闭包，
\textbf{展开}归形式语言，
\textbf{进度}归作业过程自动机。
下面用三个定义把对象名钉死，并对照它们各回答什么、不回答什么。

\begin{definition}[能力 DAG（库）]
\textbf{能力 DAG} 是 DAG $G_{\mathrm{lib}}=(V_{\mathrm{lib}},E_{\mathrm{lib}})$，
顶点为可命名、可获证的能力，边为依赖（语义依赖或已声明接缝依赖）。
它描述引理库的\textbf{静态}结构，不随单次任务进度改写边集
（结点证书状态可变，见配置层）。
\end{definition}

\begin{definition}[一次任务与派生对象]
固定目标 $T\in V_{\mathrm{lib}}$ 与文法 $\mathcal{G}$（见形式语言一节）。
\textbf{一次任务}指试图使 $T$ 获证的一次预研作业。
该作业中，从开始符号出发按产生式改写所得的符号串序列称为\textbf{派生}；
其树形记录称为\textbf{派生树}。派生树是 $G_{\mathrm{lib}}$ 上依赖信息的\textbf{一次使用痕迹}，不是整库拷贝。
\end{definition}

\begin{definition}[配置轨迹]
作业过程自动机上的状态序列 $q_0\to q_1\to\cdots\to q_m$，其中每个 $q_i$ 为配置
$(\Gamma_i,F_i,S_i)$（见作业过程自动机一节），称为\textbf{配置轨迹}。
它记录证书如何增减、前沿如何消解——即「进度」。
\end{definition}

\begin{proposition}[三件工具分工]
\begin{center}
\begin{tabular}{@{}L{2.8cm}L{2.4cm}L{4.2cm}L{4.0cm}@{}}
  \toprule
  对象 & 归属工具 & 回答 & 不回答 \\
  \midrule
  能力 DAG & 依赖图与闭包 & 库中谁依赖谁 & 某次任务如何逐步展开 \\
  派生树 & 形式语言 & 该次任务的展开句子 / 树形 & 全局共享边的全貌 \\
  配置轨迹 & 作业过程自动机 & 证书如何增减；接受/拒绝 & 输出是否符合 FIPS 字节 \\
  \bottomrule
\end{tabular}
\end{center}
\noindent
\textbf{依赖归依赖图；展开归形式语言；进度归作业过程自动机。}
\end{proposition}

\subsection{由顶点导出节点卡}
\label{sec:math-node}

第~3~章把证书主语定为顶点 $v\in V$，但未规定工程上如何记录 $v$。
下面的算法把「$v$ 可被引用」所需的检查信息，编码成一张有限字段卡。

下面把「顶点 $\mapsto$ 节点卡」写成可执行手续。
体例上：本算法\textbf{只}吃顶点集与约束，\textbf{不}吃边集——边的分类见算法~\ref{alg:classify-rel}，闭包沿边展开见算法~\ref{alg:depstar}；
调用方若持有完整 DAG，此处只传入其顶点部。

\begin{methodalgo}{编码节点卡 $\mathrm{EncodeNode}$}
\label{alg:encode-node}
\algoparam{能力顶点集 $V$；
分层映射 $\lambda:V\to\{\mathrm{P0},\mathrm{P1},\mathrm{P2},\mathrm{P3}\}$；
当前已获证集 $\Gamma\subseteq V$；约束库 $S$（含与各顶点相关的 $\mathrm{Forbidden}$ 片段）；
仓库锚点映射 $\rho:V\to\mathrm{Paths}$（活跃权威路径，禁止指向 \texttt{frozen/} 正向源码）。}
\algoin{顶点 $v$。}
\algoout{节点卡 $\mathrm{Card}(v)=(\texttt{id},\texttt{layer},\texttt{interface},\texttt{cert},\texttt{forbid},\texttt{repo})$；
若前置检查失败则拒绝输出。}
\begin{algosteps}
  \item \textbf{前置（用到 $V$）}：若 $v\notin V$，拒绝并报错「未知能力顶点」。
  \item 令 $\texttt{id}(v)$ 为 $v$ 的稳定名字（跨任务可引用；不得用临时目录名冒充）。
  \item 令 $\texttt{layer}(v)=\lambda(v)$（P0--P3 只描述能力角色，不要求与磁盘树同构）。
  \item 从 $S$ 中抽取 $v$ 对外可复用的 I/O、dtype、布局与同步约定，写入 $\texttt{interface}(v)$。
        约定：后续边与引用只允许挂 $\texttt{interface}$，不允许默许「拷源码」。
  \item 若 $v\in\Gamma$，令 $\texttt{cert}(v)$ 记录获证证据指针（路径、CPU+SIM/KAT、版本锚点）；
        若 $v\notin\Gamma$，令 $\texttt{cert}(v)=\bot$。
  \item 令 $\texttt{forbid}(v)$ 为 $S$ 中与 $v$ 相关的否定约束（可空）。
  \item 令 $\texttt{repo}(v)=\rho(v)$；若 $\rho(v)$ 落在 \texttt{frozen/} 正向实现路径，则拒绝输出并报错
        （否定说明可引用 frozen 判决，正向 \texttt{repo} 不可）。
  \item 返回六元组 $\mathrm{Card}(v)$。
\end{algosteps}
\end{methodalgo}

（名字可本地化，语义不要丢）：

\begin{proposition}[节点卡是门禁检查的充分记录]
\label{prop:card-sufficient}
固定 $G,\Gamma,S$。对任意 $v\in V$，由算法~\ref{alg:encode-node} 得到的 $\mathrm{Card}(v)$ 足以判定：
\begin{enumerate}
  \item $v$ 当前是否已获证（看 $\texttt{cert}(v)\neq\bot$，等价于 $v\in\Gamma$）；
  \item 引用 $v$ 时对外应遵守的接口（$\texttt{interface}$）；
  \item 是否触碰与 $v$ 相关的禁止项（$\texttt{forbid}$）。
\end{enumerate}
换言之：门禁若只关心「能否引用 $v$」，不必再翻开 $v$ 的实现源码。
\end{proposition}
\begin{proof}[证明梗概]
第~3~章定义「已获证」为 $v\in\Gamma$，算法~\ref{alg:encode-node} 中写入 $\texttt{cert}$ 的步骤正是该隶属关系的工程编码；
$\texttt{interface}$ 与 $\texttt{forbid}$ 直接截取自约束库 $S$，而合法引用在定义上只依赖证书资格与 $S$ 中接口/禁止约束。
\end{proof}

\begin{corollary}[禁止同任务发明未获证底层]
若目标 $T$ 满足 $\lambda(T)=\mathrm{P3}$，且存在 $u\in\mathrm{Missing}_\Gamma(T)$ 使 $\lambda(u)\in\{\mathrm{P0},\mathrm{P1}\}$，
则任何声称「在做 $T$ 的同一任务里顺便实现 $u$ 并立刻引用」的计划，都与
「先 $\mathsf{Probe}/\mathsf{Certify}$ 再引用」的合法转移相悖（见第~3~章基本转移）。
\end{corollary}

\subsection{由边关系导出三类边}
\label{sec:math-edges}

第~3~章的依赖边与接缝、禁止拼法在工程上常混称「关系」。
下面算法把一次「关系声明」分类，便于写入 $E$ 或 $\mathrm{Forbidden}$。

\begin{methodalgo}{边分类 $\mathrm{ClassifyRel}$}
\label{alg:classify-rel}
\algoparam{能力 DAG $G=(V,E)$（本算法可读 $V$、写 $E$，从而更新 $G$）；
禁止拼法族 $\mathrm{Forbidden}$；接缝声明集 $\mathcal{C}_{\mathrm{seam}}\subseteq V\times V$
（由约束库维护：哪些「$A$ 与 $B$ 已各自获证仍须单独认证」）。}
\algoin{关系请求 $r$，形态为以下之一：
（i）有序对 $(u,v)$ 表示「$v$ 语义依赖 $u$」；
（ii）接缝请求 $\mathrm{compose}(A,B)$；
（iii）禁止请求 $\mathrm{forbid}(x)$（关闭路线、禁模板等）。}
\algoout{标签 $\tau(r)\in\{\mathsf{semantic},\mathsf{compose},\mathsf{forbidden}\}$，以及应写入的载体
（$G$ 的一条边、接缝节点候选、或 $\mathrm{Forbidden}$ 的一条）；失败则拒绝。
成功后调用方持有的图为更新后的 $G$。}
\begin{algosteps}
  \item 若 $r=\mathrm{forbid}(x)$，令 $\tau=\mathsf{forbidden}$，把 $x$ 并入 $\mathrm{Forbidden}$（或写入对应 \texttt{forbid} 字段），返回。
  \item 若 $r=\mathrm{compose}(A,B)$，或 $(A,B)\in\mathcal{C}_{\mathrm{seam}}$：
        若 $A\notin V$ 或 $B\notin V$，拒绝；
        否则令 $\tau=\mathsf{compose}$：新建或引用接缝顶点 $s_{A\!\circ\!B}$；
        若 $s_{A\!\circ\!B}\notin V$，则更新图 $G$：令 $V\leftarrow V\cup\{s_{A\!\circ\!B}\}$；
        要求日后单独 $\mathsf{Probe}/\mathsf{Certify}$；
        \textbf{不}把「$A$ 与 $B$ 均已获证」推成 $s_{A\!\circ\!B}$ 已获证。
  \item 否则若 $r=(u,v)$：若 $u\notin V$ 或 $v\notin V$，拒绝；
        若任务语义为「$v$ 的正确性依赖 $u$ 的 interface」，令 $\tau=\mathsf{semantic}$，
        并更新图 $G$：令 $E\leftarrow E\cup\{(u,v)\}$（若尚无该边）。
  \item 返回 $\tau(r)$ 与载体（及更新后的 $G$，若本步改写了 $V$ 或 $E$）。
\end{algosteps}
\end{methodalgo}

\paragraph{输出长什么样：三类边含义表}
\begin{center}
\begin{tabular}{@{}L{2.8cm}L{5.2cm}L{5.6cm}@{}}
  \toprule
  标签 $\tau$ & 含义 & 写入何处 / 后果 \\
  \midrule
  $\mathsf{semantic}$ &
  $v$ 要对，离不开 $u$ 的 interface &
  进入 $E$；参与 $\mathrm{Dep}^*$ \\
  $\mathsf{compose}$ &
  $A,B$ 各有证，$A\!\circ\!B$ 仍须单独认证 &
  接缝顶点 $s$；\textbf{不}因 $A,B\in\Gamma$ 自动获证 \\
  $\mathsf{forbidden}$ &
  明确禁止的路线/模板 &
  进入 $\mathrm{Forbidden}$ 或节点 \texttt{forbid} \\
  \bottomrule
\end{tabular}
\end{center}

\begin{proposition}[组合不免费的算法表述]
\label{prop:compose-not-free}
设 $A,B\in\Gamma$ 且 $\mathrm{compose}(A,B)$ 被算法~\ref{alg:classify-rel} 标为 $\mathsf{compose}$，
接缝顶点为 $s$。则
\[
A\in\Gamma \;\land\; B\in\Gamma \quad\not\Rightarrow\quad s\in\Gamma.
\]
要使 $s\in\Gamma$，必须另经合法的 $\mathsf{Probe}/\mathsf{Certify}$（或等价验收）写入证书。
\end{proposition}
\begin{proof}
由算法步骤~2：$A,B$ 获证只保证接缝请求可被提出，不修改 $\Gamma$ 对 $s$ 的隶属；
第~3~章 $\mathsf{Certify}$ 才是唯一把顶点写入 $\Gamma$ 的基本转移（在约束允许时）。
\end{proof}

\begin{remark}[边 $\neq$ \texttt{\#include}]
$\mathsf{semantic}/\mathsf{compose}$ 边描述的是能力—证书关系，不是编译依赖。
自包含原则写进 $\texttt{interface}$：对外挂接口；共享库例外必须进入 $S$，不能默许 Agent 自由翻抄。
\end{remark}

\subsection{由闭包定义导出缺项算法}
\label{sec:math-missing}

第~3~章已有 $\mathrm{Dep}^*$ 的迭代收敛定理与 $\mathrm{Missing}_\Gamma$ 定义。
这里把它们写成可调用子程序，供第~5~章闭包表算法使用。

\begin{methodalgo}{依赖闭包 $\mathrm{DepStar}$}
\label{alg:depstar}
\algoparam{有限依赖图 $G=(V,E)$（第~3~章：$V$ 为顶点集，$E$ 为依赖边集）。}
\algoin{目标 $T$（或目标集 $A$，逐点并）。}
\algoout{$D=\mathrm{Dep}^*_G(T)$；若 $T\notin V$ 则拒绝。}
\begin{algosteps}
  \item 在输入图 $G=(V,E)$ 上检查：若 $T\notin V$，拒绝。
  \item 令 $D_0=\{T\}$。对任意 $v\in V$，记前驱
        $\mathrm{Pred}_G(v)=\{u\in V\mid (u,v)\in E\}$（显式读取边集 $E$）。
  \item 对 $k=0,1,2,\ldots$，令 $D_{k+1}=D_k\cup\bigcup_{v\in D_k}\mathrm{Pred}_G(v)$，直至 $D_{k+1}=D_k$。
  \item 返回 $D_k$（第~3~章已证：稳定值等于 $\mathrm{Dep}^*_G(T)$，且步数 $\le|V|$）。
\end{algosteps}
\end{methodalgo}

\begin{methodalgo}{缺项 $\mathrm{MissingOf}$}
\label{alg:missing}
\algoparam{有限依赖图 $G$；当前已获证集 $\Gamma$。}
\algoin{目标 $T$。}
\algoout{$M=\mathrm{Missing}_\Gamma(T)$。}
\begin{algosteps}
  \item 将同一图 $G$ 作为参数调用算法~\ref{alg:depstar}，得 $D=\mathrm{Dep}^*_G(T)$
        （若 $T$ 不是 $G$ 的顶点，则随 $\mathrm{DepStar}$ 拒绝）。
  \item 返回 $M=D\setminus\Gamma$。
\end{algosteps}
\end{methodalgo}

\begin{proposition}[缺项判定的直接推论]
\label{prop:missing-iff}
算法~\ref{alg:missing} 输出 $M=\emptyset$ 当且仅当 $\mathrm{Dep}^*(T)\subseteq\Gamma$
（即第~3~章「闭包已满」）。
\end{proposition}

\subsection{由非单调证书导出脏标记传播}
\label{sec:math-cert}

第~3~章指出 $\Gamma$ 可因 $\mathsf{Dirty}$ 收缩。工程上需要可计算的作废范围。

\begin{methodalgo}{脏标记传播 $\mathrm{DirtyPropagate}$}
\label{alg:dirty}
\algoparam{能力 DAG $G=(V,E)$；当前已获证集 $\Gamma\subseteq V$。}
\algoin{接口/约定发生变更的顶点集合 $U$。}
\algoout{新的已获证集 $\Gamma'$，以及被打脏的集合 $\Delta$；若 $U\not\subseteq V$ 则拒绝。}
\begin{algosteps}
  \item 在输入图 $G=(V,E)$ 上检查：若 $U\not\subseteq V$，拒绝。
  \item 令 $\Delta_0=U$。对任意 $u\in V$，记后继
        $\mathrm{Succ}_G(u)=\{w\in V\mid (u,w)\in E\}$（显式读取边集 $E$ 的出邻）。
  \item 迭代：令 $\Delta_{k+1}=\Delta_k\cup\bigcup_{u\in\Delta_k}\mathrm{Succ}_G(u)$，直至稳定，得 $\Delta$（变更锥：
        以 $U$ 为种子、沿出边在 $G$ 上可达的全部顶点）。
  \item 令 $\Gamma'=\Gamma\setminus\Delta$，返回 $(\Gamma',\Delta)$。
\end{algosteps}
\end{methodalgo}

\paragraph{输出长什么样：证书状态表}
工程交接时，对每个顶点除「是否在 $\Gamma$」外，再贴粗标签 $\sigma$（不改变 $\mathrm{Missing}$ 的集合定义）：

\begin{center}
\begin{tabular}{@{}L{2.6cm}L{11.2cm}@{}}
  \toprule
  状态 $\sigma$ & 工程含义 \\
  \midrule
  \texttt{unproven} &
  只有名字或愿望，尚无按约定跑通的证据（$v\notin\Gamma$）。 \\
  \texttt{probe} &
  探针级：平台/接缝行为已用 CPU+SIM（或任务声明级别）跑通；$v\in\Gamma$，弱证书。 \\
  \texttt{lemma} &
  可稳定引用；interface 写清，可进入依赖闭包的「已获证」栏。 \\
  \texttt{deliverable} &
  交付级（如 stable）：在 lemma 之上还有交付目录、登记表与交接文书。 \\
  \texttt{dirty} &
  \textbf{作废标记}：落入算法~\ref{alg:dirty} 的 $\Delta$ 后，$v\notin\Gamma'$；旧对拍不得再充当有效 \texttt{cert}。 \\
  \bottomrule
\end{tabular}
\end{center}

阶梯关系可记为：
\[
\mathsf{unproven}
\;\longrightarrow\;
\mathsf{probe}
\;\longrightarrow\;
\mathsf{lemma}
\;\longrightarrow\;
\mathsf{deliverable},
\qquad\text{以及回退}\qquad
\mathsf{dirty}.
\]

\begin{proposition}[证书阶梯与 $\Gamma$ 的关系]
\label{prop:cert-ladder}
为工程交接，对 $v\in\Gamma$ 可再贴标签
$\sigma(v)\in\{\mathsf{probe},\mathsf{lemma},\mathsf{deliverable}\}$（未获证则 $\sigma(v)=\mathsf{unproven}$）。
则：
\begin{enumerate}
  \item 门禁「可引用」的初级判定只依赖 $v\in\Gamma$，与 $\sigma(v)$ 的粗细无关；
  \item $\sigma$ 只影响验收级别与交付文书，不改变 $\mathrm{Missing}_\Gamma$ 的集合定义；
  \item 一经算法~\ref{alg:dirty}，$v\in\Delta\Rightarrow v\notin\Gamma'$，此时对拍旧日志不得再充当有效 $\texttt{cert}$。
\end{enumerate}
\end{proposition}

\begin{remark}[对拍 $\neq$ 证书全部]
对拍通过是 $\mathsf{Certify}$ 的必要证据之一，不是充分条件：
仍须引用合法、接缝已认证、未命中 $\mathrm{Forbidden}$、未落入 $\Delta$。
\end{remark}

\section{门禁与工作流：Agent 被允许做什么}
\label{sec:gates}

第~\ref{sec:math}~章给出了从数学对象到节点/边/证书的构造算法。
本章继续推导：把第~3~章的作业过程自动机转移，写成 Agent 可执行的门禁算法，
并推出「何时允许写码」的判定式。

\begin{quote}
\noindent
\textbf{门禁的数学含义}：只允许作业过程自动机上的合法转移；\\
\textbf{门禁的操作面}：先交闭包表，再写码；缺项先补洞；禁止项不得当模板。
\end{quote}

\subsection{闭包表算法}
\label{sec:gates-closure-algo}

第~3~章定义闭包表至少含 $A,\Gamma,\mathrm{Dep}^*(A),\mathrm{Missing}_\Gamma(A)$。
下面把它变成算法输出，并加上接缝与否定栏（仍由第~3~章对象生成）。

\begin{methodalgo}{填写闭包表 $\mathrm{BuildClosureTable}$}
\label{alg:closure-table}
\algoparam{能力 DAG $G=(V,E)$；当前已获证集 $\Gamma\subseteq V$；约束库 $S$（含 $\mathrm{Forbidden}$、接缝声明 $\mathcal{C}_{\mathrm{seam}}$）；
分层 $\lambda:V\to\{\mathrm{P0},\mathrm{P1},\mathrm{P2},\mathrm{P3}\}$；
状态标签 $\sigma$（命题~\ref{prop:cert-ladder}；用于识别已打脏但仍可能误留在文书里的点）。
子程序：算法~\ref{alg:depstar}、\ref{alg:missing}、\ref{alg:classify-rel}、\ref{alg:encode-node}。}
\algoin{目标 $T$；I/O 契约 $\mathcal{C}$；声明验收级别 $\ell\in\{\mathsf{probe},\mathsf{lemma},\mathsf{deliverable}\}$。}
\algoout{闭包表
$\mathrm{CT}=(T,\mathcal{C},\ell,\Gamma,D,M,\mathrm{Seams},\mathrm{ForbiddenHit},\mathrm{Warn})$，
其中 $D=\mathrm{Dep}^*_G(T)$，$M=\mathrm{Missing}_\Gamma(T)$；$\mathrm{Warn}$ 为警告袋（可空）。}
\begin{algosteps}
  \item \textbf{目标声明}：在图 $G=(V,E)$ 上，若 $T\notin V$ 或 $(T,\mathcal{C},\ell)$ 任一项缺失，拒绝输出（任务未声明）。
        否则写入 $(T,\mathcal{C},\ell)$。
  \item 从约束库 $S$ 取出本任务可见的 $\mathrm{Forbidden}$ 与 $\mathcal{C}_{\mathrm{seam}}$（后续接缝栏与否定栏只读这两份摘录，
        但仍以 $S$ 为唯一来源——禁止另起一份未登记的禁止表）。
  \item 以参数 $G$ 调用 $\mathrm{DepStar}(T)$ 得 $D$（该子程序沿 $E$ 取前驱）；以参数 $G,\Gamma$ 调用 $\mathrm{MissingOf}(T)$ 得 $M$。
  \item 对每张需要引用的 $v\in D\cap\Gamma$：以 $G$ 的顶点集 $V$ 等参数调用 $\mathrm{EncodeNode}(v)$，
        核对 $\texttt{cert}\neq\bot$；若维护了 $\sigma$ 且 $\sigma(v)=\mathsf{dirty}$，则把 $v$ 移出「可引用已获证」视角并记入 $\mathrm{Warn}$。
  \item \textbf{接缝栏}：对所有与 $T$ 相关的 $\mathrm{compose}$ 请求，以参数 $G,\mathrm{Forbidden},\mathcal{C}_{\mathrm{seam}}$ 跑 $\mathrm{ClassifyRel}$，
        收集尚未获证的接缝顶点集 $\mathrm{Seams}$；把 $\mathrm{Seams}\setminus\Gamma$ 并入缺项视角
        （实现上可并入 $M$ 或单列，但门禁必须看见它们）。
  \item \textbf{分层警告（用到 $\lambda$）}：若存在 $u\in M$ 使 $\lambda(u)\in\{\mathrm{P0},\mathrm{P1}\}$，
        将「禁止在做 $T$ 的同一任务里顺便发明该底层」写入 $\mathrm{Warn}$（对照推论「禁止同任务发明未获证底层」）。
  \item \textbf{否定栏}：计算 $\mathrm{ForbiddenHit}=\{x\in\mathrm{Forbidden}\mid x\text{ 与本次计划相交}\}$；
        若计划显式引用 $\mathrm{ForbiddenHit}$ 中模板，标记为硬冲突。
  \item 返回 $\mathrm{CT}$。
\end{algosteps}
\end{methodalgo}

\paragraph{输出长什么样：闭包表栏位}
算法~\ref{alg:closure-table} 输出的 $\mathrm{CT}$ 在工程上至少填成下表各栏
（第~3~章四元组 $+$ 接缝/否定扩展）：

\begin{center}
\begin{tabular}{@{}L{2.8cm}L{11.0cm}@{}}
  \toprule
  栏 & 填什么 \\
  \midrule
  目标 $T$ &
  id、I/O 黑盒 $\mathcal{C}$、声明验收级别 $\ell\in\{\mathsf{probe},\mathsf{lemma},\mathsf{deliverable}\}$ \\
  已获证 &
  $D\cap\Gamma$ 中节点（附节点卡 \texttt{repo}/版本锚点）；须未脏 \\
  依赖闭包 $D$ &
  $\mathrm{Dep}^*(T)$：语义依赖 + 已知接缝项所覆盖的先决 \\
  缺项 $M$ &
  $\mathrm{Missing}_\Gamma(T)$；每项可附「拟补洞手段」 \\
  接缝 $\mathrm{Seams}$ &
  须单独认证的接缝顶点；未获证者门禁必须看见 \\
  否定 $\mathrm{ForbiddenHit}$ &
  本次计划与 $\mathrm{Forbidden}$ 的相交；非空则硬冲突 \\
  警告 $\mathrm{Warn}$ &
  可空；含脏证书误留、同任务发明 P0/P1 缺项等非硬冲突提示 \\
  \bottomrule
\end{tabular}
\end{center}

\begin{quote}
\noindent
\textbf{先交闭包表，再写码。}\\
customspec、STATUS、baseline-registry 是重要文书，但\textbf{替代不了} $\mathrm{CT}$：
前者多半描述「打算怎么实现 / 实现结果如何」，$\mathrm{CT}$ 回答「凭什么现在允许开始实现」。
\end{quote}

\begin{theorem}[写码许可的充分必要条件（v0）]
\label{thm:coding-permit}
固定 $G,\Gamma,S$ 与目标 $T$。在算法~\ref{alg:closure-table} 输出的 $\mathrm{CT}$ 上，定义谓词
\[
\mathrm{PermitCode}(\mathrm{CT})
\;:\iff\;
M=\emptyset
\;\land\;
\mathrm{Seams}\subseteq\Gamma
\;\land\;
\mathrm{ForbiddenHit}=\emptyset
\;\land\;
\mathcal{C}\text{ 已声明}.
\]
则：
\begin{enumerate}
  \item 若 $\mathrm{PermitCode}(\mathrm{CT})$ 为真，则相对 $\Gamma$ 目标闭包已满、接缝已获证、未踩禁止拼法，
        此时进入「按 $\ell$ 实现 $T$」与第~3~章「闭包已满后方可冲击顶层」一致；
  \item 若 $M\neq\emptyset$ 或 $\mathrm{Seams}\not\subseteq\Gamma$，则任何跳过 $\mathsf{Probe}/\mathsf{Certify}$、
        直接写 $T$ 顶层实现的动作，都不是合法转移（应被门禁拒绝）；
  \item 若 $\mathrm{ForbiddenHit}\neq\emptyset$，则计划字触碰 $\mathrm{Forbidden}$，属于第~3~章工作定义下的幻觉/拒绝类行为。
\end{enumerate}
\end{theorem}
\begin{proof}[证明梗概]
（1）$M=\emptyset\Leftrightarrow\mathrm{Dep}^*(T)\subseteq\Gamma$ 为第~3~章命题；接缝与 $\mathrm{Forbidden}$ 条件分别对应
$\mathsf{Compose}$ 已写入证书与避开禁止拼法。（2）（3）直接对照第~3~章基本转移与合法性定义：
未获证引用与命中 $\mathrm{Forbidden}$ 均为非法转移。
\end{proof}

\begin{example}[填满的闭包表示意：KEM.KeyGen]
\begin{center}
\begin{tabular}{@{}L{2.4cm}L{11.4cm}@{}}
  \toprule
  栏 & 示例 \\
  \midrule
  目标 &
  \texttt{kem.keygen.k4}；ek/dk 字节；验收 $\ell=\mathsf{deliverable}$（CPU+SIM，必要时 KAT） \\
  已获证 &
  \texttt{pke.keygen.k4}（stable 节点卡）；相关 P1 在 PKE 获证时已闭合 \\
  依赖闭包 &
  PKE.KeyGen + KEM 相对 PKE 的尾缝（2-launch / Alg.16 / $\mathit{dk}$ 展开等） \\
  缺项 &
  若尾缝尚未单独获证 $\Rightarrow$ 非空；不得在「写 KEM」任务里顺便重写 NTT \\
  接缝 &
  Alg.16 / $\mathit{dk}$ 等接缝顶点；未获证则 $\mathrm{PermitCode}=\mathrm{false}$ \\
  否定 &
  不得以 frozen / correctness vendor 为模板；不得把 liboqs C 当 AscendC 规格 \\
  \bottomrule
\end{tabular}
\end{center}
若尾缝尚在 $\mathrm{Seams}\setminus\Gamma$，则许可为假——即使 PKE 已绿。
\end{example}

\subsection{门禁判定与最小补洞}
\label{sec:gates-decide}

\begin{methodalgo}{门禁判定 $\mathrm{GateCheck}$}
\label{alg:gate-check}
\algoparam{本算法\textbf{只读}闭包表 $\mathrm{CT}$ 的各栏（不另取 $G$）。
若输入尚不是表，则携带与算法~\ref{alg:closure-table} \textbf{相同}的参数，先调用之得到 $\mathrm{CT}$。}
\algoin{闭包表 $\mathrm{CT}$（或先输入 $T,\mathcal{C},\ell$ 再内生调用 $\mathrm{BuildClosureTable}$）。}
\algoout{$\mathsf{ALLOW}$（允许按 $\ell$ 写 $T$）或 $\mathsf{BLOCK}(R)$（拒绝原因袋 $R$）。}
\begin{algosteps}
  \item 若输入不是完整 $\mathrm{CT}$，则用本算法参数调用算法~\ref{alg:closure-table} 生成 $\mathrm{CT}$；失败则
        $\mathsf{BLOCK}(\{\mathsf{no\_table}\})$。
  \item 若 $\mathrm{CT}$ 未完整，返回 $\mathsf{BLOCK}(\{\mathsf{no\_table}\})$。
  \item 若 $\mathrm{ForbiddenHit}\neq\emptyset$，返回 $\mathsf{BLOCK}(\{\mathsf{forbidden}\}\cup\mathrm{ForbiddenHit})$。
  \item 若 $M\neq\emptyset$ 或 $\mathrm{Seams}\not\subseteq\Gamma$，返回
        $\mathsf{BLOCK}(\{\mathsf{missing}\}\cup M\cup(\mathrm{Seams}\setminus\Gamma))$。
  \item 否则返回 $\mathsf{ALLOW}$。
\end{algosteps}
\end{methodalgo}

\begin{methodalgo}{最小补洞一轮 $\mathrm{MinimalFillRound}$}
\label{alg:min-fill}
\algoparam{有限依赖图 $G$；当前已获证集 $\Gamma$
（选取缺项生成集时必须相对 $G$ 上的 $\mathrm{Dep}^*_G$ 判定）。}
\algoin{目标 $T$；当前 $M=\mathrm{Missing}_\Gamma(T)$（可含未获证接缝）。}
\algoout{本轮补证对象集合 $B\subseteq M$，以及建议的动作序列（对每个 $u\in B$：$\mathsf{Probe}$ 然后条件性 $\mathsf{Certify}$）。}
\begin{algosteps}
  \item 若 $M=\emptyset$，返回 $B=\emptyset$。
  \item 以参数 $G$ 调用 $\mathrm{DepStar}(T)$ 得 $D=\mathrm{Dep}^*_G(T)$。
  \item 在 $M$ 中选取 $B\subseteq M$，使
        $\mathrm{Dep}^*_G\bigl((D\cap\Gamma)\cup B\bigr)=\mathrm{Dep}^*_G(T)$
        （即第~3~章「相对 $\Gamma$ 的缺项生成集」；优先较小者；有限图 $G$ 上极小生成集存在）。
  \item 对每个 $u\in B$：输出动作「$\mathsf{Probe}(u)$；验收通过则 $\mathsf{Certify}(u)$ 使 $\Gamma\leftarrow\Gamma\cup\{u\}$」。
  \item 禁止把 $B$ 选成「整份 $T$ 顶层实现」来冒充补洞——补洞对象应是缺项，不是跳过闭包。
\end{algosteps}
\end{methodalgo}

\begin{corollary}[补洞单调消缺项]
若一轮补洞成功得到 $\Gamma'\supseteq\Gamma$ 且 $B\subseteq\Gamma'$，则
$\mathrm{Missing}_{\Gamma'}(T)\subseteq\mathrm{Missing}_\Gamma(T)$（第~3~章缺项基本性质~3）。
反复执行算法~\ref{alg:min-fill} 直至 $M=\emptyset$，在有限 $V$ 上必终止。
\end{corollary}

\subsection{四步工作流＝外层算法}
\label{sec:gates-workflow}

把「声明—展开—补洞—写回」写成调用上述子程序的外层算法。

\begin{methodalgo}{任务工作流 $\mathrm{TaskWorkflow}$}
\label{alg:task-workflow}
\algoparam{作业过程自动机的合法转移集（第~3~章）；本章算法~\ref{alg:closure-table}--\ref{alg:min-fill}；
脏传播算法~\ref{alg:dirty}。}
\algoin{目标 $T$；I/O 契约 $\mathcal{C}$；级别 $\ell$。}
\algoout{接受（$T\in\Gamma$ 且前沿清空）或拒绝/冻结；以及写回后的 $\Gamma$。}
\begin{algosteps}
  \item \textbf{目标声明}：固定 $(T,\mathcal{C},\ell)$。
  \item \textbf{闭包展开}：$\mathrm{CT}\leftarrow\mathrm{BuildClosureTable}(T,\mathcal{C},\ell)$。
  \item \textbf{门禁}：若 $\mathrm{GateCheck}(\mathrm{CT})=\mathsf{BLOCK}(R)$，则
        对 $R$ 中缺项跑 $\mathrm{MinimalFillRound}$，每成功一次更新 $\Gamma$ 并回到步骤~2；
        若命中 $\mathsf{forbidden}$，执行 $\mathsf{Freeze}$ / 拒绝，停止。
  \item \textbf{允许写码}：当 $\mathrm{GateCheck}=\mathsf{ALLOW}$ 后，按 $\ell$ 实现 $T$；
        验收通过则 $\mathsf{Certify}(T)$，写回 INDEX/STATUS/节点卡。
  \item \textbf{非单调维护}：若随后某 $u$ 的 interface 变更，调用 $\mathrm{DirtyPropagate}(\{u\})$ 更新 $\Gamma$，
        并要求依赖锥内任务重新进入步骤~2。
\end{algosteps}
\end{methodalgo}

把算法~\ref{alg:task-workflow} 收成可扫读的表（任一步未完成，不得进入「大规模写码 / 开放试错」）：

\begin{proposition}[工作流轨迹是自动机路径的投影]
\label{prop:workflow-automaton}
算法~\ref{alg:task-workflow} 的每一步成功更新，都对应第~3~章作业过程自动机上的有限转移序列片段：
展开 $\sim\mathsf{Expand}$，补洞 $\sim\mathsf{Probe};\mathsf{Certify}$，写回 $\sim\mathsf{Certify}(T)$，
作废 $\sim\mathsf{Dirty}$，冻结 $\sim\mathsf{Freeze}$。
因此「守门禁」不是额外口号，而是要求 Agent 的轨迹落在合法转移集合内。
\end{proposition}

  统一 schema 未进日常流程；Dirty 传播无自动机制；
  「先交表再写码」正例当时未落地（第~\ref{sec:forward}~章已补） \\
  \bottomrule
\end{tabular}
\end{center}

\subsection{分析结论}
\label{sec:replay-verdict}

\begin{enumerate}
  \item \textbf{理论够不够复述已完成故事？够。}
        依赖闭包、接缝、禁止集、节点卡字段，都能在 KeyGen/Encaps 的交付态找到对应物；
        不必引入密码代数也能讲完「凭什么站在 PKE 上」。
  \item \textbf{史实不等于方法论已生效。}
        两条交付线都曾经历 correctness 或混乱探索；文书与 launch 约束大量\textbf{后置}。
        因此本章结论是「理论可解释」，不是「当时已按门禁派生」。
  \item \textbf{欠债清单（供第~\ref{sec:forward}~章对照）}
        \begin{itemize}
          \item 闭包表未始终领先实现（device 先绿、规格后补常见）；
          \item 接缝与 launch 预算后知（KeyGen 3$\to$2 launch；Encaps $m$ 语义漂移）；
          \item Dirty 失效传播仍靠人记；
          \item 门禁未工具化，Agent 仍可能绕开 $\mathrm{Forbidden}$。
        \end{itemize}
  \item \textbf{对下一章的输入。}
        若方法论有效，Decaps 应能在写码前交出真 $\mathrm{CT}$（含多父依赖与 FO 失败路径接缝），
        并在门禁下实现到约定验收级别；过程应可明显区别于 correctness 探索史
        （比较轴见第~\ref{sec:correctness}~章）。若做不到，应如实判「弱成功未达成」，并回写理论欠债——
        而不是事后贴标签。
\end{enumerate}

\subsection{本章小结}
\label{sec:replay-summary}

\begin{enumerate}
  \item 为 \texttt{kem.keygen}、\texttt{kem.encaps} 各补了一张事后 $\mathrm{CT}$；$M=\emptyset$ 与交付态一致。
  \item 三类边均有仓库实例；correctness/\texttt{frozen/} 归入 $\mathrm{Forbidden}$，不作正向 \texttt{repo}。
  \item 第~\ref{sec:hook}~章四组问题：复述与负例已加强；「先交表再写码」的正例见第~\ref{sec:forward}~章（已判决）。
\end{enumerate}

\section{对照组：\texttt{correctness} 标本的意义}
\label{sec:correctness}

\subsection{为何保留 correctness}
\texttt{*-correctness-*} 在\textbf{完全不考虑优化}的前提下，只追求能跑、结果对：
多 kernel launch、多搬运与同步——这是「一定能搭出正确积木」的保守拼法，
性能谈不上，后续 P0/P1 的工程优化也几乎接不进去。

它还记下了一段真实的 Agent 过程：故意不给确定的拼装路线时，
探索成本极高（失败、卡死、回退；短时间内曾烧掉大量 token），最后只得到「结果正确」的代码。

\subsection{在方法论里扮演什么角色}
\begin{center}
\begin{tabular}{@{}L{3cm}L{11cm}@{}}
  \toprule
  角色 & 含义 \\
  \midrule
  正确性锚 & 下界存在性：积木搭得出来，I/O 也对得上 \\
  结构反例 & 展示「只求对」会长成怎样的 launch/同步膨胀 \\
  过程对照 & 没有确定路线时，搜索要付多大代价 \\
  实验基线 & 和方法论 Agent、人工指导路径三方比较 \\
  \bottomrule
\end{tabular}
\end{center}

\textbf{纪律}：correctness 是\textbf{基线标本}，不是活跃实现模板；可读、可对拍、可对比，\textbf{禁止}当抄码来源（和 frozen「出门不带码」同一条规矩）。

\subsection{建议比较的几条轴}
\begin{enumerate}
  \item \textbf{过程}：token / 轮次 / 回退；有没有先交闭包表；非法边有没有被拦住；
  \item \textbf{结构}：launch 数、同步点、lemma 复用、接缝是否写清楚；
  \item \textbf{结果}：CPU+SIM；SIM tick 相对 correctness 是几倍。
\end{enumerate}
三档：A 旧式无路线探索 $\sim$ correctness；B 新方法论下的 Agent（本章 \texttt{-ct} 树）；
C 人工指导的交付 device/stable（无 \texttt{-ct}）。
第~\ref{sec:forward}~章已给出一轮证据：B 明显好过 A（强成功），且\textbf{不必}打赢 C 的性能/1-session 定标；
五指标精简表见 \texttt{docs/research/2026-07-24-Decaps-correctness与CT五指标对照.md}。
