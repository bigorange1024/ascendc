\begin{abstract}
\textbf{愿景}：把「层层递进、先验证底层再拼高层」的工程直觉，提升为一套可教学、可门禁、可对照实验的形式方法——
使 Agent（以及人类协作者）在复杂预研任务中，\textbf{只沿已验证能力及其合法组合}生长实现，
从机制上压缩跳层发明与幻觉空间；最终服务一般预研开发，而非仅服务某一密码标准的算子清单。

\textbf{写法}：仿教材而非论文——先从特例讲故事，再抽象数学对象，再复盘与前瞻；
证明与完备性后置，允许边做边补。\textbf{地位}：\texttt{docs/research/} 调研草稿，非定稿、非交付验收依据。

\textbf{压力测试床}：ML-KEM-1024 链上的 \texttt{pke.keygen} / \texttt{kem.keygen} / \texttt{kem.encaps}，
并以 \texttt{kem.decaps} 为理论前瞻试金石；\texttt{*-correctness-*} 作为「只求正确、不计优化」的对照组标本。
\end{abstract}

\subsection{愿景（一句话）}
我们想表达的是：预研开发\textbf{不应当}变成「对着算法说明书自由发挥写核」。
我们应当只在\textbf{已经拿到证书}的能力之上，按规则组合出更复杂的任务；
静态 DAG 只是「引理库谁依赖谁」的一张投影图，真正的作业过程还要另说。

\begin{enumerate}
  \item 一套\textbf{教材式}叙述：新人 / 新 Agent 能从特例读懂「图从哪来、树怎么长」；
  \item 一套\textbf{可操作门禁}：任务启动必须先交依赖闭包与缺项，再写码；
  \item 一套\textbf{对照实验协议}：方法论指导下的实现 vs correctness 标本 vs 人工指导路径；
  \item （成型后）可解释的接受/拒绝轨迹，以及必要的证明——\textbf{不}作为本稿前置条件。

\section{一个完整例子：我们怎样做出 ML-KEM-1024 的 KEM.KeyGen}
\label{sec:hook}

本章用一个\textbf{已经做完}的真实任务当例子。
我们先说清楚「要算什么」，再贴 FIPS~203 里的算法原文，
然后交代我们手里已经有什么、前期做过哪些实验、最后怎样拼出 KEM.KeyGen。
例子讲完之后，我们再\textbf{提问}——这些问题应当能把读者自然带到后文的研究课题里。

\subsection{我们要交付什么}

我们的目标是：在 Ascend AI Core 上用 AscendC 实现
\textbf{FIPS~203 ML-KEM-1024 的密钥生成}（\texttt{ML-KEM.KeyGen}，即 Algorithm~19）。

读者可以把交付物理解成下面这张黑盒表（细节以 stable 目录 customspec 为准）：

\begin{center}
\begin{tabular}{@{}lll@{}}
  \toprule
  方向 & 内容 & 说明 \\
  \midrule
  输入 & \texttt{seed\_d.bin}（4\,B） & Host 写入；设备侧派生 $d$、$z$ \\
  输入 & NTT LUT（静态） & 与 PKE KeyGen 同表 \\
  输出 & \texttt{ek\_kem.bin}（1568\,B） & 与 \texttt{ek\_PKE} 相同 \\
  输出 & \texttt{dk\_kem.bin}（3168\,B） & 与 liboqs 展开布局一致 \\
  \bottomrule
\end{tabular}
\end{center}

我们\textbf{不}把 $d$、$z$、中间 $\hat{A}$、$\hat{s}$ 等当作交付文件落盘。
验收方式是：\texttt{run.sh} 跑 CPU 孪生 + SIM，输出与 golden / liboqs 对拍一致。

\subsection{FIPS~203 原文：三层算法怎样套在一起}

标准把 KEM 密钥生成拆成三层。
下面给出\textbf{与 FIPS~203 原文一致的参数、Input/Output 与步骤编号}。
正文引用 NIST FIPS~203 Algorithm~13 / 16 / 19；本文实例固定为 \texttt{ml\_kem\_1024}（$k{=}4$ 时 $\lvert\mathit{ek}\rvert{=}1568$\,B，$\lvert\mathit{dk}\rvert{=}3168$\,B）。

\begin{fipsalgo}{Algorithm 19 \texttt{ML-KEM.KeyGen()}（FIPS~203 §7.1）}
\fipsioparam{$n{=}256$，$q{=}3329$，$k{=}4$，$\eta_1{=}\eta_2{=}2$，$d_u{=}11$，$d_v{=}5$。}
\fipsioin{（无显式输入；$d$、$z$ 在算法内由 RBG 采样，见步骤 1--2。）}
\fipsioout{封装密钥 $\mathit{ek} \in \mathbb{B}^{384k+32}$；\\
           解封密钥 $\mathit{dk} \in \mathbb{B}^{768k+96}$。}
\begin{fipssteps}
  \item $d \leftarrow\$ \mathbb{B}^{32}$
  \item $z \leftarrow\$ \mathbb{B}^{32}$
  \item \textbf{if} $d = \mathrm{NULL}$ \textbf{or} $z = \mathrm{NULL}$ \textbf{then}
  \item \quad\textbf{return} $\bot$ \hfill{\footnotesize RBG 失败指示}
  \item \textbf{end if}
  \item $(\mathit{ek}, \mathit{dk}) \leftarrow \texttt{ML-KEM.KeyGen\_internal}(d, z)$
  \item \textbf{return} $(\mathit{ek}, \mathit{dk})$
\end{fipssteps}
\end{fipsalgo}

\begin{fipsalgo}{Algorithm 16 \texttt{ML-KEM.KeyGen\_internal}$(d, z)$（FIPS~203 §6.1）}
\fipsioparam{$n{=}256$，$q{=}3329$，$k{=}4$，$\eta_1{=}\eta_2{=}2$，$d_u{=}11$，$d_v{=}5$。}
\fipsioin{随机种子 $d \in \mathbb{B}^{32}$；随机种子 $z \in \mathbb{B}^{32}$。}
\fipsioout{封装密钥 $\mathit{ek} \in \mathbb{B}^{384k+32}$；\\
           解封密钥 $\mathit{dk} \in \mathbb{B}^{768k+96}$。}
\begin{fipssteps}
  \item $(\mathit{ek}_{\mathrm{PKE}}, \mathit{dk}_{\mathrm{PKE}}) \leftarrow \texttt{K-PKE.KeyGen}(d)$
  \item $\mathit{ek} \leftarrow \mathit{ek}_{\mathrm{PKE}}$
  \item $\mathit{dk} \leftarrow \mathit{dk}_{\mathrm{PKE}} \Vert \mathit{ek} \Vert H(\mathit{ek}) \Vert z$
  \item \textbf{return} $(\mathit{ek}, \mathit{dk})$
\end{fipssteps}
\end{fipsalgo}

\noindent 其中 $H = \mathrm{SHA3\text{-}256}$（FIPS~203 记号 $H$）。

\begin{fipsalgo}{Algorithm 13 \texttt{K-PKE.KeyGen}$(d)$（FIPS~203 §5.1）}
\fipsioparam{$n{=}256$，$q{=}3329$，$k{=}4$，$\eta_1{=}\eta_2{=}2$，$d_u{=}11$，$d_v{=}5$。}
\fipsioin{随机种子 $d \in \mathbb{B}^{32}$。}
\fipsioout{加密密钥 $\mathit{ek}_{\mathrm{PKE}} \in \mathbb{B}^{384k+32}$；\\
           解密密钥 $\mathit{dk}_{\mathrm{PKE}} \in \mathbb{B}^{384k}$。}
\begin{fipssteps}
  \item $(\rho, \sigma) \leftarrow G(d \Vert k)$ \hfill{\footnotesize 域分离：字节 33 为模块维 $k$}
  \item $N \leftarrow 0$
  \item \textbf{for} $i \leftarrow 0$ \textbf{to} $k-1$ \textbf{do}
  \item \quad\textbf{for} $j \leftarrow 0$ \textbf{to} $k-1$ \textbf{do}
  \item \quad\quad$\hat{A}[i,j] \leftarrow \texttt{SampleNTT}(\rho \Vert j \Vert i)$
  \item \quad\textbf{end for}
  \item \textbf{end for}
  \item \textbf{for} $i \leftarrow 0$ \textbf{to} $k-1$ \textbf{do}
  \item \quad$s[i] \leftarrow \texttt{SamplePolyCBD}_{\eta_1}(\texttt{PRF}_{\eta_1}(\sigma, N))$;\quad $N \leftarrow N+1$
  \item \textbf{end for}
  \item \textbf{for} $i \leftarrow 0$ \textbf{to} $k-1$ \textbf{do}
  \item \quad$e[i] \leftarrow \texttt{SamplePolyCBD}_{\eta_1}(\texttt{PRF}_{\eta_1}(\sigma, N))$;\quad $N \leftarrow N+1$
  \item \textbf{end for}
  \item $\hat{s} \leftarrow \texttt{NTT}(s)$
  \item $\hat{e} \leftarrow \texttt{NTT}(e)$
  \item $\hat{t} \leftarrow \hat{A} \circ \hat{s} + \hat{e}$ \hfill{\footnotesize NTT 域矩阵–向量乘加}
  \item $\mathit{ek}_{\mathrm{PKE}} \leftarrow \texttt{ByteEncode}_{12}(\hat{t}) \Vert \rho$
  \item $\mathit{dk}_{\mathrm{PKE}} \leftarrow \texttt{ByteEncode}_{12}(\hat{s})$
  \item \textbf{return} $(\mathit{ek}_{\mathrm{PKE}}, \mathit{dk}_{\mathrm{PKE}})$
\end{fipssteps}
\end{fipsalgo}

\textbf{读者只需抓住一条结构链}：
$\text{Alg.19} \Rightarrow \text{Alg.16} \Rightarrow \text{Alg.13}$。
Alg.19 比 Alg.13 \textbf{多出来的}主要是步骤 1--2 的 $z$、Alg.16 步骤 3 的拼接——
\textbf{并不是}把 NTT 或矩阵乘从头再写一遍。

\paragraph{本仓工程差异（验收已锁定，写在算法旁便于对照）}
\begin{itemize}
  \item 我们可复现跑分时，Host 只提供 4\,B \texttt{seed\_d}；$d$ 与 $z$ 在设备 UB 内派生（对应 Alg.19 步骤 1--2 的确定性扩展）。
  \item 我们对拍 liboqs 时，$\mathit{dk}$ 为 3168\,B 展开式
        $\mathit{dk\_pke}\Vert\mathit{ek}\Vert H\Vert z$，与 FIPS 代数最小形态一致，但字节布局与偏移以 customspec 为准。
\end{itemize}

\subsection{从这个例子出发，我们应当问什么？}

例子讲完，真正重要的是\textbf{问题}。
如果我们的研究课题是「怎样让 Agent 预研少幻觉、少撞墙」，
那么面对 KEM.KeyGen 这个故事，我们至少应当认真问下面四组问题。

\paragraph{第一组：标准与工程之间的缝隙}
\begin{enumerate}
  \item FIPS 只告诉我们\textbf{算什么}；它并没有告诉我们，在 Ascend 上应当\textbf{先验哪几块、按什么顺序拼}。
        我们凭什么在动手前就说「可以直接站在 stable PKE 上」——凭的是目录名，还是某种可写的证书？
  \item 探针列表（INDEX）像一张「能力菜单」。
        \textbf{菜单本身}是否等于\textbf{合法拼装说明书}？若不等，缺的那一页应当长什么样？
\end{enumerate}

\paragraph{第二组：「单点都对」之后，组合还对吗}
\begin{enumerate}
  \setcounter{enumi}{2}
  \item 当 NTT 探针 PASS、PKE KeyGen PASS 之后，\textbf{谁}来保证「2-launch 接缝」「Alg.16 尾拼 $\mathit{dk}$」也一定 PASS？
        我们能否把这种「组合不免费」写进理论，而不是每次靠工程师的经验？
  \item 若我们把 correctness 路线（更多 launch、更保守同步）与 device/stable 路线（更少 launch、吃到优化）
        都称为「正确」，\textbf{我们究竟在验收什么}——仅仅是输出字节，还是也要验收「沿已证能力生长」？
\end{enumerate}

\paragraph{第三组：Agent 若只知道算法和菜单，会发生什么}
\begin{enumerate}
  \setcounter{enumi}{4}
  \item 若我们只给 Agent 一段 Alg.19 伪代码 + INDEX 里有哪些探针 PASS，
        \textbf{但不给}确定的拼装路线，搜索空间会有多大？
        我们亲眼见过：过程高度混乱、大量回退、极耗 token，最后只留下「能跑对」的 correctness 标本。
  \item 我们能否把搜索空间收束为「只允许沿已证书边生长」，同时又\textbf{不}把工程优化堵死？
        收束的规则应当写在图里，还是写在某种「合法句子」里？
\end{enumerate}

\paragraph{第四组：怎样把一次成功变成可复用的方法}
\begin{enumerate}
  \setcounter{enumi}{6}
  \item 这次 KEM.KeyGen 的成功，能否被复述成一张\textbf{闭包表}：
        依赖谁、缺了谁、哪条边有证书、哪条边被禁止？
        若下一个人（或 Agent）做 Encaps / Decaps，我们能否\textbf{先交这张表再写码}？
  \item 当上游改了 tiling 或同步壳，下游哪些节点应当自动标「脏」？
        我们是否需要一种比「记得上次 PASS」更可靠的失效传播？
\end{enumerate}

\subsection{本工程现在能回答这四组问题吗？}

四组问题都很好，但「能回答」要分层次：
\textbf{工程实践里我们已有碎片}，\textbf{形式化方法论里我们尚未闭环}。
下表诚实对照（2026-07 专题讨论时的判断）。

  \item \textbf{第一组}：我们能指着 stable PKE 说「KEM 应站在这里」，但还缺一张人人（含 Agent）都认的\textbf{证书页}。
  \item \textbf{第二组}：我们知道接缝要单独验（例如 2-launch、尾缝），但还没把这条经验收成\textbf{可检查的规则}。

\subsection{集合、笛卡尔积、关系与函数}

\begin{definition}[集合与属于关系]
称由确定对象组成的汇集为\textbf{集合}。
若对象 $x$ 属于集合 $A$，记 $x\in A$；否则记 $x\notin A$。
不含任何元素的集合称为\textbf{空集}，记作 $\emptyset$。
若 $A$ 的每个元素都属于 $B$，称 $A$ 为 $B$ 的\textbf{子集}，记 $A\subseteq B$。
\end{definition}

\begin{definition}[笛卡尔积]
设 $A,B$ 为集合。其\textbf{笛卡尔积}为
\[
A\times B \;=\; \{\,(a,b)\mid a\in A,\; b\in B\,\}.
\]
元素 $(a,b)$ 称为\textbf{有序对}；一般地 $(a,b)=(a',b')$ 当且仅当 $a=a'$ 且 $b=b'$。
\end{definition}

\begin{definition}[二元关系]
设 $A,B$ 为集合。若 $R\subseteq A\times B$，则称 $R$ 为从 $A$ 到 $B$ 的\textbf{二元关系}。
当 $A=B$ 时，也称 $R$ 为 $A$ 上的二元关系。
若 $(a,b)\in R$，常简记为 $a\,R\,b$。
\end{definition}

\begin{definition}[关系的定义域与值域]
对关系 $R\subseteq A\times B$，定义
\[
\mathrm{dom}(R)=\{a\in A\mid \exists b\in B,\;(a,b)\in R\},
\quad
\mathrm{ran}(R)=\{b\in B\mid \exists a\in A,\;(a,b)\in R\}.
\]
\end{definition}

\begin{definition}[函数]
设 $A,B$ 为集合。称关系 $f\subseteq A\times B$ 为从 $A$ 到 $B$ 的\textbf{函数}
（记 $f:A\to B$），若对每个 $a\in A$，存在唯一的 $b\in B$ 使得 $(a,b)\in f$。
此时记 $b=f(a)$，称 $b$ 为 $a$ 在 $f$ 下的\textbf{像}。
\end{definition}

\begin{property}[关系与函数的对比]
二元关系允许「一个 $a$ 对应多个 $b$」；函数禁止这一点。
后文「证书状态赋值」按函数理解；「依赖边」按一般关系理解。
\end{property}

\begin{example}[纯数学：课程先修关系]
令 $A=\{\text{高数},\text{线代},\text{概率},\text{机器学习}\}$，

\[
R=\{(\text{高数},\text{概率}),\,(\text{线代},\text{机器学习}),\,(\text{概率},\text{机器学习})\}.
\]
则 $(\text{高数},\text{概率})\in R$，但 $(\text{概率},\text{高数})\notin R$（有序性）。

\subsection{有向图、路与环}

\begin{definition}[有向图]
\textbf{有向图}是一个有序对 $G=(V,E)$，其中 $V$ 为非空有限集（称为\textbf{顶点集}），
$E\subseteq V\times V$ 为\textbf{有向边集}。
若 $(u,v)\in E$，称有向边 $u\to v$，并称 $u$ 为该边的\textbf{起点}，$v$ 为\textbf{终点}。
\end{definition}

\begin{definition}[出邻域与入邻域]
对 $v\in V$，定义
\[
N^+(v)=\{u\in V\mid (v,u)\in E\},
\quad
N^-(v)=\{u\in V\mid (u,v)\in E\}.
\]
分别称为 $v$ 的\textbf{出邻域}与\textbf{入邻域}；
$|N^+(v)|$、$|N^-(v)|$ 称为出度、入度。
\end{definition}

\begin{definition}[有向途径、路径与环]
设 $G=(V,E)$。
\begin{enumerate}
  \item 顶点序列 $v_0,v_1,\ldots,v_k$（$k\ge 0$）称为\textbf{有向途径}，若对所有 $0\le i<k$ 有 $(v_i,v_{i+1})\in E$；
        称 $k$ 为该途径的\textbf{长度}。
  \item 若途径中顶点两两不同，则称为\textbf{有向路径}（简称路径）。
  \item 若 $k\ge 1$、$v_0=v_k$，且 $v_0,\ldots,v_{k-1}$ 两两不同，则称为\textbf{有向环}（简称环）。
\end{enumerate}
\end{definition}

\begin{definition}[可达]
若存在从 $u$ 到 $v$ 的有向途径，则称 $v$ 从 $u$ \textbf{可达}，记 $u\rightsquigarrow_G v$
（在上下文明确时可略去 $G$）。约定任意 $v$ 满足 $v\rightsquigarrow v$（长度为 $0$ 的途径）。
\end{definition}

\begin{lemma}[路径与途径]
在有限有向图中，$u\rightsquigarrow v$ 当且仅当存在从 $u$ 到 $v$ 的有向路径。
\end{lemma}
\begin{proof}
若存在途径，删去其上环段可得路径；反之，路径本身是途径。
\end{proof}

\begin{example}[纯数学：四点有向图]
令 $V=\{1,2,3,4\}$，$E=\{(1,2),(1,3),(2,4),(3,4)\}$。
则 $1\rightsquigarrow 4$，且存在两条不同路径 $1\to2\to4$ 与 $1\to3\to4$。
$4$ 的入邻域为 $N^-(4)=\{2,3\}$，出邻域 $N^+(4)=\emptyset$。
该图无环。

\subsection{有向无环图与拓扑序}

\begin{definition}[DAG]
若有向图 $G$ 不含有向环，则称 $G$ 为\textbf{有向无环图}（Directed Acyclic Graph，DAG）。
\end{definition}

\begin{definition}[拓扑序]
设 $G=(V,E)$，$|V|=n$。
顶点序列 $v_1,\ldots,v_n$ 称为 $G$ 的一个\textbf{拓扑序}，
若它是 $V$ 的排列，且对每条边 $(v_i,v_j)\in E$ 都有 $i<j$。
\end{definition}

\begin{theorem}[DAG 与拓扑序的刻画]
设 $G$ 为有限有向图。则下列条件等价：
\begin{enumerate}
  \item $G$ 是 DAG；
  \item $G$ 存在拓扑序。
\end{enumerate}
\end{theorem}
\begin{proof}[证明梗概]
（2）${\Rightarrow}$（1）：若有环，则环上边无法全部满足「起点下标小于终点下标」。\\
（1）${\Rightarrow}$（2）：DAG 中必有入度为 $0$ 的顶点；取其为 $v_1$，删去后再对剩余图归纳。
\end{proof}

\begin{corollary}[可按先决条件调度]
若依赖关系构成 DAG，则存在线性顺序，使得每条依赖边都从「先处理」指向「后处理」。
\end{corollary}

\begin{remark}[预研建模提示]
「先验证下层能力，再拼上层任务」要求依赖关系可拓扑排序，因而应建模为 DAG。
若出现环，通常意味着节点切分不清或误把双向约束画成了依赖。
\end{remark}

\subsection{闭包：从一般概念到依赖闭包}

前几节已有集合、关系、有向图。本节先回答一个更基本的问题：
\textbf{数学里说的「闭包」究竟是什么？}
然后再说明：后文的「依赖闭包 / 闭包表」，只是同一种想法在能力 DAG 上的具体化。

\subsubsection{在运算下封闭}

\begin{definition}[一元运算下的封闭性]
设 $U$ 为全集（讨论所在的大集合），$A\subseteq U$，
又设 $\varphi:U\to U$ 为一元运算（函数）。
称 $A$ 对 $\varphi$ \textbf{封闭}（或「在 $\varphi$ 下封闭」），若
\[
\forall x\in A,\quad \varphi(x)\in A.
\]
即：从 $A$ 里任取元素做一次 $\varphi$，结果仍落在 $A$ 里。
\end{definition}

\begin{definition}[二元运算下的封闭性]
设 $*\!:U\times U\to U$ 为二元运算。
称 $A\subseteq U$ 对 $*$ \textbf{封闭}，若
\[
\forall x,y\in A,\quad x*y\in A.
\]
\end{definition}

\begin{definition}[对一族运算封闭]
若给定若干运算（可混一元、二元），称 $A$ 对它们\textbf{封闭}，
当且仅当 $A$ 对其中每一个运算都封闭。
\end{definition}

\begin{example}[纯数学：封闭与不封闭]
取 $U=\mathbb{Z}$。
\begin{itemize}
  \item 偶数集 $2\mathbb{Z}$ 对加法封闭：两偶数之和仍为偶数。
  \item 奇数集对加法\textbf{不}封闭：$1+1=2$ 不是奇数。
  \item $\{0,1,2\}$ 对「加 $1$」这一元运算不封闭，因为 $\varphi(2)=3\notin\{0,1,2\}$。
\end{itemize}

\subsubsection{闭包：最小的封闭扩张}

直观想法：给定种子集合 $A$，以及若干「生成规则」（运算），
我们希望找到\textbf{既包含 $A$，又对规则封闭，又尽可能小}的集合。
这个最小集合就叫做 $A$ 的闭包。

\begin{definition}[闭包（由封闭性刻画）]
设 $U$ 为全集，$A\subseteq U$，并固定一组使子集可谈「封闭」的运算规则 $\mathcal{R}$。
称 $B\subseteq U$ 为 $A$ 关于 $\mathcal{R}$ 的一个\textbf{闭包}，若：
\begin{enumerate}
  \item $A\subseteq B$（包含种子）；
  \item $B$ 对 $\mathcal{R}$ 封闭；
  \item 若 $C\supseteq A$ 且 $C$ 对 $\mathcal{R}$ 封闭，则 $B\subseteq C$
        （$B$ 是所有「含 $A$ 的封闭集」中的\textbf{最小}者）。
\end{enumerate}
若这样的 $B$ 存在，常记作 $\mathrm{Cl}_{\mathcal{R}}(A)$，或在上下文明确时记 $\mathrm{Cl}(A)$。
\end{definition}

\begin{theorem}[闭包的存在性（有限情形够用版）]
若 $U$ 有限，则对任意 $A\subseteq U$ 与任意「从已有元素产生新元素」的规则族 $\mathcal{R}$
（形式：由已有元组确定性地加入有限个新点），$\mathrm{Cl}_{\mathcal{R}}(A)$ 存在且唯一，
并可取为
\[
\mathrm{Cl}_{\mathcal{R}}(A)
\;=\;
\bigcap\{\,C\subseteq U\mid A\subseteq C,\; C\text{ 对 }\mathcal{R}\text{ 封闭}\,\}.
\]
（任意一族含 $A$ 的封闭集，其交仍含 $A$ 且封闭；有限全集上该族非空，因 $U$ 本身封闭。）
\end{theorem}
\begin{proof}[证明梗概]
验证「含 $A$ 的封闭集」对任意交封闭，故交集是最小元。唯一性由最小性立即得到。
\end{proof}

\begin{remark}[两种看法同一个对象]
\begin{itemize}
  \item \textbf{由外向内}：所有合格封闭集的交；
  \item \textbf{由内向外}：从 $A$ 出发反复施加规则，直到不能再扩大（见下一小节迭代）。
\end{itemize}
后文算法几乎总用「由内向外」。
\end{remark}

\begin{definition}[迭代构造（一般模板）]
设规则是：对当前集合 $X$，令 $\Phi(X)$ 为「把 $X$ 对规则应用一轮后应有的元素」
（要求 $X\subseteq\Phi(X)$）。定义
\[
A_0=A,\qquad A_{k+1}=\Phi(A_k)\quad(k\ge 0),\qquad
A_\infty=\bigcup_{k\ge 0}A_k.
\]
在有限全集且 $\Phi$ 单调时，存在 $K$ 使 $A_K=A_{K+1}=\cdots=A_\infty$，且 $A_\infty=\mathrm{Cl}(A)$。
\end{definition}

\begin{example}[纯数学：对「加 $1$」的闭包]
取 $U=\{0,1,2,3,4\}$，$\varphi(x)=x+1$（约定 $\varphi(4)=4$ 以免越界），$A=\{2\}$。
则迭代：$\{2\}\to\{2,3\}\to\{2,3,4\}\to\{2,3,4\}$。
故 $\mathrm{Cl}(A)=\{2,3,4\}$——包含种子，并对 $\varphi$ 封闭的最小集。

\subsubsection{闭包算子}

不必每次都提运算 $\mathcal{R}$，也可以直接把「取闭包」看成作用在幂集上的函数。

\begin{definition}[闭包算子]
设 $U$ 为集合。映射 $\mathrm{Cl}:2^{U}\to 2^{U}$ 称为\textbf{闭包算子}，若对任意 $A,B\subseteq U$：
\begin{enumerate}
  \item \textbf{扩张性}：$A\subseteq \mathrm{Cl}(A)$；
  \item \textbf{单调性}：$A\subseteq B\Rightarrow \mathrm{Cl}(A)\subseteq\mathrm{Cl}(B)$；
  \item \textbf{幂等性}：$\mathrm{Cl}(\mathrm{Cl}(A))=\mathrm{Cl}(A)$。
\end{enumerate}
称 $\mathrm{Cl}(A)$ 为 $A$ 的\textbf{闭包}；若 $A=\mathrm{Cl}(A)$，称 $A$ 为\textbf{闭集}（对该算子而言）。
\end{definition}

\begin{proposition}[闭集即「已经封闭」]
$A$ 为闭集当且仅当 $\mathrm{Cl}(A)=A$。
对由规则 $\mathcal{R}$ 导出的闭包算子，闭集恰好是对 $\mathcal{R}$ 封闭的那些子集。
\end{proposition}

\begin{property}[闭包是「补全到封闭」]
$\mathrm{Cl}(A)$ 可以理解为：从 $A$ 出发，把所有被规则逼出来的点都补上，直到不能再补。
幂等性说：补第二次不会再增加新点。
\end{property}

\begin{example}[纯数学：若干熟悉的闭包]

  \toprule
  场景 & 种子 $A$ & 闭包在补什么 \\
  \midrule
  实数区间 & $\{0,1\}$ & 对「中间点」封闭 $\to [0,1]$（拓扑闭包的朴素版） \\
  线性代数 & 若干向量 & 对加与数乘封闭 $\to$ 生成子空间 \\
  关系 & 边集 $E$ & 对「可走更长路径」封闭 $\to E^{*}$（下一小节） \\
  \bottomrule
\end{tabular}
\end{center}
\end{example}

\subsubsection{关系的传递闭包：闭包的第一个正式例子}

现在回到二元关系。这是连接「一般闭包」与「图上依赖闭包」的桥梁。

以下固定有限集 $V$，关系 $R\subseteq V\times V$。

\begin{definition}[关系的复合与幂]
对 $R,S\subseteq V\times V$，定义复合
\[
R\circ S=\{\,(u,w)\mid \exists v,\;(u,v)\in R,\;(v,w)\in S\,\}.
\]
令 $R^{1}=R$，$R^{k+1}=R^{k}\circ R$，并令 $R^{0}=\Delta_V=\{(v,v)\mid v\in V\}$。
注意：$R^{0}$ 是\textbf{单独约定}的恒等关系，表示长度为 $0$ 的途径；
它\textbf{不是}把 $R$ 与自身复合得到的（复合从 $R^{1}$、$R^{2},\ldots$ 才开始）。
\end{definition}

\begin{definition}[传递闭包与自反传递闭包]
\[
R^{+}=\bigcup_{k\ge 1}R^{k},
\qquad
R^{*}=\bigcup_{k\ge 0}R^{k}=R^{0}\cup R^{+}.
\]
称 $R^{+}$ 为 $R$ 的\textbf{传递闭包}，$R^{*}$ 为\textbf{自反传递闭包}。
\end{definition}

\begin{proposition}[$R^{*}$ 确实是闭包]
在「关系集合」$U=2^{V\times V}$ 上，若规则是「若有 $(u,v),(v,w)$ 则加入 $(u,w)$，且保留全部恒等对」，
则从 $R$ 生成的闭包恰为 $R^{*}$。
特别地：$R\subseteq R^{*}$，$R^{*}$ 传递且自反，且是满足这些性质的最小关系。
\end{proposition}

\begin{theorem}[传递闭包与路径]
$(u,v)\in R^{k}$ 当且仅当存在长度恰为 $k$ 的 $R$-途径从 $u$ 到 $v$。
因而 $(u,v)\in R^{*}$ 当且仅当 $u$ 经若干步（含 $0$ 步）到达 $v$。
\end{theorem}

\begin{example}[纯数学：三点关系的传递闭包]
令 $V=\{a,b,c\}$，$R=\{(a,b),(b,c)\}$。逐项按定义展开：
\begin{align*}
R^{0} &=\Delta_V=\{(a,a),(b,b),(c,c)
\} && \text{（恒等关系；\textbf{不是}由 $R$ 复合得到）}, \\
R^{1} &=R=\{(a,b),(b,c)\}, \\
R^{2} &=R\circ R=\{(a,c)
\} && \text{（复合：经中间点 $b$）}, \\
R^{+} &=R^{1}\cup R^{2}=\{(a,b),(b,c),(a,c)
\} && \text{（传递闭包：只含正长度路径）}, \\
R^{*} &=R^{0}\cup R^{+}=\{(a,a),(b,b),(c,c),(a,b),(b,c),(a,c)\}.
\end{align*}
因此：$(a,a)$ 这类对角元来自 $R^{0}$（$0$ 步路径约定），
\textbf{不是} $R\circ R$ 算出来的；本例中 $R$ 本身也没有自环。
图中三种线分别对应三类来源：

\subsubsection{有向图上的依赖闭包}

从此固定有向图 $G=(V,E)$，并取边语义为依赖：
\[
u\to v \quad\text{表示}\quad\text{「$v$ \textbf{依赖} $u$」}
\quad\text{（$u$ 先决，$v$ 后继）}.
\]
与 §2 数据流箭头可能相反；\textbf{计算闭包以本节为准}。

\begin{definition}[转置图]
$G^{\top}=(V,E^{\top})$，$E^{\top}=\{(v,u)\mid (u,v)\in E\}$（箭头反向）。
\end{definition}

\begin{definition}[直接前驱 / 直接后继]
\[
\mathrm{Pred}_G(v)=N^-(v),\qquad
\mathrm{Succ}_G(v)=N^+(v).
\]
\end{definition}

\begin{definition}[祖先与后代]
若 $u\rightsquigarrow_G v$，称 $u$ 为 $v$ 的\textbf{祖先}，$v$ 为 $u$ 的\textbf{后代}
（含 $u=v$）。
\end{definition}

\begin{definition}[单点依赖闭包]
对目标 $T\in V$，定义
\[
\mathrm{Dep}^*_G(T)
\;=\;
\{u\in V\mid u\rightsquigarrow_G T\}
\;=\;
\{u\in V\mid (u,T)\in E^{*}\}.
\]
恒有 $T\in\mathrm{Dep}^*_G(T)$。略下标时写作 $\mathrm{Dep}^*(T)$。
\end{definition}

\begin{remark}[与一般闭包的对接]
取种子 $\{T\}$，规则为「若 $v$ 已在集合中，则把 $\mathrm{Pred}(v)$ 全部加入」。
则对该规则的闭包恰等于 $\mathrm{Dep}^*(T)$。
换言之：\textbf{依赖闭包 $=$ 「对取前驱封闭」的最小扩张}。
\end{remark}

\begin{proposition}[四种等价说法]
对任意 $u,T\in V$，下列等价：
\begin{enumerate}
  \item $u\in\mathrm{Dep}^*(T)$；
  \item $(u,T)\in E^{*}$；
  \item 存在路径 $u\to\cdots\to T$ 或 $u=T$；
  \item 在 $G^{\top}$ 中 $T\rightsquigarrow_{G^{\top}} u$。
\end{enumerate}
\end{proposition}

\subsubsection{依赖闭包的迭代、算法与算子性质}

\begin{definition}[依赖闭包的迭代序列]
定义集合序列
\begin{align*}
D_0(T) &= \{T\}, \\
D_{k+1}(T) &= D_k(T) \;\cup\; \bigcup_{v\in D_k(T)}\mathrm{Pred}(v)
\quad (k\ge 0).
\end{align*}
\end{definition}

\begin{theorem}[迭代收敛到依赖闭包]
对有限图 $G$，序列 $\{D_k(T)\}_{k\ge 0}$ 在有限步内稳定，且
\[
\bigcup_{k\ge 0} D_k(T) \;=\; \mathrm{Dep}^*(T).
\]
更精确地：存在 $K\le |V|$ 使对所有 $k\ge K$ 有 $D_k(T)=\mathrm{Dep}^*(T)$。
\end{theorem}
\begin{proof}[证明梗概]
$D_k(T)$ 单调递增且含于有限集 $V$，故稳定。
稳定时集合对取 $\mathrm{Pred}$ 封闭，且含 $T$，故包含一切能走到 $T$ 的顶点；
反之，任何通向 $T$ 的长度为 $\ell$ 的路径上的点在 $D_\ell(T)$ 中出现。
\end{proof}

\begin{remark}[迭代即一般模板的特例]
$D_k(T)$ 正是前面「由内向外」迭代构造中 $A_k$ 的特例：
种子 $A=\{T\}$，一轮算子 $\Phi(X)=X\cup\bigcup_{v\in X}\mathrm{Pred}(v)$。
定理「迭代收敛到依赖闭包」即一般闭包存在性在图上的具体化。
\end{remark}

\begin{lemma}[反向搜索算法]
在有限图上执行：
从 $T$ 出发，在 $G^{\top}$ 中做 BFS/DFS（等价于沿 $G$ 的边反向走），
访问到的顶点集合恰为 $\mathrm{Dep}^*(T)$。
时间复杂度 $O(|V|+|E|)$（邻接表）。
\end{lemma}

\subsubsection{目标集的闭包、基与缺项}

\begin{definition}[有限目标集的依赖闭包]
对非空有限集 $A\subseteq V$，定义
\[
\mathrm{Dep}^*_G(A) \;=\; \bigcup_{T\in A}\mathrm{Dep}^*_G(T).
\]
约定 $\mathrm{Dep}^*_G(\emptyset)=\emptyset$。
\end{definition}

\begin{proposition}[$\mathrm{Dep}^*$ 是闭包算子]
映射 $\mathrm{Cl}:2^{V}\to 2^{V}$，$\mathrm{Cl}(A)=\mathrm{Dep}^*(A)$ 满足扩张、单调、幂等三条公理，
因而是前文所定义的\textbf{闭包算子}；其闭集恰为「对取前驱已封闭」的顶点集。
\end{proposition}
\begin{proof}[证明梗概]
扩张与单调由并与可达性立即得到；幂等因为祖先的祖先仍是祖先。
\end{proof}

\begin{definition}[已证书集、缺项与闭包已满]
设 $\Gamma\subseteq V$ 为当前\textbf{已证书}顶点集。对 $A\subseteq V$，定义
\[
\mathrm{Missing}_\Gamma(A) \;=\; \mathrm{Dep}^*(A)\setminus \Gamma.
\]
若 $\mathrm{Missing}_\Gamma(A)=\emptyset$，称 $A$ 相对 $\Gamma$ \textbf{闭包已满}。
当 $A=\{T\}$ 时简记 $\mathrm{Missing}_\Gamma(T)$。
\end{definition}

\begin{definition}[相对基（直观）]
若 $B\subseteq\mathrm{Dep}^*(T)$ 满足 $\mathrm{Dep}^*(B)=\mathrm{Dep}^*(T)$，称 $B$ 为 $\mathrm{Dep}^*(T)$ 的一个\textbf{生成集}。
工程上常关心「最小还缺哪些叶子能力」，即在 $\mathrm{Missing}_\Gamma(T)$ 中寻找生成缺项的关键结点；
精确极小基的算法后文门禁章再展开，此处只要求会算 $\mathrm{Dep}^*$ 与 $\mathrm{Missing}$。
\end{definition}

\begin{property}[菜单、$\Gamma$ 与闭包]
INDEX 等「菜单」提供构造 $\Gamma$ 的证据来源，但
\[
\text{菜单上有许多绿项}
\quad\not\Rightarrow\quad
\mathrm{Missing}_\Gamma(T)=\emptyset.
\]
必须先算 $\mathrm{Dep}^*(T)$，再与 $\Gamma$ 做差。
\end{property}

\subsection{三层对象：库、一次派生、过程}

进入形式语言之前，必须把三个层次从定义上分开；否则后文「DAG / 语法树 / 自动机」会混用。

\begin{definition}[能力 DAG（库）]
\textbf{能力 DAG} 是 DAG $G_{\mathrm{lib}}=(V_{\mathrm{lib}},E_{\mathrm{lib}})$，
顶点为可命名、可获证的能力，边为依赖（语义依赖或已声明接缝依赖）。
它描述引理库的\textbf{静态}结构，不随单次任务进度改写边集
（结点证书状态可变，见配置层）。
\end{definition}

\begin{definition}[一次任务与派生对象]
固定目标 $T\in V_{\mathrm{lib}}$ 与文法 $\mathcal{G}$（定义见后文）。
\textbf{一次任务}指试图使 $T$ 获证的一次预研作业。
该作业中，从开始符号出发按产生式改写所得的符号串序列称为\textbf{派生}；
其树形记录称为\textbf{派生树}。派生树是 $G_{\mathrm{lib}}$ 上依赖信息的\textbf{一次使用痕迹}，不是整库拷贝。
\end{definition}

\begin{definition}[配置轨迹]
预研过程中的状态序列 $q_0\to q_1\to\cdots\to q_m$，其中每个 $q_i$ 为配置
$(\Gamma_i,F_i,S_i)$（定义见迁移系统一节），称为\textbf{配置轨迹}。
它记录证书如何增减、前沿如何消解。
\end{definition}

\subsection{字母表、字与语言}

\begin{definition}[字母表与字]
非空有限集 $\Sigma$ 称为\textbf{字母表}；其元素称为\textbf{字母}。
$\Sigma$ 上的\textbf{字}是有限序列 $w=a_1a_2\cdots a_n$（$n\ge 0$，$a_i\in\Sigma$）；
$n=0$ 时称为\textbf{空字}，记 $\varepsilon$。
称 $n=|w|$ 为字长。全体字之集记 $\Sigma^*$（Kleene 星）。
又记 $\Sigma^+=\Sigma^*\setminus\{\varepsilon\}$。
\end{definition}

\begin{definition}[前缀、后缀与因子]
设 $w,x\in\Sigma^*$。
\begin{itemize}
  \item 若存在 $y$ 使 $w=xy$，称 $x$ 为 $w$ 的\textbf{前缀}；
  \item 若存在 $y$ 使 $w=yx$，称 $x$ 为 $w$ 的\textbf{后缀}；
  \item 若存在 $y,z$ 使 $w=yxz$，称 $x$ 为 $w$ 的\textbf{因子}（子字）。
\end{itemize}
\end{definition}

\begin{definition}[语言]
若 $L\subseteq\Sigma^*$，则称 $L$ 为 $\Sigma$ 上的一个\textbf{语言}。
称 $w$ 对 $L$ \textbf{合法}（或 $w$ 属于 $L$），若 $w\in L$。
\end{definition}

\begin{definition}[语言的连接与星闭包]
对 $x,y\in\Sigma^*$，\textbf{连接} $xy$ 表示把 $y$ 接在 $x$ 后。
对语言 $L,M\subseteq\Sigma^*$，定义
\[
LM=\{xy\mid x\in L,\,y\in M\},
\quad
L^{0}=\{\varepsilon\},\;
L^{k+1}=L^{k}L,\;
L^{*}=\bigcup_{k\ge 0}L^{k}.
\]
\end{definition}

\begin{property}[连接对合法性不必封闭]
一般地，$x\in L$ 且 $y\in L$ \textbf{不能}推出 $xy\in L$。
（这是后文「组合不免费」的纯语言版本。）
\end{property}

\begin{proposition}[$\Sigma^*$ 的通用性]
任一语言都是 $\Sigma^*$ 的子集；讨论「合法计划」即指定某个 $L\subseteq\Sigma^*$。
门禁的数学内核是：给定 $w$，判定 $w\in L$ 是否成立（成员判定，见后文）。
\end{proposition}

\subsection{文法、产生式、派生与派生树}

\begin{definition}[上下文无关文法（本教材用法）]
\textbf{上下文无关文法}是四元组 $\mathcal{G}=(N,\Sigma,P,S)$，其中：
\begin{itemize}
  \item $N$ 为有限\textbf{非终结符}集；
  \item $\Sigma$ 为有限\textbf{终结符}集，$N\cap\Sigma=\emptyset$；
  \item $S\in N$ 为\textbf{开始符号}；
  \item $P$ 为有限\textbf{产生式}集，每个产生式形如 $A\to\alpha$，其中 $A\in N$，$\alpha\in(N\cup\Sigma)^*$。
\end{itemize}
\end{definition}

\begin{definition}[一步派生与多步派生]
若 $\alpha=\alpha_1 A \alpha_2$，$A\to\beta\in P$，则称 $\alpha$ \textbf{一步派生}出 $\alpha_1\beta\alpha_2$，记 $\alpha\Rightarrow\alpha_1\beta\alpha_2$。
$\Rightarrow^*$ 表示 $\Rightarrow$ 的自反传递闭包（零步或多步派生）。
\end{definition}

\begin{definition}[文法生成的语言]
\[
L(\mathcal{G}) \;=\; \{\,w\in\Sigma^*\mid S\Rightarrow^* w\,\}.
\]
\end{definition}

\begin{definition}[派生树]
对一次从 $S$ 到 $w\in\Sigma^*$ 的派生，其\textbf{派生树}（语法树）是满足以下条件的有根有序树：
根标记为 $S$；内部结点标记为非终结符；叶子从左到右连接恰为 $w$；
若内部结点标记 $A$ 且其孩子标记依次拼成 $\alpha$，则 $A\to\alpha\in P$。
\end{definition}

\begin{theorem}[派生与派生树]
对上下文无关文法，$\mathcal{G}$ 能派生出 $w$ 当且仅当存在以 $w$ 为叶子连接的派生树。
\end{theorem}

\begin{remark}[方法论中的对应]
非终结符 $\approx$ 尚未落到已证书原子步骤的目标；
终结符 $\approx$ 已证书调用或不可再分的合法动作；
产生式 $\approx$ 「目标可展开为哪些子目标 / 接缝」的改写规则。
\end{remark}

\begin{example}[纯数学：匹配括号的文法片段]
令 $N=\{S\}$，$\Sigma=\{(,)\}$，产生式 $S\to(S)\mid SS\mid\varepsilon$。
则 $()\in L(\mathcal{G})$，$()()\in L(\mathcal{G})$，而 $()\notin$ 的补——更精确地说 $)(\notin L(\mathcal{G})$。
派生树记录括号如何嵌套，而不仅仅是字母的前后顺序。
\end{example}

\begin{example}[工程：KEM.KeyGen 的改写]
直觉产生式（符号仅作说明）：
\[
\texttt{KEM.KeyGen}
\;\to\;
\texttt{PKE.KeyGen}\;\cdot\;\texttt{Alg16Tail}.
\]
若 $\texttt{PKE.KeyGen}$ 已是终结的已证书调用，而 $\texttt{Alg16Tail}$ 仍是非终结接缝，
则派生树根为 KEM.KeyGen，一侧叶子为 PKE，另一侧继续展开尾缝直至获证动作。

\subsection{成员判定、禁字与组合不免费}

\begin{definition}[成员判定问题]
给定语言 $L\subseteq\Sigma^*$ 与字 $w\in\Sigma^*$，判断是否 $w\in L$，称为 $L$ 的\textbf{成员判定}。
\end{definition}

\begin{definition}[禁字集]
设 $\mathrm{Forb}\subseteq\Sigma^*$。称语言 $L$ \textbf{避开} $\mathrm{Forb}$，若
\[
L \;\subseteq\; \{w\in\Sigma^*\mid \text{不存在 }f\in\mathrm{Forb}\text{ 作为 }w\text{ 的因子}\}.
\]
其中「因子」指存在 $x,y$ 使 $w=xfy$。
\end{definition}

\begin{definition}[组合不免费（方法论公理图式）]
称语言 $L$ 满足\textbf{组合不免费}，若存在 $x,y\in L$ 使得 $xy\notin L$。
在预研建模中我们\textbf{不假定} $L$ 对连接封闭；
若工程上需要把 $x$ 与 $y$ 顺序拼装，通常引入新的非终结符（接缝）与产生式，并要求该接缝获证。
\end{definition}

\begin{proposition}[菜单不能代替成员判定]
设 $\Sigma_0\subseteq\Sigma$ 为「菜单上可见的字母」。
仅给出 $\Sigma_0$ 不能唯一确定 $L$。
尤其，$L$ 还依赖产生式集合与禁字集 $\mathrm{Forb}$。
\end{proposition}

\begin{example}[纯数学]
取 $L=\{a,b\}\subseteq\{a,b\}^*$。则 $a,b\in L$ 但 $ab\notin L$，故组合不免费。
若希望允许 $ab$，必须把 $ab$ 显式加入 $L$，或增加产生式（例如 $S\to ab$）。
\end{example}

\begin{example}[工程]
PKE.KeyGen 计划与「某段哈希拼接」各自可能合法，
但「在新的 2-launch 边界下拼接二者」不必自动合法——这正是接缝节点
（如 Alg.16 尾缝、\texttt{KemKgTailFused}）存在的理由。
\texttt{frozen/} 文书对应 $\mathrm{Forb}$ 的工程来源之一。
\end{example}

\begin{remark}[门禁雏形]
Agent 提交「闭包表 + 展开计划 $w$」时，门禁检查的是：
$\mathrm{Missing}_\Gamma(T)=\emptyset$（全依赖已覆盖）且存在派生表明 $w\in L(\mathcal{G})$，
并且 $w$ 避开 $\mathrm{Forb}$。这是「先交闭包表，再写码」的数学表述。
\end{remark}

\subsection{迁移系统、配置与接受}

\begin{definition}[迁移系统]
\textbf{迁移系统}是三元组 $\mathcal{T}=(Q,\to,Q_0)$，其中 $Q$ 为配置集，
$\to\subseteq Q\times Q$ 为转移关系，$Q_0\subseteq Q$ 为初始配置集。
若 $(q,q')\in{\to}$，记 $q\to q'$。
\end{definition}

\begin{definition}[预研配置]
\textbf{预研配置}是三元组 $q=(\Gamma,F,S)$，其中
\begin{itemize}
  \item $\Gamma\subseteq V_{\mathrm{lib}}$ 为已证书能力集；
  \item $F$ 为前沿目标的有限多重集（待展开或待获证的目标）；
  \item $S$ 为约束库（含 I/O 契约、接缝声明、禁字集等）。
\end{itemize}
\end{definition}

\begin{definition}[基本转移（名称可修订）]
在约束 $S$ 允许的前提下，定义以下几类转移（均为 $\to$ 的子集）：
\begin{center}
\begin{tabular}{@{}L{2.4cm}L{11.2cm}@{}}
  \toprule
  名称 & 作用 \\
  \midrule
  $\mathsf{Expand}$ & 按产生式展开 $F$ 中某目标，更新缺项 \\
  $\mathsf{Probe}$ & 对缺项启动探针/预研以寻求证据 \\
  $\mathsf{Certify}$ & 验收通过后将结点写入 $\Gamma$ \\
  $\mathsf{Compose}$ & 声明并认证接缝（落实组合不免费） \\
  $\mathsf{Dirty}$ & 使部分证书失效（见下一节） \\
  $\mathsf{Freeze}$ & 将某路线写入禁字 / 否定约束 \\
  \bottomrule
\end{tabular}
\end{center}
\end{definition}

\begin{definition}[接受与拒绝]
固定目标 $T$ 与生产 I/O 契约 $\mathcal{C}$。
\begin{itemize}
  \item 配置 $q=(\Gamma,F,S)$ 称为\textbf{接受配置}，若 $T\in\Gamma$、$F$ 为空（或仅含已放电目标），且 $\mathcal{C}$ 满足；
  \item 若转移过程试图使用 $\mathrm{Forb}$ 中的因子、或引用 $\notin\Gamma$ 的依赖边且未先 $\mathsf{Probe}/\mathsf{Certify}$，
        则进入\textbf{拒绝}（具体可建模为沉入拒绝阱状态）。
\end{itemize}
\end{definition}

\begin{definition}[合法性与幻觉（工作定义）]
\begin{enumerate}
  \item 称一次预研过程\textbf{合法}，若它对应迁移系统中从某初始配置到接受配置的有限转移序列，
        且每一步都符合产生式与 $S$ 中约束。
  \item 称行为构成\textbf{幻觉}，若它执行了非法转移，或在图上使用了无证书边
        （等价地：计划字 $w\notin L$ 或未避开 $\mathrm{Forb}$）。
\end{enumerate}
语义 oracle（FIPS / liboqs / golden）判定「计算结果是否正确」；
本定义判定「砖是否允许那样砌」。
\end{definition}

\begin{example}[纯数学：门禁自动机小品]
状态 $\{q_0,q_{\mathrm{ok}},q_{\mathrm{bad}}\}$，字母 $\{a,b\}$。
$q_0\xrightarrow{a}q_0$，$q_0\xrightarrow{b}q_{\mathrm{ok}}$，其余进 $q_{\mathrm{bad}}$。
则字 $aab$ 被接受，$ba$ 被拒绝。这与「先合法前缀、再结束符」的门禁同构。
\end{example}

\begin{example}[工程]
初始 $\Gamma$ 含 stable PKE 等；$F=\{\texttt{kem.keygen}\}$。
经 $\mathsf{Expand}$ 得到尾缝缺项 $\to$ $\mathsf{Compose}/\mathsf{Probe}$ $\to$ $\mathsf{Certify}$ 后 $T\in\Gamma$，到达接受。
若中途从 \texttt{frozen-exp-*} 抄实现，则触发拒绝（$\mathsf{Freeze}$ 已写入 $\mathrm{Forb}$）。
\end{example}

\subsection{证书的非单调更新}

\begin{definition}[单调与非单调证书库]
称证书更新机制为\textbf{单调}的，若任意转移满足 $\Gamma\subseteq\Gamma'$（证书集只增不减）。
若允许某次转移后 $\Gamma'\subsetneq\Gamma$，则称为\textbf{非单调}的。
\end{definition}

\begin{definition}[脏标记]
对 $v\in\Gamma$，若因上游接口、布局或同步约定变更，使 $v$ 的既有证书不再被承认，
则称 $v$ 被标记为 $\mathsf{dirty}$，并在转移 $\mathsf{Dirty}$ 下将 $v$ 移出 $\Gamma$
（或移入「待重证」区）。具体存储格式后文工程化。
\end{definition}

\begin{proposition}[工程引理库非单调]
本方法论采用的证书库是非单调的：存在合法的 $\mathsf{Dirty}$ 转移使 $\Gamma$ 严格缩小。
\end{proposition}

\begin{corollary}[过期证书不可当作永真公理]
门禁在引用 $v\in\Gamma$ 时，须能够回答「自获证以来上游是否触发 $\mathsf{Dirty}$」。
\end{corollary}

\begin{example}[纯数学：撤回引理]
证明系统中若发现引理 $L_1$ 的证明有漏洞而撤回，则所有依赖 $L_1$ 的定理证书失效。
这与「断言永真后只增不减」的理想图景不同。
\end{example}

\begin{example}[工程]
P1 某能力的 tiling/同步壳变更后，曾基于旧 iface 的 P2/P3 证书应标 $\mathsf{dirty}$，
不得因「上次 PASS」而默认继续合法。
\end{example}

节点 $v$ 建议携带：
\begin{itemize}

\begin{center}
\begin{tabular}{@{}ll@{}}
  \toprule
  层 & 含义（本仓库语境） \\

  P3 & 顶层算子 / 算法入口（如 KEM.KeyGen、KEM.Encaps） \\
  P2 & 算法构件（如 PKE.KeyGen / Encrypt / Decrypt 全链） \\

\end{tabular}

\subsection{边的三种类型}
\begin{enumerate}
  \item \textbf{语义依赖}：$u$ 的正确性需要 $v$ 的 iface（如「NTT 能力」$\to$ PKE.KeyGen）；
  \item \textbf{接缝（compose）}：$A$、$B$ 各自有证，$A\!\circ\!B$ \textbf{仍须}单独成节点获证
        （「组合不免费」）；
  \item \textbf{否定边}：显式禁止（frozen 模板、未登记计算块、Host 默认密码路径等）。
\end{enumerate}

\subsection{证书状态（含非单调）}
\[
\mathsf{unproven}\to\mathsf{probe}\to\mathsf{lemma}\to\mathsf{deliverable},
\quad\text{以及}\quad
\mathsf{dirty}.
\]
\texttt{dirty} 表示上游 iface/tiling 变更后下游证书失效——引理库 $\Gamma$ \textbf{可收缩}。

\subsection{仓库机制与数学对象的对照（直觉）}
\begin{itemize}
  \item 活跃 \texttt{INDEX.md}：当前可引用的能力菜单（$\Sigma$ 的工程投影，\textbf{还不是} $L$）；
  \item \texttt{frozen/} + \texttt{FROZEN.md}：否定边；
  \item \texttt{baseline-registry}：golden 允许调用的已验证计算块；
  \item \texttt{customspec}：examples 写码的规格门禁（派生计划的文书形态之一）。
\end{itemize}

\subsection{立论（承接第~\ref{sec:mathbg}~章）}
\begin{quote}
预研开发的合法性 $\approx$ 在已证书能力生成的语言 $L$ 上，
由配置自动机搜索接受路径；\\
\textbf{幻觉} $\approx$ 非法转移 / 无证书边。\\
语义 oracle（FIPS/liboqs/golden）管「算对」；形式方法管「从哪砌砖」。
\end{quote}

\section{门禁与工作流：Agent 被允许做什么}
\label{sec:gates}

\subsection{合法性规则（v0）}
接到目标 $T$ 时，只允许：
\begin{enumerate}
  \item 展开依赖闭包（语义边 + 接缝边）；
  \item 分类：已有 lemma/deliverable；缺项；仅否定边；
  \item 缺项 $\Rightarrow$ 先探针/exp 并获证，再引用；禁止在 $T$ 任务里顺便发明 P0/P1；
  \item 新接缝 $=$ 新节点，须认证；
  \item 验收看 I/O 与 golden/KAT，不看「与参考源码同构」；
  \item 自包含：挂 iface，不跨目录偷源码（仓库既有例外除外）；图边 $\neq$ \texttt{\#include}。
\end{enumerate}

\subsection{四步工作流}
\begin{lstlisting}
1. 目标声明  T、I/O、验收级别（probe / lemma / deliverable）
2. 闭包展开  P0--P3；ok / missing / dirty；接缝清单
3. 最小补洞  只补 missing 与新接缝；forbid 写入否定边
4. 闭环写回  新节点入图；失败则改规则或 Freeze，不默认可复用
\end{lstlisting}
\textbf{先交闭包表，再写码。} customspec / STATUS / registry 是文书形态，不是替代闭包表。

\subsection{域无关性}
抽出密码词之后，对象仍是：终端（axiom）、非终端（goal）、产生式（compose）、证书（judgment）。
同一套问题适用于非密码 AscendC 预研；ML-KEM 只是 oracle 清晰、接缝丰富的\textbf{压力测试床}。

\section{前瞻：用理论指导尚未完成的 \texttt{kem.decaps}}
\label{sec:forward}

\subsection{为什么 Decaps 适合做试金石}
Decaps 同时依赖 Encrypt、Decrypt、KeyGen I/O 与 FO 失败路径，是典型的\textbf{多父 DAG}；
且若理论只能解释已完成故事、不能生成待做清单，则方法论停在修辞。

\subsection{前瞻时 Agent（或人类）应交付的最小闭包}
\begin{enumerate}
  \item 目标 I/O 与验收级别；
  \item 依赖节点清单（标 ok / missing / dirty）；
  \item 接缝清单（含对称失败 / 重加密比对等是否独立成节点）；
  \item 否定边（不可引用的 correctness vendor / frozen 实现）；
  \item 最小补洞顺序（先探针哪条缝）。
\end{enumerate}

\subsection{成功标准（阶段性）}
\begin{itemize}

\section{对照组：\texttt{correctness} 标本的意义}
\label{sec:correctness}

\subsection{为何保留 correctness}
\texttt{*-correctness-*} 在\textbf{完全不考虑优化}的前提下，只追求可执行性与结果正确：
多 kernel launch、多搬运与同步——这是「一定能搭出正确积木」的保守拼法，
性能不可用，也几乎吃不进后续 P0/P1 工程优化。

它还记录了一段真实的 Agent 过程史：故意不给确定性拼装路线时，
探索成本极高（失败、卡死、回退；曾短期内耗尽大量 token），最终仅得到「结果正确」的代码。

\subsection{在方法论中的角色}
\begin{center}
\begin{tabular}{@{}L{3cm}L{11cm}@{}}
  \toprule
  角色 & 含义 \\
  \midrule
  正确性锚 & 下界存在性：积木可搭、I/O 可对 \\
  结构反例 & 展示「只求对」会长成怎样的 launch/同步膨胀 \\
  过程对照 & 无确定路线的搜索成本 \\
  实验基线 & 与方法论 Agent、人工指导路径三方比较 \\
  \bottomrule
\end{tabular}
\end{center}

\textbf{纪律}：correctness 是\textbf{基线标本}，不是活跃实现模板；可读、可对拍、可对比，\textbf{禁止}当抄码来源（与 frozen 出门不带码一致）。

\subsection{建议比较轴}
\begin{enumerate}
  \item \textbf{过程}：token / 轮次 / 回退；是否先交闭包表；非法边是否被拦截；
  \item \textbf{结构}：launch 数、同步点、lemma 复用、接缝是否显式；
  \item \textbf{结果}：CPU+SIM；SIM tick 相对 correctness 的倍数。
\end{enumerate}
三档：A 旧式无路线探索 $\sim$ correctness；B 新方法论 Agent；C 人工指导 device/stable。
B 不必一次打赢 C；明显优于 A，即方法论第一关。
