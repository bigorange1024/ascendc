## 1. 研究路线总原则：从特殊到一般

构思对齐「写教材」而非「先写论文」：

| 阶段 | 做什么 | 刻意后置 |
|------|--------|----------|
| 特例引出 | 用已完成工程故事引出图、语法树 | 不上完备公式 |
| 套公式 / 理论 | 用数学语言**复述**已见现象 | 不证明 |
| 完善公式 / 理论 | 特例装不下的缺口（接缝、dirty、freeze）反过来改理论 | 不为漂亮删工程事实 |
| 套别的例子 | Encaps 复盘；再换域 / Decaps 前瞻 | 一次一类新缺口 |
| 迭代方法论 | 门禁、闭包表、Agent 流程随例子收敛 | 不急进 Rule |
| 成型后 | 证明、可解释性、成员判定完备性 | 过早形式化锁死错误抽象 |

**证明与推导**：可边做边补，也可事后补；不挡主线叙事。

## 2. 教材式提纲（初步草稿）

叙事主线（发生学 / 剥洋葱），而非定义先行：

1. **引子**  
   从 `pke.keygen` 如何接出 `kem.keygen`：多了哪些接缝（如 G、`dk` 展开、生产 I/O），先给人「图感」。

2. **方法论数学背景（第3章）**  
   **导论必读**：为何学依赖图/合法拼装/预研过程、工程里怎么用；术语预告表（工程词→后文记号）；最小集合与必须掌握清单；再六阶段主线。  
   **用词纪律**：导论与读章地图只用工程术语；$\mathrm{Dep}^*$ 等数学记号在定义处首次挂钩。  
   **不讲** PQC / 数论变换等密码代数；「整个工程」在此特指过程控制，非整仓 AscendC/密码栈。

3. **装进工程对象与门禁**  
   节点/边/证书字段；Agent 合法工作流。  
   分工钉死：**DAG = 引理库依赖投影**；**语法树 / 派生 = 某次任务如何展开**。

4. **复盘对照**  
   用理论回看 `kem.keygen`、`kem.encaps` 的实现过程：是否与理论一致；实现如何把数学原理**具象化**；可总结哪些推理与结论。  
   偏离处（若有）如实写，作为改公式的素材。

5. **前瞻试金石**  
   用同一套理论指导尚未做完的 `kem.decaps`：闭包、缺项、接缝、禁止边；检验理论是否可行。  
   成功标准优先是「清单可执行 / 偏差可归因」，不是一次写对。

6. **附录旁注**  
   证明、推导、形式化深度随讨论补充。

## 4. `correctness` 对照组的定位（重要）

保留 `*-correctness-*` 的动机（用户说明，记入纪要）：

| 用途 | 说明 |
|------|------|
| 正确性锚 | 在**不考虑优化**的前提下，只求可执行 + 结果正确，证明「积木能搭起来」 |
| 结构反例 | 大量 kernel launch、大量搬运与同步——稳，但性能不可用；未吃进底层工程优化 |
| 过程对照 | 当时故意不给确定性拼装路线，Agent 自行探索 → 高成本（失败 / 卡死 / 回退；曾短时间耗尽月度 token） |
| 实验对照 | 日后比较：方法论指导下的新 `kem.encaps` / `decaps` vs correctness vs 人工指导下的 device/stable |

**纪律**：correctness 是**基线标本（baseline specimen）**，可对拍、可对比数字与结构；**不是**活跃实现的抄码模板（与 frozen「出门不带码」一致）。

建议比较轴（日后实验设计）：

1. **过程**：token / 轮次 / 回退；是否先交闭包表；非法边是否被拦  
2. **结构**：launch 数、同步点、是否复用已证 lemma、接缝是否显式  
3. **结果**：CPU+SIM；SIM tick 相对 correctness 的倍数  

三档对照设想：旧式无路线探索（A） / 新方法论 Agent（B） / 人工指导路径（C）。B 不必一次打赢 C；明显优于 A 即方法论第一关。
