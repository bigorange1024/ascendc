## 1. 上机要回答的唯一主问

**在重写路径的哪一档几何上，实机粘性挂首次出现？最后稳定 TRACE 号是什么？**

由此判断挂因落在：

| 层级 | 含义 |
|------|------|
| L-host | Host launch/Sync/环境 |
| L-hand | 2-launch+SET(4) 握手本身 |
| L-glue | Encrypt 形态粘合（采样/代数角色、双路、压码） |
| L-sntt | SampleNTT 独立 phase / Â 汇合 |
| L-sticky | 单轮绿、多轮后挂（粘性） |
| L-out | 套件全绿 → 挂因在套件未覆盖的 Encrypt 特有结构 |

## 2. 测什么（三档阶梯 + 可选加码）

### 首轮必跑（E16 套件）

| 档 | 测的结构差 | 相对上一档多出来的嫌疑 |
|----|------------|------------------------|
| **C0** e01 | 2-launch + SET(4) 空壳 | Host/握手/SET 旗语 |
| **C1** e13 | +形态粘合真链（无完整 Â） | 采样↔代数编排、双 AIV 重活、压码 |
| **C2** e15 | +独立 SampleNTT phase + Â 2×2 | SampleNTT launch、Â 汇合进 L2 |

每档默认 **1 轮**；只抄三位 TRACE；超时/无 `111` 记 HANG。

### 首轮之后才加（按分支触发，不首轮全开）

| 加码 | 何时开 | 测什么 |
|------|--------|--------|
| **R×N** 多轮 | 某档单轮绿但疑粘性 | 是否第 N 轮才挂（对齐历史「跑若干轮后挂」） |
| **C1-bisect** | C0绿 C1挂 | 从 C1 减负：保 SET4，砍双路/压码/SoftSync 等**一个**因子 |
| **C2a/C2b** | C1绿 C2挂 | C2a=仅 SampleNTT phase；C2b=粘合但 Â stub（禁正确性比对，只比挂/不挂） |
| **EARLY** | 挂且设备 TRACE 全空 | 核入口第一指令打点（400/500 尽量靠前）+ Host 超时语义 |
| **ENCRYPT-GAP** | C0–C2 均绿 | 只读对照现 Encrypt：列出套件**没有**而 l18 路径**有**的同步/Cube/GATE 结构 → 开**单因子**结构 toy（仍禁止抄实现、禁止正确性） |

## 3. 反馈分支 → 下一步推理计划

```
跑 C0 → C1 → C2（遇挂可停更高档，但须记「未跑」）
```

### B0 — C0 即挂

| 子型 | 判据 | 推论 | 下一刀 |
|------|------|------|--------|
| B0-empty | Host≥`110`，设备无任何 `4xx/5xx` | 核未进或极早死；或 TRACE 落盘失败 | **EARLY** 打点；查 device/stream/同步；对照冻结 skel 是否同机可绿 |
| B0-set | 有 `400/401`+`500/510`，无 `402/502/512`，无 `111` | SET(4) 旗语实机失败 | 查 CrossCore/SET 实机路径；**禁**当「缺 SET⇒SIM124」复述结案 |
| B0-host | 无 `111`，甚至卡在 `100/101` | Host/ACL/launch 侧 | 缩到单 launch；查借入机环境/卡号 |
| B0-pass | C0 有 `111` | 握手壳本机可活 → 挂因在更高档 | 看 C1 |

**禁止**：因此回测「双 Cube / GATE alone」等 retracted。

### B1 — C0 绿，C1 挂

| 子型 | 判据 | 推论 | 下一刀 |
|------|------|------|--------|
| B1-l2entry | `110` 有，`4xx/5xx` 无，无 `111` | 对齐历史空 TRACE @L2 | EARLY + 查 L2 kernel 入口/混部 |
| B1-mid | 停在某业务号（如 `2xx/5xx/7xx`） | 卡在该号→下一号之间 | **单边界**短刀：只动该边界同步/搬运 |
| B1-set | 近 SET 无 `402` | 粘合负载下 SET 不可达 | 减负仍保双 AIV SET；查是否有 Wait 中 SyncAll |
| B1-round | 第1轮绿，第 N 轮挂 | 粘性 | **R×N** 定 N；查复用缓冲/工作区 |

**下一推理焦点**：挂因 ∈ **L-glue**（形态粘合），不在 SampleNTT。

### B2 — C0+C1 绿，C2 挂

| 子型 | 判据 | 推论 | 下一刀 |
|------|------|------|--------|
| B2-sntt | 卡在 `104/106` 或 `300–305` | SampleNTT phase 实机挂 | **C2a** 只跑 SampleNTT；验证「独立 launch」实机是否仍必需/是否仍挂 |
| B2-merge | SampleNTT 段齐，卡在随后 `110/111` 或 L2 | Â 汇合进粘合出问题 | **C2b** 粘合+Â stub vs 真 Â（只看挂因，不看正确性） |
| B2-round | 单轮绿多轮挂 | 粘性 × SampleNTT 资源 | R×N + 查 GM/workspace 复用 |

**下一推理焦点**：挂因 ∈ **L-sntt**。

### B3 — C0–C2 单轮全绿

| 子型 | 判据 | 推论 | 下一刀 |
|------|------|------|--------|
| B3-sticky | 同档 R×N（建议 N=7，对齐历史）后挂 | 粘性触发器未进单轮 | 定最低挂轮次；查轮间状态 |
| B3-clean | R×N 仍绿 | **套件覆盖结构 ≠ 现 Encrypt 挂因** | **ENCRYPT-GAP**：只读列差异 → 单因子结构探针（仍禁抄、禁正确性） |
| B3-env | 套件绿但用户跑旧 Encrypt 仍挂 | 对照有效；重写路径可能已避开挂因，或旧路径独有结构 | 保留旧 Encrypt 只读对照；**不**把套件绿当成旧路径已修好 |

### B4 — 各档 TRACE 模式与历史 N1/N2 对齐

| 模式 | 对齐 | 强化假设 |
|------|------|----------|
| Host 有 launch L2 文案/号，无 Sync 回 | N1 | 死在 L2 设备侧 |
| 设备 TRACE 全空 | N2 | 早期 AIV 未标或不可见 → EARLY 优先于加砖 |
| KeyGen 类壳不挂、Encrypt 形态挂 | N3 | 继续粘合/Encrypt 特有编排，不查通用 NTT 积木本身 |

## 4. 主控推理纪律（上机回报后）

1. **先定最低挂档**（C0/C1/C2/均未挂），再开子型。  
2. **一次只引入一个新因子**（短刀）；墙钟紧则 ABORT 回写图谱。  
3. 结果写入知识库 §失败/§实机事实 + 图谱 `F-/J-`；**support/refute** 标明。  
4. 未钉 `Q-root-cause` 前：**不**开 ByteDecode、不权威交叉、不把 SIM 绿当 NPU 结案。  
5. 若 B3-clean：承认「积木阶梯已穷尽本套件」→ 转向 ENCRYPT-GAP，而不是加正确性。
