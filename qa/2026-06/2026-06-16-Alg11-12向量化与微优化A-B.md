## 结论摘要

1. **默认交付路径（SIM 最快）**：`ALG11_IMPL=1` + `ALG11_VEC_VARIANT=2`（B2）+ **全向量 Barrett**（`OPTS=0`）+ **`ALG11_MEM_OPS=1`**（`__gm__` ROM + Init `DataCopy`）。
2. **`ALG11_MEM_OPS=1` vs `0`**：SIM Total tick **~9031 vs ~16359**（约 **−45%**）；墙钟 **~1324 ms vs ~2312 ms**。热路径 **零** `SetValue`/`GetValue`/`CreateVecIndex`。
3. **`ALG11_VEC_OPTS=1` 仍非默认**：固定 n 索引用 **标量 `SetValue`×256** 替代 `CreateVecIndex`，SIM **慢约 8%**；与 MEM_OPS 目标相反。
4. **仅把 γ 挪到 Init**（仍 `SetValue` 填表）对单 tile **几乎不降 tick**；收益来自 **索引 + interleave + γ 全部改为 MTE DataCopy/Gather**。
5. **FIPS 算法**：3 次 Barrett 不可省；负值修正在 `[0,q)` 输入下可省略（`OPTS=1`），单独收益小于错误索引路径的损失。
6. **迁入 basemul**：复制 `RomUbLuts` / `alg11_rom_tables` / `copy_rom_int32_ub`；见 [ALG11_12_VEC_PLAN.md §0](../../ascendc-tests/ml-kem/ml-kem-1024/pass-fix-f203-alg11-12-multiplyntts-k4/ALG11_12_VEC_PLAN.md)。

## 2. 宏与路径

| 宏 | 默认 | 说明 |
|----|------|------|
| `ALG11_IMPL` | `1` | `0`=标量 C |
| `ALG11_VEC_VARIANT` | `2` | `1`=B1；`2`=B2 Gather |
| `ALG11_VEC_OPTS` | **`0`** | `1`=§6 微优化（**较慢**） |
| `ALG11_MEM_OPS` | **`1`** | `0`=CreateVecIndex/SetValue legacy |

### 2.1 最快路径数据流（`MEM_OPS=1`）

```text
Init（每核一次）:
  DataCopy: gAlg11GammasGm, gAlg11GatherEven/OddByteGm, gAlg11InterleaveReorderByteGm → UB

Compute:
  4× Gather(f,g → a0,a1,b0,b1)     # 索引已驻留 UB
  alg12_elementwise_vec              # 3× Barrett + Mul(γ)
  DataCopy(c0→t1, c1→t2)             # ws 内连续 scratch
  Gather(h, t1‖t2, reorderRom, 256)
```

### 2.2 慢路径对照（`MEM_OPS=0`）

```text
CreateVecIndex + Muls + Adds   # 或 OPTS=1 时 SetValue×256
4× Gather
… alg12 …
for i: SetValue interleave ×256
```

### 3.3 为何 MEM_OPS=1 优于上午「CreateVecIndex」基准（~2020 ms）

| 因素 | 说明 |
|------|------|
| 索引 | Init 2×`DataCopy(128)` 替代每 tile 3 条向量建索引指令 |

## 4. FIPS 203 算法侧经验

### 4.1 三次 Barrett

Alg.12：`reduce(a1·b1)` → `reduce(a0·b0 + r·γ)` → `reduce(a0·b1 + a1·b0)`。`γ` 一般时 `a1·b1·γ` 需先 `reduce(a1·b1)` 防 int32 溢出。

### 4.2 负值修正

NTT 域 `[0,q)` 输入下 BaseCaseMultiply 中间量非负 → `reduce_zq_vec_barrett_basemul` 算法成立（`OPTS=1`），但默认仍用含修正版直至 basemul 真卡 A/B。

### 4.3 Cast/Div

`c0/c1` 两级和超 float 精确整数范围 → 不宜替换 Barrett。

## 5. 工程经验（AscendC / SIM）

1. **「预计算」= `__gm__` ROM + Init `DataCopy`**，不是 device 上 `for` + `SetValue`（即使公式是 `i*8`）。
2. **`CreateVecIndex`+`Muls` 快于 `SetValue` 填表**，但仍慢于 **Init 一次 DataCopy 后复用**（单 tile 场景亦然）。
3. **interleave scratch 必须 UB 连续**：本实现用 ws 的 `t1‖t2`；两个独立 `TQue` 不满足 reorder 表的字节偏移假设。
4. **Gather 解交织 / 交织 reorder 仍必要**：`SliceInfo` 不能表达 stride-2 int32（见 DataCopy 知识库 §6.3）。
5. **SIM 链接**：`__gm__` 表需与 kernel 同翻译单元（`#include "alg11_rom_tables.cpp"`）。
6. **MTE2 barrier**：`copy_rom_int32_ub` 后 `PipeBarrier<PIPE_MTE2>` 再进 Vector/Gather。
7. **`constexpr` / 命名空间**：`multiply_ntts_vec.hpp` 须在 `namespace alg11_ub` 外 include，避免 `alg11_vec` 不可见。
