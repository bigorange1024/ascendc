# 2026-07-28 — T18 PKE ref 链接修复 · Cloud KEM RT 回归

## 背景

新 Cloud Agent 三组 KEM↔liboqs round-trip（1024/768/512）CPU+SIM 全绿后，旁路报：
`liboqs_pke_ref_mlkem1024` 链接失败（`indcpa_enc/dec` 未定义）。用户判断「应是改名造成」。

## 结论

**不是改名问题**（2026-07-27 仅把 `liboqs_pke_ref` → `liboqs_pke_ref_mlkem1024`，逻辑未改）。根因是历史 **T18**：

| 事实 | 说明 |
|------|------|
| liboqs 构建 | `-fvisibility=hidden` |
| `PQCP_MLKEM_NATIVE_MLKEM1024_C_indcpa_{enc,dec}` | 在 `liboqs.so` 内为 **local**（`nm` 为 `t`），**不进** dynsym |
| 仅 `-loqs` | KeyGen（公开 `OQS_KEM_*_keypair_derand`）可链；Encrypt/Decrypt 失败 |

## 修复

[`scripts/build_liboqs_pke_ref_mlkem1024.sh`](../../scripts/build_liboqs_pke_ref_mlkem1024.sh)：

1. 链入 `ml_kem_1024_ref` 相关 `.o`（indcpa/compress/poly/…，不含 kem.c）
2. 链入 `pqclean_shims` 的 `fips202.c.o` / `fips202x4.c.o`（提供 `OQS_SHA3_*_absorb_once`）
3. 链入 `liboqs-internal.a`（SHA3 实现）+ `-loqs` + `-lcrypto`

冒烟：`keygen` / `encrypt` / `decrypt` / `cmp m==m_out` 均 exit 0。

**T18 关闭**（见 [`qa/TODO.md`](../TODO.md)）。
