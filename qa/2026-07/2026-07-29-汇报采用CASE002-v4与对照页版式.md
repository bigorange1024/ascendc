## Cloud 稿 vs v4：差距分析（2026-07-29）

体裁不同：**Cloud 稿偏工程复盘手册；v4 偏领导短讲。** 同题，裁剪目标不同。

### 结构

| | Cloud 合稿衔接片 | v4 提案 |
|--|--|--|
| 页数 | 10 | **6**（封面+5） |
| 主线 | 上篇四约束/人机 → 下篇方法 → 效果 → 合稿 | **疼 → 方法一张图 → 实例图 → 对照图 → 带走** |
| 听感 | 两段历史 + 教材味 | 一条问题链，短讲可讲完 |

v4 直接回应领导三点：要有实例图、要有 AI 对照、要能带走方法。Cloud 稿把「过去项目全景」铺太厚，方法与对照被冲淡。

### 叙事主语

- **Cloud**：过去项目「要做什么 / 四约束 / 人掌舵表38 / CCE 换路 / 验证链」——制度细节多。
- **v4**：主语是「不合理用 AI vs 合理用 AI」。

四约束与人机分工在 v4 压进「三类失败 + 真实伤疤」和末页五条规矩，不单独占多页。

### 最大缺口：对照页

| 维度 | Cloud 第7页 | v4 对照页 |
|--|--|--|
| 主视觉 | A/B/C 文字大方框 + 模糊「很高/收小」棒 | **性能条（cycles 真数）+ 配额条（≈2/3 vs &lt;5%）** |
| 口径 | 过程负担「体感」、768 一夜配额 | **同任务 Decaps 严格对账**；整套 ML-KEM 另起一句 |
| 数字 | 基本未钉 ticks | A&gt;150万 / B≈1050646 / C≈1041906 |
| 交付范围 | 弱 | **A 代价只换 1 个不可交付算子；B 后续可扩整套** |
| 四维表 | 散在框里 | 正确性 / 性能 / 可交付 / 可迁移 |

Cloud 稿在「密文」与「空心大框」间摇摆，始终没做成「反差一眼可见」的条形图主视觉（见版式文档）。

### 实例页

- **Cloud**：几乎无「方法真正干的活」的拓扑；KeyGen 一笔带过。
- **v4**：单点 → PKE.KeyGen → **缺项（收尾接缝）** → 补齐 → KEM.KeyGen，旁挂 A/B 泳道——方法可感知的关键页。

### 术语与合稿

- **Cloud**：Γ / 闭包表气味更重；单独「跟别人材料怎么接」页。
- **v4**：绿灯 / 缺项 / 禁止项 / 先表后码；合稿接口不单独占页。

### Cloud 多写、短讲用不上的

四阶段、CCE→计算图、表38、验证分层细则——对内培训有用，合稿短讲是负担。v4 收成末页五条规矩。

### 一句话

差距不在信息多少，而在是否按领导短讲三问（**实例 / 对照 / 可带走**）裁剪，以及对照页是否用**同任务真数条形图**做主视觉。
