## 2. 多 launch 怎么测准（禁止「终端一行 duration」借口）

| 层 | 做法 |
|----|------|
| 设备真值 | `MSPROF_MODE=app`：`msprof --application` **真实进程跑一遍**；`kernel_details.csv` 每 kernel 一行，脚本 `[msprof_kernel]` / `[msprof_kernel_total]` 求和 |
| Host | `acl_session::TimedSynchronizeStream` 在每次 KernelLaunch 后的 sync 打 `[npu_launch]` + `output/npu_launch_metrics.jsonl` |
| 进程墙钟 | 原 `[wall_sec]`（不含 cmake/gen_data） |

`msprof op --launch-count` 是单 op 重放，KEM 默认不用；app 失败才回退并警告。

入口：`unset ASCEND_DEVICE_ID`；`SKIP_L18_RISK=0 bash scripts/npu_kem_textbook_perf.sh`（默认开 msprof app）。分卡仍 1/2/3。

## 9. Cloud Agent 14 档回归意见 — 处置与反馈（2026-08-19 追加）

**背景**：另一 Cloud Agent 跑 14 档 KEM 回归后给出三条待处理意见；本机核对后已落盘修复并推 main。

### 9.1 意见 #1：`exp-fips203-mlkem-kem-decaps-k2` CPU verify FAIL、SIM PASS

| 项 | 结论 |
|----|------|
| **根因** | **非设备算子**：`run.sh` 曾 `ln -sfn …/scripts/host_golden` 到**自身**，git 还跟踪了 `host_golden/host_golden` 自引用 symlink；CPU/SIM 连跑时 `input/golden/output` 未清理，Phase-E CPU twin 可能读到旧 `golden_v.bin` → verify 偶发红、SIM 仍绿 |
| **处置** | `7378243` 起 decaps-k2；本轮同类：`decaps-ct-k2` 去自引用 + 删 tracked symlink；**全部 Decaps 档**（512/768/1024 examples + stable + ascendc-tests 探针）`gen_data` 前 `rm -rf input golden output` |
