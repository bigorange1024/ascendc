# 2026-08-31 — 方法论演示：开局批量底座 · 并排对比

## 决策

- **有界**：开局 `seedProven` 一次上必用已有能力；补缺仍逐步。
- **无序 / correctness**：开局底座与有界对齐（同一批已证能力 + 同初拍 `TICK_ENC`/`TICK_SEED`）；差异只在后续乱探/过补/直达落空。解封无序重加密节点 id=`phE`（开局 `enc` 保留为公钥加密）。
- **连线**：`addEdge` 同层跳过；底座不横串；缺口并排各自接到目标，不 g1→g2 横链。
- **图成员**：只留能汇入目标的节点；过补债先列表后汇入；终态 `pruneUnreachable`。
- **生长**：新节点必须先有更低层入边且可回溯 L0（L1=`enc→ek`/`prep0→m` 等）；禁止中层凭空冒出。
- **无序收口**：过补不闪回；`attachOne` 逐条并入，忌终局一次铺边。
- **correctness**：曾被误改成暗色简图 → **已从 transcript 恢复原版**（浅色 L0–L4）；开局再补 `seedProven`。
- **并排页** `compare-encaps-process-demo.html` / `compare-decaps-process-demo.html`：左右各嵌一套 cinema+embed；父页同步 `demo-play`；两侧 `CAP_MS=550`。
- **无序终局**：多次旧节点直达失败 → 探出新能力（封装收口 / 两段并入）→ 再接到目标。
- **无序布局 x**：同层禁止均分槽；封装/解封均用手写非对称 x，收口/并入偏心（避免「尺子对称」感）。
- **有界后半段**：④ 不再 `seedProven` 一次上两节点；改为 `growCap` 逐步（1/2、2/2），⑤ 先接到目标再验收。
- **无序未采用命名**：改为具体技术试探点（整链套模板、主机拼消息、六核分片、行交织重排、忙等同步、只验拒绝枝等），避免空泛词。
